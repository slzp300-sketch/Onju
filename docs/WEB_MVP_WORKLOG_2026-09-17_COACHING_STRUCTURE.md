## 구현

- `coachingQuestions.ts`: 질문별 ID/상태/사용자 원문 근거. 답변·부분 답변·모름·거절을 구분하고 새로고침 뒤 유지한다. 번호 목록 머리말을 질문으로 저장하지 않으며 마지막 단독 질문 앞의 묶음 질문도 보존한다.
- `agent.ts`: 묶음 전체를 제거하던 반복 질문 억제를 항목 단위로 적용. 보조 질문 갱신의 잘못된 ID/현재 발언에 없는 근거는 개별 무시해 별도로 검증된 목표 정보까지 실패시키지 않는다. 장비·환경·안전 조건만으로 기존 운동 수행 수준을 덮어쓰지 못하게 한다.
- `planningReadiness.ts`: 운동 목표의 환경·자원·제약 원문 근거를 초안 전에 확인한다. 타인의 정보·가정·미정·거절을 안전 확인으로 대체하지 않는다. 단답은 해당 질문의 답변 근거로 연결했을 때 인정한다. 모든 분야에 같은 설문을 강제하지 않는다.
- `goal.ts`: 초안의 계획 근거를 구조화하고 보존한다. 실행 방법/설명/카드의 기존 단일 원본 구조를 유지한다.
- `coachingGuide.ts`: 같은 내용 반복, 조정 조건/행동 누락, 실제 기록 예시 누락을 최소 검사한다. 의미 품질 전체를 보증하는 검사는 아니다.
- 프롬프트·응답 스키마: 질문별 상태와 분야 조건을 모델에 전달. 과거 원문을 현재 질문 갱신 근거로 다시 보내지 않기, 장비와 수행 수준 구분, 복합 질문은 부분 답변으로 처리하도록 명시.
- 가상 사용자 진단 4~11차: 새 필수 응답 필드 `question_updates`에 빈 배열을 추가. 기존 후보 사실·검증 기대값은 유지했다.
