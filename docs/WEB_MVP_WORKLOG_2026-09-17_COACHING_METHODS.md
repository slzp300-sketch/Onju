## 판정

직전 점검에서 발견한 세 가지 결함을 로컬에서 수정했다. 전체 무료 검사 30개 그룹, 2,337개 테스트가 통과했고 저장 응답 재검사의 정상/오류 대조 사례 8개가 기대한 결과와 오류 원인으로 처리됐다. **이번 범위의 구조 보완 완료이며, 새 모델 응답의 문서급 품질 합격은 아니다.**

유료 호출, 평가 함수 배포, 공개 배포, 커밋/푸시, Notion 쓰기는 하지 않았다. 기존 작업과 배포 상태를 유지했다.

## 1. 반복을 포함한 시간 계산

- `timedRepeats`를 추가했다. 단계 인덱스, 구간별 초, 반복 횟수, 휴식 시간, 휴식 위치를 분리해 계산한다.
- 합계 = 구간 시간 합 × 반복 횟수 + 휴식 시간 × 휴식 횟수. `between`은 마지막 뒤를 제외한 n−1회, `after_each`는 n회다.
- 1분 달리기 + 1분 걷기 × 12회 = 24분이므로 20분 단계에서는 거절한다. 10회 = 20분은 통과한다.
- 초/분 단위, 복합 시간, 명시된 시간 범위의 상한, 시간으로 유지하는 세트를 검사한다. 시간 없는 일반 운동 반복 수를 임의의 초로 환산하지 않는다.
- 설명에 60초 구간 두 개가 있는데 구조 데이터에는 하나만 보내는 경우도 거절한다. 시간 값의 존재뿐 아니라 구간 개수를 비교한다.
- 대화·초안·확정 계획·수정 초안에서 공통 계산식을 표시한다. 한국어/영어 표시 라벨을 제공한다.
- 새 도구 스키마에는 배열을 요구하며 해당 없으면 빈 배열이다. 구형 카드의 필드 누락은 읽기 단계에서 허용한다. 새 계획/수정 계획에 명시적인 시간 구간 반복이 있는데 계산 자료가 빠지면 보완을 요구한다.

한계: 자유 문장을 완전히 해석하는 수학 증명기는 아니다. 구조화된 반복 시간 계산은 정확히 검사하지만, 문장 교차검사는 명시적인 한국어/영어 표현의 제한된 범위다. 운동 적합성·실제 수행 시간은 별도 검토/실행 기록이 필요하다.

## 2. 기간·주당 횟수·시간을 유지한 실행 방법 수정

- 기존 `revise_goal`에 `executionMethod` 편집을 추가했다. 세트·반복 등을 바꾸려고 관계없는 기간/시간을 억지로 수정할 필요가 없다.
- 현재 사용자 발언의 정확한 근거와 기존 행동/단계의 대상 표현을 확인한다. 같은 대상이 여러 행동에 있으면 행동 이름으로 구분하거나 추가 확인한다.
- 목표·기간·주당 횟수·회당 시간은 유지한다. 요청하지 않은 행동의 단계/시간/반복/수칙은 바꿀 수 없다. 특정 동작만 요청했을 때는 같은 행동 안의 다른 단계도 보호한다.
- 상세 가이드·실행 순서·시간·조건부 수칙·부가 설명을 함께 갱신하고 다시 검증한다. 새 방법의 실제 의미가 사용자의 의도에 맞는지는 모델 판단과 사용자 확인 대상이다.
- 수정 전/후를 보여주며 기존 활성 계획은 즉시 덮어쓰지 않는다. 명시적 승인 후 반영하고 재로딩에도 보존한다.
- 주간 시간은 그대로 두고 세트/반복을 줄일 수 있으므로, 이 경로에는 ‘가벼운 계획이면 반드시 주간 시간을 줄여야 한다’는 기존 검사를 적용하지 않는다.
- 실행 방법 변경과 기간/빈도 등 조건 변경을 한 편집에 섞거나, 요청하지 않은 관련 수정안을 끼워 넣는 것은 차단한다. 두 종류 변경은 별도로 확인한다.

## 3. 사용자 상황에 대한 설명을 먼저 표시

- 고정된 긴 도입문 대신 모델이 작성한 `coachingGuide.rationale`로 시작한다. 현재 수준·목표·제약과 선택 이유를 먼저 전달한다.
- 이어서 미확정 상태, 목표, 주간 행동, 완료 기준, 실행법, 진행·기록·조정·복귀를 표시한다. 승인 상태와 수치의 명확성을 위한 공통 표제는 유지한다.
- 앞에서 표시한 이유를 가이드 뒤에서 중복하지 않는다. 간결 모드에서도 개인화 이유와 중요 부가 조건은 남긴다.
- 상세 카드의 목표/완료 기준을 화면 길이에 맞춰 잘라내지 않는다. 상세 가이드가 없는 구형 간결 표시의 기존 길이 제한은 유지한다.
- 용어를 쉽게 풀고, 조정할 때 어느 세트/구간을 얼마나 바꿀지 명시하도록 지침을 보강했다. 프롬프트 변경은 실제 모델 준수의 증거가 아니다.
