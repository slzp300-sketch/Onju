## 수정 내용

1. **동일한 실행 시간의 표현 차이 처리**
   - `한 번에 30분`, `회당 30분`, `1회 30분`이 같은 실행 여건이면 동일한 한도로 해석한다.
   - `주 1회`라는 실제 주간 횟수는 별도로 보존한다. 회당 제한만 있는 문장에서 주간 횟수를 만들어내지 않는다.
   - 주간 총량과 회당 분량, 다른 사람의 시간, 임의로 늘린 횟수·분량을 허용하는 방향으로 근거 검사를 완화하지 않았다. 사용자 원문 evidence도 그대로 유지한다.
2. **추가 질문이 사라지는 흐름 수정**
   - 기본 목표 필드가 채워졌다는 이유만으로 정보 저장 응답 안의 추가 확인 질문을 버리던 조건을 수정했다.
   - 모델이 작성한 유효한 질문이 있으면 같은 호출에서 사용자에게 전달한다. 새로고침 후에도 미해결 질문으로 남는다.
   - 추가 질문 없는 단순 저장 확인은 기존 최종 응답·계획 작성 경로로 이어진다. 승인 전 활성 목표 변경은 여전히 금지한다.
3. **개인 계획 설명과 용어 설명 구분**
   - ‘이 조건으로 계획과 실행 방법·이유·조정 방법을 설명해줘’가 용어 조회 작업으로 분류되지 않도록 보완했다.
   - 실제 용어·정의 질문은 지식 확인 경로와 도구를 계속 사용할 수 있다.
4. **상세 설명 지침의 충돌 제거**
   - 계획 태스크 T04에 남아 있던 고정 2~3단계 설명 지침을 상세 실행 구조(필요에 따라 2~8단계)와 맞췄다.
   - 실행 방법·분량·순서·휴식·난이도, 구성 이유·진행·기록 예시·조정·복귀 설명을 기존 `actions.steps`와 `coachingGuide`에 연결한다.
   - 수행 능력만 보고 집에 장비가 있다고 추정하지 않도록 지침을 보강했다. 선택적인 점검 주기 때문에 초안을 계속 미루지 않도록 명시했다.
   - 정보 부족 시 임시·예시 실행안을 먼저 만들지 않는 원칙, 필요한 질문을 한 번에 묻는 원칙은 유지한다.
5. **질문 가독성 개선**
   - 묶음 질문의 모든 줄을 강제로 굵게 만들지 않는다. 번호 목록과 모델이 작성한 짧은 항목명 강조를 보존한다.
   - 짧은 단일 후속 질문의 강조는 유지한다. 질문마다 같은 확인 이유·관리 약속을 반복하지 않도록 지침을 수정했다.
   - 실제 React 메시지 렌더러에서 번호 목록과 항목명 강조가 유지되는지 검사했다. 390px 실제 브라우저 육안 검사는 이번에 수행하지 않았다.
6. **연결 실패 진단 보강**
   - 요청 단계/본문 읽기 단계, 시간 초과/취소/네트워크/JSON 해석/HTTP/미완료 응답을 구분할 수 있는 진단 정보를 추가했다.
   - 식별자·HTTP 상태·경과 시간 등 허용된 필드만 기록한다. 대화 원문, 키, 세션 토큰, 원시 오류 본문은 진단 로그에 넣지 않는다.
   - 결과를 알 수 없는 요청의 비용 예약과 자동 재시도 차단을 유지한다. 로그 기록 자체가 실패해도 유료 호출이 다시 발생하지 않는다.
   - 공통 비용 통제 코드는 루트와 Site 소스를 일치시켰다. 상세 OpenAI 어댑터 진단은 현재 웹의 Site 소스에 적용했다.
