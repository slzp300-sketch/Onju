# 온주 웹 에이전트 Claude 운영 전환

2026-10-23 KST. 사용자가 Claude를 주력으로 쓰고 운영 전환까지 진행하도록 승인했다. 기존의 기본 모델 유지 방침을 이 요청에 따라 변경했다.

## 반영 결과

- 현재 웹서비스의 대화(stable/pilot), 주간 계획 생성·수정, 실행 조정·주간 점검을 Claude Sonnet 4.6으로 전환했다. 동일 Claude 모델이 주·빠른·대체 경로에 사용되며 OpenAI 자동 fallback은 없다.
- Claude 키와 제공자·모델 설정을 서버 시크릿으로 등록했다. 값은 출력하지 않았고 등록 후 시크릿 digest를 로컬 값의 SHA-256과 대조했다.
- OpenAI·혼합·캐시 평가 경로는 서버의 `ONJU_ENABLE_OPENAI_EVAL=false`로 차단했다. 필요할 때 명시적인 서버 설정으로만 다시 활성화할 수 있다.
- 대화 빌드 `2026-10-23-claude-production-01`, stable 함수 114, pilot 함수 38. 변경 대상 함수 15개 모두 ACTIVE와 기존 JWT 설정을 확인했다.
- 시간 계산·기억 갱신의 직전 수정도 같은 검증 소스에 포함돼 운영에 반영됐다. 웹 프런트와 공개 URL은 그대로이며 백엔드 함수만 배포했다.

현재 웹에서 호출하는 서비스 경로가 전환 범위다. 별도 구형 `onju-agent`, `onju-goal-agent`, `interpret-schedule` 등의 코드는 교체하지 않았다. 기존 OpenAI 키를 폐기하거나 프로젝트에서 제거하지 않았으므로, 모든 구형 API나 외부 호출자까지 OpenAI 지출이 불가능해졌다고 주장하지 않는다. 현재 웹서비스 경로는 Claude 키만으로 동작하도록 구성했다.

## 문제와 해결

1. **남은 OpenAI 호출:** 대화만 전환하면 계획 생성·수정 및 점검은 계속 OpenAI를 사용했다. 각 기능이 공통 `createCoachProvider`를 사용하도록 바꾸고, 키 누락 시 OpenAI로 자동 복귀하지 않게 했다.
2. **계획 JSON 출력:** 계획 기능의 JSON schema는 큰 native strict 문법 컴파일 한도에 걸릴 수 있다. 전체 스키마를 가진 강제 결과 도구를 사용하고 도구 입력을 기존 JSON 출력 형식으로 정규화했다. 기존 계획·겹침·승인 검증은 유지했다. 작은 도구에만 native strict를 사용하는 이전 제약도 유지한다.
3. **출력 한도:** 계획 생성과 수정에는 명시적 출력 한도가 없었다. 두 경로에 6,500토큰 상한을 넣어 Claude 요청과 호출 전 예산 예약을 명확히 했다.
4. **이전 응답 식별자:** 기존 소유권 검사는 `resp_`만 받아 Claude의 `msg_` 결과 저장이 실패할 수 있었다. 두 형식 모두 서버가 기록한 세션 소유권을 검증한다. Claude에 OpenAI의 이전 응답 ID를 보내지 않으며 제공자를 바꿀 때도 서로 다른 형식의 ID를 API에 전달하지 않는다.
5. **회귀 검사 환경:** 기존 HTTP 핸들러 테스트의 가짜 환경에는 OpenAI 키만 있어 기본 경로 변경 뒤 500이 발생했다. 가짜 Claude 키를 추가하고 예산 초과·만료 세션·타인 응답 포인터의 거절 및 모델 호출 0회 조건을 그대로 검증했다. 집중 88개 검사가 통과했다.
6. **호출 지연:** Claude 요청에도 전체 110초 처리 기한의 남은 시간을 적용했다. Claude의 HTTP 429/5xx에 대한 자동 재시도는 하지 않는다. 기존의 응답 유실·비용 미확인 중단 및 예약 보존 규칙은 유지한다. 실제 코칭의 여러 도구 왕복과 응답 형식 오류는 후속 개선 대상이다.
7. **대상 외 함수 버전 증가:** 시크릿 등록과 배포 이후 대상 외 5개 함수도 버전이 각각 1 증가했다. 단순히 검사를 무시하지 않고 전환 전후 `ezbr_sha256`, JWT, 상태를 대조했다. 5개 모두 코드 해시와 접근 설정이 동일하고 ACTIVE였다. 환경 갱신으로 판단하며 코드 변경으로 분류하지 않았다. 대상 15개는 새 코드 해시·버전 증가를 확인했다.
