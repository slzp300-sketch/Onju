# 온주 코칭 규칙 확정·구현 및 첫 $1 평가

## 사용자 결정

- 실행 방법, 선택 이유, 기록·점검·조정 등 관리 방식을 충분히 설명한다.
- 필수 정보가 부족하면 임시·조건부 실행 초안도 먼저 만들지 않는다. 대신 원할 때 어떤 방향의 도움을 받을 수 있는지 제안한다.
- 지금 판단에 필요한 미확인 정보는 한 번에 묻는다. 이미 받은 정보, 모름·거절·유동 상태는 반복 수집하지 않는다. 사용자가 하나씩 원하면 그 선호를 존중한다.
- 첫 실제 모델 평가 예산은 $1. 추가 평가 예산을 승인받은 것으로 해석하지 않는다.

## 구현

1. 공통 운영 규칙, 대화 계약, 목표 탐색 태스크, 도구 설명의 질문 제한을 통일했다. 기존 기본 1개/최대 3개 규칙을 제거했다. 12개/1,800자는 과도한 출력 방지용 상한이며 목표 문항 수가 아니다.
2. 질문 묶음이 저장·재접속 때 잘리지 않도록 같은 제한을 사용한다. 핵심 목표 대화는 '자세히'라는 단어 없이도 설명을 작성할 출력 여유를 준다. 무조건 긴 답을 강제하지 않는다.
3. 정보가 부족한 때에는 방향·이유·지원 방식만 설명하고 실제 실행안은 보류하도록 지침을 수정했다. 기존 근거·준비도·명시적 승인 검증은 유지했다.
4. 관리 설명을 중복 질문으로 잘못 삭제하던 필터를 좁혔다. 일정의 빈 시간 판별 필터가 '여유 반복' 같은 운동 실행 설명을 삭제하지 않게 했다.
5. 모델이 떨어진 문장들을 이어 붙인 인용을 제시하면 조용히 버리지 않고 원문 인용을 고치도록 반환한다. 사용자가 이미 준 정보를 다시 물어보게 하지 않는다.
6. 목표 조건과 설명 요청이 같이 들어오는 복합 요청에서 목표 기록 태스크를 유지한다. 사용할 도구가 없는데 도구 호출을 강제하던 요청은 모델 API 호출 전 차단한다.
7. 검증된 초안의 핵심 승인 조건은 유지하면서, 모델이 작성한 실행 방법·이유·관리 설명도 보존한다. 다만 이 경로의 실제 완주 검증은 아직 통과하지 못했다.
8. 시험용 호출은 사용자 소유 세션에 대해 기존 운영 한도를 낮추는 요청별 예산을 적용할 수 있다. 모든 제공자 시도·재시도·대체 모델 호출이 원자적 비용 예약을 거친다. 공개 서비스 한도를 높일 수 없다.

## 실제 평가와 발견 사항

원문 사용자 발언 3개를 그대로 사용했다. 원문의 ChatGPT 답변은 모델에 전달하지 않았다. 이후 기간·운동 가능량·장비·완료 기준을 제공하는 가상 발언 1개를 별도 표시했다. 이전 원문에서 빠진 조건을 추측해 실행표를 만드는 것은 이번 합의의 합격 기준이 아니다.

### 첫 실행 (시험용 빌드 12)

- 4턴/4모델 호출. 정보 수집 시 필요한 질문을 한 번에 묶었고 미확인 조건을 임의로 채우지 않았다.
- 그러나 관리 설명과 상세 실행 문단이 필터로 사라졌고, 말로 '초안'을 설명하면서 실제 `goalDraft`는 없었다. **실패로 기록**, 결과를 선별해 합격시키지 않았다.

### 수정본 (시험용 빌드 13)

- 원문 3턴에서 관리 설명·현재 수준 해석·미확인 정보 묶음을 확인했다. 원문 세 번째 턴에서도 이미 알려준 현재 수준을 다시 요구하지 않았다.
- 정보 보충 4턴에서 `openai_400`. 무료 재현 결과 '설명 요청'으로 분류한 태스크에는 목표 기록 도구가 빠져 있는데 목표 기록을 강제하면서 빈 도구 목록을 전송한 문제였다. 복합 요청 태스크와 호출 전 방어를 수정했다.

### 마지막 단계만 재검증 (시험용 빌드 14)

- 앞선 3턴은 반복하지 않았다. 실패가 명확히 거절된 요청임을 확인한 뒤 동일 소유 세션에서 마지막 정보 보충 요청만 새 식별자로 검증했다.
- 첫 모델 호출에서는 기간·실행 여건 등을 기록할 구조화 응답이 생성됐다. 다음 모델 호출은 `ai_outcome_unknown`으로 종료되어 최종 계획 카드를 받지 못했다.
- 제공자 응답을 받지 못한 상태는 연결·시간 제한 등 수송 문제를 포함하며, 정확한 원인이나 실제 청구액을 단정하지 않는다. 중복 과금 가능성이 있어 추가 유료 시도는 중단했다.

## 완료 판정·배포 상태

**규칙 구현과 무료 검증 완료, 실제 맞춤 초안 생성의 종단 검증 미완료.**

현재 공개 서비스는 이전 배포를 유지한다. 이번 코드는 로컬과 분리된 `onju-agent-openai-eval`에만 적용했다. 공개 서버, Sites 공개 버전, 기존 앱, DB 스키마·이용자 대화·키·공개 범위는 변경하지 않았다.

다음 진행은 장문 설계 요청의 수송 안정성과 미확인 호출 복구를 먼저 점검하는 것이다. 원문 수준의 품질 100% 또는 모든 사례 통과를 선언하지 않는다. 제공자 결과가 불명확한 요청을 좋은 답변이 나올 때까지 반복하지 않는다. 공개 반영 전에 실제 초안 카드와 설명·승인 상태의 일치를 확인해야 한다.

## 검토 두 차례

1. 요구 충족: 충분한 설명, 정보 우선, 일괄 질문, $1 평가 한도를 규칙·검사·실제 결과별로 대조했다. 정보 수집은 개선 확인, 최종 계획 생성은 미통과로 남겼다.
2. 회귀·부작용: 단건 질문 선호, 개인정보·원문 근거, 초안 승인, 기존 일정, 비용 제한·미확인 비용, 실제 세션 분리 검사를 확인했다. 무료 통과와 실제 품질을 혼동하지 않았다.

평가 원문, 건강 정보, 세션 접근 토큰, 제공자 응답 원본은 비공개 로컬 평가 폴더에만 보관한다. 공통 프롬프트·웹 번들·공개 보고서에 원문을 넣지 않았다.
