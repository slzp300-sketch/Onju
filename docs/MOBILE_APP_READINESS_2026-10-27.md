Storage 파일을 소유한 사용자 삭제의 제약과 파일 삭제 API 사용 기준은 [Supabase 사용자 관리](https://supabase.com/docs/guides/auth/managing-user-data), [Storage 삭제 문서](https://supabase.com/docs/guides/storage/management/delete-objects)로 확인했다. Storage 삭제와 DB 삭제는 하나의 원자적 트랜잭션이 아니므로 중간 실패 시 일부 사진이 먼저 지워질 수 있음을 확인창·오류 안내에 표시했다. 실제 사용자 계정이나 파일을 삭제한 것은 아니다.

## 새 DB 변경과 적용 주의

새 파일: `supabase/migrations/202610270001_mobile_community_safety.sql`.

- `community_consents`: 본인 동의 버전·시각.
- `user_blocks`: 본인만 조회·추가·삭제하는 차단 목록.
- `content_reports`: 신고 접수·운영 상태. 신고자는 본인 신고만 조회하고 처리 상태를 바꿀 수 없음.
- 일반 사용자는 신고 테이블에 직접 쓰지 못하고 검증 RPC를 사용한다. 서버가 대상 작성자를 확인한다.
- 기존 RLS에 restrictive 정책을 추가해 기존 소유권·멤버 검사와 동의·차단 검사를 함께 적용한다.
- 기존 멤버 집계 함수를 내부 함수로 이동하고 차단 필터를 거치는 공개 RPC를 둔다. 필터 없는 내부 함수는 일반·익명 실행 권한을 회수한다.
- 새로 동의를 받아야 UGC를 게시할 수 있으므로 기존 앱 버전의 게시 동작에도 영향을 준다. 대상 DB의 함수·정책·마이그레이션 원장을 먼저 확인하고 새 클라이언트와 적용 순서를 맞춰야 한다.
- 이 저장소에는 별도 AI 웹 마이그레이션도 있다. **전체 `supabase db push`를 무작정 실행하지 않는다.** 이번 모바일 변경의 적용 범위를 따로 검토한다.

운영자 신고 처리 절차와 남은 운영 요건은 [소모임 신고 처리 안내](COMMUNITY_MODERATION.md)에 정리했다. 신고 이메일 자동 통보나 관리자 앱 화면은 이번 범위에 포함하지 않았다. 담당자가 관리자 콘솔에서 대기 신고를 확인하고 실제 조치해야 한다.

PGlite는 devDependency로 추가했다. 이 검사는 메모리 DB에서 기존 모바일 마이그레이션과 새 SQL을 실행한다. Supabase Auth·Storage 스키마 일부는 테스트용 모형이며 실제 Storage 서비스나 운영 DB의 설정을 검증하지 않는다. 새 커뮤니티 화면의 브라우저 fixture도 모든 API를 로컬 응답으로 바꿨다. **실제 로그인·운영 신고 접수·사진 삭제·실기기 검증을 완료했다는 뜻은 아니다.**

검사 로그와 화면 증거는 git에서 제외되는 `logs/mobile-release/2026-10-27/`에 저장했다. `tmp/mobile-release-ui/`는 화면 검증 fixture이며 제품 라우트에 추가하지 않았다.

## 확인한 실행 환경

- Node 24.20.0, npm과 로컬 의존성으로 빌드·검사 가능.
- `JAVA_HOME`과 PATH에 Java가 없어 기본 `gradlew --version`은 실패했다. 다른 로컬 도구 경로의 Temurin JDK 21.0.12.1 실행은 확인했다. 시스템 설정은 바꾸지 않았다.
- 기본 설치 경로에서 Android SDK·Studio를 찾지 못했다. 다른 경로의 SDK 존재 여부와 연결 기기·에뮬레이터는 미확인이다.
- `android/key.properties`, `android/local.properties`는 없었다. 새 키스토어를 만들거나 기존 키를 교체하지 않았다.
- 패키지 `com.onju.app`, versionCode 2, versionName 1.1, targetSdk 36은 로컬 설정값이다. 스토어 업로드 이력·버전 충돌을 확인한 값이 아니다.
- Supabase URL·anon key·Google Web client ID의 설정 존재와 placeholder 여부만 확인했다. 실제 값은 출력·기록하지 않았다. 제공자 승인·콘솔 지문·Redirect URL은 미확인이다.
- 공개 개인정보 페이지는 브라우저에서 열렸다. 공개본에는 아직 예전 로그아웃 경로 설명이 있고 이번 로컬 변경은 배포하지 않았다.
- `ios/`가 없으며 Android/iOS 출시 범위는 아직 확정하지 않았다. 사용자는 플랫폼 선택보다 기능 보완을 우선하도록 요청했다.
- AGENTS.md가 참조한 `~/.Codex/guides/`의 세 가이드 파일은 이 PC에서 찾지 못했다. 저장소 AGENTS.md와 기존 앱 구조를 기준으로 작업했다.

## 공식 정책 확인

2026-10-27에 확인한 자료다. 계정별 적용 상태나 스토어 승인 완료를 뜻하지 않는다.

- [Google Play UGC 정책](https://support.google.com/googleplay/android-developer/answer/9876937?hl=en): 수칙 동의와 신고·차단, 지속적인 콘텐츠 관리가 필요하다. 비공개 소모임도 다른 사용자가 보는 콘텐츠를 포함하므로 이번 보완의 근거로 삼았다.
- [Google Play 계정 삭제 요건](https://support.google.com/googleplay/android-developer/answer/13327111?hl=en): 앱 안의 삭제 경로와 앱 밖의 요청 경로를 제공해야 한다. 웹 페이지의 고객지원 이메일을 통한 요청도 가능한 방식에 포함된다.
- [신규 개인 개발자 계정 테스트 요건](https://support.google.com/googleplay/android-developer/answer/14151465?hl=en): 2023-11-13 이후 생성된 개인 계정은 프로덕션 신청 전 12명 이상이 연속 14일 참여한 비공개 테스트가 필요하다. 내부 테스트와는 별도이며 이 계정의 해당 여부는 아직 확인하지 않았다. 유료 테스터 모집은 진행하지 않았다.
