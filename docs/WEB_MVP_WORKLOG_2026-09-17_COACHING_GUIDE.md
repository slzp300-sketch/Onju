# 온주 원문 수준 코칭 — 상세 계획·관리 설명 구조 보완

작성: 2026-09-17 (KST)

## 요청과 이번 작업 범위

원문 대화처럼 필요한 정보를 먼저 모으고, 사용자에게 맞는 실행 방법·이유·관리 방식을 충분히 설명한다. 구현이 그 수준의 평가를 받을 준비가 되기 전에는 유료 모델 평가를 반복하지 않는다.

기존 결정은 유지한다. 필요한 미확인 정보는 한 번에 묻고, 정보가 부족하면 조건부·예시 실행 초안도 먼저 만들지 않는다. 대신 어떤 도움을 제공할 수 있는지 제안한다. 원문에서 기간·여건을 추측한 부분까지 그대로 복제하지 않는다.

이번 작업은 로컬 구현, 코드 검토, 네트워크를 차단한 회귀 검사에 한정했다. 새 유료 모델 호출은 0회다. 공개 서비스와 분리 평가 서버 모두 이번 변경을 배포하지 않았다.

## 확인한 구조적 문제와 개선

### 1. 자세한 설명이 실제 계획 데이터에 남도록 연결

- 새 계획의 실행 방법은 행동별 2–8개 단계, 단계당 최대 240자로 확장했다. 운동의 세트·반복·휴식처럼 필요한 수치 설명을 허용한다. 합의한 실행 시간·빈도 검사는 유지한다.
- `coachingGuide`에 구성 이유, 기간 동안의 진행, 기록 방법과 예시, 기록에 따른 조정, 놓쳤을 때 재시작을 저장한다.
- 새 제안 도구의 구조화 응답에는 이 다섯 항목이 필수다. 기존 저장 카드의 호환성을 위해 과거 데이터에는 선택 필드로 둔다.
- 채팅과 계획 카드가 같은 실행 방법·관리 설명을 표시한다. 자유 문단에만 상세 설명을 작성했다가 카드 저장 시 사라지는 경로를 줄였다.
- 화면의 목표·핵심 행동 요약은 간결하게 유지하고, 확정 계획의 상세 설명은 펼쳐 볼 수 있게 했다. 기존 간단한 응답 선호도 유지한다.
- 주간 계획 생성도 승인된 실행 방법과 관리 기준을 따르도록 연결했다.

### 2. 수정·재접속 시 이전 설명 또는 기본값이 덮어쓰지 않도록 보완

- 상세 설명이 있는 계획을 바꾸면 수정된 실행 방법과 관리 설명을 함께 받는다. 이전 설명이 새 시간·빈도와 어긋난 채 남지 않도록 검사한다.
- 추가 동의가 필요한 연관 수정안은 실행 조건이 달라질 때 별도 설명을 요구한다. 승인된 원본은 수정 제안만으로 바꾸지 않는다.
- 저장된 실행 여건이 있으면 이를 재사용한다. 재접속 후 기본 15분 제한이 사용자가 합의한 20분·30분을 덮어쓰던 경로를 수정했다.

### 3. 맥락에 맞는 도구·모델 선택

- 이전 질문에 '일정'이 있었다는 이유만으로 '통증은 없어' 같은 현재 수준·안전 관련 답변을 일정 수정으로 처리하던 경로를 보완했다.
- 정보 수집 도구를 이미 완료한 뒤에도 상세 계획 작성에 수집용 빠른 모델을 선택하던 조건을 수정했다. 계획 작성은 기존 품질용 모델을 사용한다.
- 상세 계획 작성·수정의 출력 여유를 6,500토큰으로 확보했다. 이는 최대치이지 매번 그 길이로 출력하거나 그만큼 과금한다는 뜻은 아니다.
- 초안과 수정안은 최종 답변 검사까지 통과한 뒤 상태에 반영한다. 실패한 초안 문구만 답변으로 남고 카드가 없는 상태를 방지한다.
- 지원하지 않는 알림 설정 등을 완료했다고 주장하는 답변 검사를 문장 단위로 좁혔다. 긴 답변의 다른 문장에 '방법'이나 '아직'이 있다고 해서 잘못된 완료 주장이 통과하지 않도록 했다.

### 4. 장문 응답의 수송·시간 제한

- 상세 출력 요청에는 최대 90초의 개별 응답 시간을 허용하되, 전체 모델 처리 시간은 110초로 제한한다. 남은 시간이 부족하면 새 유료 호출을 시작하지 않는다.
- 브라우저 응답 제한은 135초로 두고 서버 대기 중에는 10초마다 연결 유지용 SSE 주석을 보낸다. 이것은 생성 중인 답변을 흉내 내는 텍스트가 아니다.
- 응답 본문 읽기 실패도 수송 오류로 처리하고, 완료되지 않은 제공자 응답으로 도구를 실행하지 않는다. 결과 미확인 호출은 자동으로 중복 재시도하지 않는다.
- OpenAI 공식 Background mode 문서를 검토했지만 이번에는 저장·보존 방식 변경을 추가하지 않았다. 기존 `store: false`를 유지했다. 근거: https://developers.openai.com/api/docs/guides/background

## 무료 검사와 두 차례 검토

1. 요구 충족 검토: 원문의 설명 깊이를 저장·렌더링·수정·승인 후에도 유지할 수 있는지, 미확인 정보 우선 원칙과 간결한 요약 화면을 함께 유지하는지 확인했다.
2. 회귀·부작용 검토: 일정 맥락, 기존 카드, 승인 상태, 저장된 여건, 지원하지 않는 기능 주장, 수송 실패와 비용 한도를 확인했다.

중간 전체 검사에서 '유동적이라고'라는 짧은 정정이 기존 취침 질문을 마무리하지 못하는 회귀 1건이 드러났다. 생활 리듬 맥락에서는 해당 정정을 계속 처리하도록 고친 뒤 전체 검사를 다시 실행했다. 중간 실패를 성공으로 처리하지 않았다.

## 완료 판정과 다음 경계

**원문 수준을 목표로 한 구조 보완과 무료 회귀 확인 완료. 제한된 유료 품질 평가에 들어갈 구현 준비는 됐다고 판단하나, 원문 수준의 실제 응답 품질은 아직 미확인이다.**

다음 유료 평가는 예산 승인 후, 정보 수집 → 상세 초안 → 카드 내용 일치 → 승인·재접속의 흐름을 우선 확인한다. 이전 답변과 새 답변을 섞어 새 버전 전체가 검증됐다고 주장하지 않는다. 실패·비용·불확실한 결과도 그대로 기록한다.

작업 파일은 로컬에 저장했다. 공개 사이트, 기존 앱, DB 스키마와 이용자 데이터, API 키는 변경하지 않았다. 이번 작업의 커밋·푸시·Notion 업로드는 수행하지 않았다. 원문과 개인 건강 정보·세션 접근 토큰은 공개 번들이나 이 작업로그에 포함하지 않았다.
