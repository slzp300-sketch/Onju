## 원인과 수정

1. **질문 필드 위치:** Claude가 `paragraphs`에 질문을 두고 `question`을 비웠다. 같은 내용으로 두 번 실패하는 사례가 있었다. Claude 어댑터에서 question이 비어 있을 때만 질문이 있는 문단을 전용 필드로 옮긴다. 글의 내용·수치·초안·승인은 바꾸지 않으며 원래 검증기로 다시 검사한다. 이미 질문 필드도 차 있으면 임의 병합하지 않는다. 적용 횟수는 `provider_metadata.anthropic.presentation_repairs`에 남겨 모델이 처음부터 정확했던 것으로 숨기지 않는다.
2. **시간 요약과 원문:** 모델이 “월수금 30분”을 요약하며 주 3회·90분을 덧붙이면 중복 주기나 인용에 없는 숫자로 거절될 수 있었다. 계산이 들어간 요약에 한해, 인용에서 명시적으로 측정된 단일 시간 절을 표시 요약으로 사용한다. 160자 이내이며 복수 시간 절·변동 표현이 있으면 보정하지 않는다. 정상 요약과 전체 인용은 보존한다. 원문 인용·현재 사용자 여부·수치·범위 검증은 기존 서버가 계속 수행한다. 인용이 위조되거나 미측정 상태가 잘못됐으면 여전히 거절한다.
3. **작은 시작의 단위:** `minimumMinutes`는 시작 진입 행동의 1~2분인데 모델이 바쁜 날 대체 실행 5~10분을 넣었다. 스키마의 동일 범위를 enum 1·2로도 명시하고 목적을 설명했다. 실패 시 필드 경로와 허용 범위를 알려주는 오류로 개선했다. 모델이 보낸 10분을 서버가 임의로 2분으로 바꾸지 않는다.
4. **계획 근거의 분야명:** `planningEvidence.area`에 독서 같은 분야 대신 기간·현재 독서량·가용 시간 같은 항목명을 넣었다. 현재 분야와 올바른 필드를 구체적으로 설명하도록 스키마·실패 안내를 보완했다. 원문과 일치하지 않는 근거는 계속 거절한다.
5. **캐시 없는 반복 입력:** Claude는 캐시를 명시해야 한다. 고정 정책과 동적 맥락을 분리하고 고정 정책 앞부분에 5분 `ephemeral` 캐시 경계를 넣었다. 동적 사실·기억 블록에 직접 캐시 표시를 붙이지 않는다. 캐시 접두사에는 앞선 도구 정의도 포함되므로 도구 변경 시 미스가 날 수 있다. 비용 절감·지연 개선을 가정하지 않고 실제 읽기·쓰기 토큰과 지연을 측정한다.
6. **실패 턴 관측:** 예전 보고서는 전달되지 않은 턴의 도구 오류를 충분히 남기지 않았다. 후속 실행은 다음 요청의 실제 tool output 오류를 call ID로 중복 제거해 보존한다. 기존 실패 원본은 그대로 두었다.

집중 검사에서 질문 렌더러가 자동으로 굵게 표시하는 기존 동작 때문에 문자열 비교 한 개가 실패했다. 정규화가 글 자체를 바꾸지 않는지와 기존 표시 결과를 구분해 기대값을 수정했다. 검증 코드를 느슨하게 바꾸지 않았다.
