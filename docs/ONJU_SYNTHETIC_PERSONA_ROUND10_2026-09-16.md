## 결론

한국어 10명·영어 10명, 22~48세의 새 가상 설정을 추가했다. 기존 165명과 ID가 겹치지 않는 **누적 가상 설정 185명**이다. 실제 참여자는 0명이다.

신규 **747개 조건 중 681개 통과·66개 실패**가 동일 소스·동일 기대값으로 두 번 재현됐다. 의미별로 묶으면 **10개 보완 유형**이다. 17개 프로필에 실패 조건이 있지만 이것을 실제 사용자 실패율이나 대표 표본의 품질 점수로 해석하면 안 된다. 같은 문제를 저장 여부·저장값·도구 경로 등으로 중복 검사한 조건도 포함한다.

기존 165명의 5,777개 조건과 기존 테스트 1,799개, 기존 전체 무료 검사 27개 묶음은 다시 통과했다. **27개 묶음에는 이번 신규 10차 진단이 아직 포함되지 않는다.** 따라서 기존 검사 통과가 전체 완료를 뜻하지 않는다. 누적 조건은 6,524개 중 6,458개 통과·66개 실패다.

이번에는 신규 진단 데이터·실행 도구·로컬 보고서만 추가했다. 제품 코드 수정, 배포, 운영 DB 변경, 커밋·푸시, 노션 등록은 하지 않았다. 공급자 API 호출 0회, **이번 추가 모델 API 비용 $0**.

### 중요한 재현 사례

**목표 간 혼입**

- 원문: `코딩은 프로젝트 3개를 완료했어. 디자인은 그대로야.`
- 잘못된 후보: 디자인의 현재 실적을 프로젝트 3개로 변경.
- 실제: 디자인이 1개에서 3개로 저장되고 코딩은 기존 2개 유지. 직접 저장 함수와 실제 수집 처리기 모두 재현.
- 정상 대조: 같은 원문으로 코딩만 3개로 업데이트하면 디자인 1개를 유지하며 통과.

**요약은 맞아도 제약은 사라짐**

- 원문: 평일 하루 두 번, 회당 10분.
- 저장 후보: 주당 100분. 총량 환산 자체는 맞으므로 이 저장 성공을 오류로 세지 않았다.
- 이후 한도 검사: 월요일 30분짜리 행동 하나 또는 월요일 5분 행동 세 개를 허용했다.
- 정상 대조: 원래 표현을 그대로 보존한 상태에서 월·화 10분씩은 통과.
- 확인한 코드 경로: `goalFeasibility.ts`의 `capacityLimits`가 `brief.capacity.summary`만 분석한다. 근거에는 세부 제한이 남아 있어도 해당 검사에서 적용되지 않는 공백이다. 이번에는 최종 전체 초안 처리 경로까지 검증하지 않았다.

**미측정 정보와 다른 숫자의 결합**

- 원문: `I do not know my available time yet. The project number is 2.`
- 잘못된 후보: `2 hours per week`, 근거는 원문 전체.
- 실제: 시간으로 저장됨. 현재 수치 검증이 숫자 2가 어느 대상에 속하는지까지 보장하지 못한다.
- 한국어 대조는 직접 저장에서 거절되고, 수집 처리기에서는 잘못된 후보를 제외한 안전한 무변경 처리로 통과했다. 두 언어 모두 실패한 것으로 보고하지 않는다.

**정상 완료량 과잉 차단**

- 원문: `I have 2 completed projects and 3 unfinished projects toward my goal of 5 projects.`
- 의도된 현재 실적: 완료 2개.
- 실제: 2개 후보가 수치 근거 오류로 거절됨. 비교용 수량 함수는 원문에서 `5 projects`를 선택한다. 완료/미완료 수식어가 숫자와 단위 사이에 있는 구조를 충분히 구분하지 못한다.
- 잘못된 3개 후보를 막는 것은 정상이며, 정상 완료 2개까지 거절한 부분만 결함으로 기록했다.

## 다음 보완의 권장 순서

1. **사실의 관계 보존**: 목표·대상·수량·단위·완료 상태·주체·현재/예상 상태가 함께 맞는지 검사한다. 문장에 숫자나 단어가 있다는 이유만으로 저장하지 않는다.
2. **제약의 손실 없는 보존**: 주간 요약 문구와 계산용 일간·회당 제한을 분리한다. 변환·요약 뒤에도 같은 초과안을 막는지를 불변 조건으로 검사한다.
3. **표현 지원 확대**: 요일별 횟수, 0분 예외, 복수 요일, 한국어·영어 글자 수량을 정상/반대 사례와 함께 추가한다.
4. 수정 후 이번 실패 조건을 그대로 재실행하고, 기존 185명 전체 조건·기존 테스트 및 실제 모의 처리 완료 경로로 회귀를 확인한다.

현재 결과로는 단순히 금지 문구를 더 추가하는 것보다 ‘어느 목표의 어떤 사실인가’와 ‘원래 제약이 남아 있는가’를 공통 검증하는 개선의 우선순위가 높다. 모든 자연어를 한 번에 완전히 해결할 수 있다는 뜻은 아니다. 이번 요청에서는 진단까지만 수행했다.
