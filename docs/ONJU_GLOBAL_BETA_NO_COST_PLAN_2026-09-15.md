# 온주 해외 무료 베타 — 추가 모델 API 비용 없는 보완 계획

작성일: 2026-09-15 (KST)  
상태: 1단계 로컬 조사 완료 · 2단계 세션 보호 및 3단계 비용 보호 로컬 구현·검증 완료 · 4단계 지역 설정 및 5단계 안내·데이터 제어 로컬 구현·검증 완료 · 6단계 대기 · 운영 적용 없음

## 1. 목표와 완료의 의미

**한국어·영어 무료 베타에 필요한 개발과 오프라인 검증을 먼저 마친다.** 기존 한국어 사용자 경험과 데이터를 보존하고, 실제 AI 품질 검증은 개발 완료 후 한 번의 통합 평가로 모은다.

- 이번 단계에서는 유료 모델 호출, 실제 AI 대화 테스트, 모델 비교 평가를 실행하지 않는다.
- 외부 API 대신 가짜 응답과 로컬 테스트 데이터로 개발한다. 검증의 외부 네트워크 차단을 유지한다.
- 모델이나 대화 프롬프트를 비용 절감 목적으로 바꾸지 않는다. 비용 통제는 중복 호출·누락된 제한·잘못된 집계를 먼저 다룬다.
- 공개 사이트, 운영 DB, 운영 환경변수는 이 계획의 로컬 개발 과정에서 변경하지 않는다. 배포 준비와 실제 배포를 구분한다.
- “추가 모델 API 비용 없음”은 이번 개발·검증에서 공급자 API를 호출하지 않는다는 뜻이다. 기존 호스팅·DB·개발 도구 비용까지 없어지는 것은 아니다.
- 오프라인 검증 통과는 실제 자연어 품질, 해외 접속 성공, 운영 서버 설정의 정상 작동을 증명하지 않는다.

초기 범위는 한국어·영어 무료 베타다. 중국어 정식 지원, 중국 대상 운영 검토, 국제 결제·구독은 별도 출시 단계로 남긴다. 영어 지원을 전 세계 모든 국가의 출시 준비 완료로 표현하지 않는다.

## 2. 현재 확인된 출발점

아래는 로컬 코드와 작업로그 기준이다. 운영 서버의 동일한 상태나 실제 정보 유출을 확인했다는 의미가 아니다.

1단계 조사로 출발점을 보완했다. 별도 사이트 저장소에는 루트에서 빠진 보호·삭제·베타 안내 기능과 SQL 원본이 있었다. 따라서 다음 단계는 전부 신규 구현하는 것이 아니라 **양쪽 기능을 보존하며 통합하고 부족한 부분을 검증하는 작업**이다. [1단계 조사 결과](agent/global-beta/STAGE_1_SOURCE_AND_SCHEMA_AUDIT.md)를 기준으로 진행한다. 사이트 기준 커밋과 미커밋 작업본도 구분했으며, 실제 운영 상태는 이번에 확인하지 않았다.

## 3. 단계별 실행 계획

### 1단계 — 호출 경로·DB·설정 정합성 정리

목적: 일부 기능만 고쳐 같은 문제가 다른 경로에 남는 것을 방지한다.

구현·정리할 내용:

- 웹의 대화, 목표, 초안, 수정, 확정, 일일 점검, 회고, 메모리, 피드백, 삭제 요청을 서버 함수까지 연결한 목록을 작성한다.
- 각 요청의 데이터 읽기·쓰기, 세션 확인, 모델 호출, 재시도, 비용 제한 적용 여부를 기록한다. 별도 목표·계획 수정 함수도 포함한다.
- 클라이언트에서 실제 호출하는 경로와 더 이상 쓰지 않는 경로를 구분한다. 기존 앱이 공유하는 함수는 웹 전용으로 가정하지 않는다.
- 필요한 DB 필드·RPC·권한·마이그레이션과 환경변수 **이름**을 대조한다. 키 원문은 문서·로그에 기록하지 않는다.
- 정의가 없는 DB 기능은 확인된 스키마를 바탕으로 재현 가능한 로컬 마이그레이션을 준비한다. 운영에 이미 존재할 가능성을 확인할 절차도 남긴다.
- 지금 공개 중인 버전과 로컬 변경을 구분하는 배포 전 대조표를 만든다. 운영 상태를 조회하지 못한 항목은 미확인으로 남긴다.

1차 점검: 모든 화면 동작과 서버 진입점이 목록에 있고, 기존 앱 영향과 누락된 의존성이 표시됐는가?  
2차 점검: 목록을 실제 import·invoke·fetch 및 SQL 참조와 대조하고, 로컬에서 재현 가능한 범위를 확인했는가?

완료 기준: 이후 수정 대상과 DB 의존성을 추적할 수 있고, 미확인 운영 항목이 완료 항목에 섞이지 않는다. 후속 구현을 막는 스키마 정보가 없으면 먼저 그 정보를 확보한다.

진행 결과: 호출 목록·동작 분기·설정 이름·세 소스 상태를 대조했고, 누락 DB 정의가 담긴 기준 SQL 15개를 별도 참고 폴더에 확보했다. 같은 번호의 마이그레이션 충돌 때문에 자동 실행 경로에는 넣지 않았다. 원본 해시와 의존성 존재를 검사한다. SQL 통합·실행 검증·운영 적용은 완료로 간주하지 않는다.

### 2단계 — 대화·계획 데이터의 세션 분리

목적: 본인 세션에 속한 대화와 계획만 읽고 변경할 수 있게 한다.

구현할 내용:

- 공통 요청 형식에 세션 ID·세션 토큰·필요한 요청 ID를 넣고, 메모리 클라이언트까지 일관되게 전달한다.
- 주 대화·메모리 및 1단계에서 확인한 모든 읽기·쓰기·피드백·삭제 경로에 동일한 소유 확인을 적용한다.
- 다른 토큰, 누락·변형된 토큰, 만료된 세션을 구분해 처리한다. ID를 아는 것만으로 접근하거나 소유권을 선점하지 못하게 한다.
- 기존 토큰 없는 세션은 소유 확인 가능 여부에 따라 안전한 이전 정책을 정한다. 편의를 위해 검증을 생략하거나 운영 데이터를 자동 삭제하지 않는다.
- 새로고침·재시도에는 같은 세션 정체성을 유지하고, 새 사용자 시작과 기존 사용자 이어하기를 분리한다.
- 인증 오류에서도 사용자의 방금 입력한 내용을 보존하고, 명확한 복구 안내를 제공한다.

1차 점검: 읽기·쓰기뿐 아니라 수정·삭제·오류·이전 경로에도 우회가 없는가?  
2차 점검: A/B 독립 세션, 토큰 누락·위조·만료, 동시 생성, 저장 후 재접속을 가짜 DB와 로컬 UI로 검증한다.

완료 기준: 다른 세션의 자료가 반환·변경되지 않고, 정상 사용자의 저장·재시도가 동작한다. 운영 보호 적용 여부는 배포 후 별도로 확인한다.

진행 결과: 양쪽 작업본의 소유 확인·만료·삭제·응답 ID 보호와 세션별 로컬 저장을 보완했다. 실제 서버 핸들러의 모의 요청, 로컬 PostgreSQL/WASM SQL 실행, React DOM 오류 복구를 검사했다. [보호 계약과 적용 조건](agent/global-beta/STAGE_2_SESSION_PROTECTION.md)에 검증 범위·이전 정책을 기록했다. 다중 DB 연결 경쟁, 390px 브라우저 시각 검사, 운영 ledger 통합·적용은 아직 완료로 계산하지 않는다.

### 3단계 — 비용 제한·중복 호출·실패 처리 통합

목적: 품질을 낮추는 모델 변경 없이 불필요한 호출과 예상하지 못한 비용을 막는다.

구현할 내용:

- 모든 유료 호출 경로에 사용량 제한과 비용 예약·정산을 적용한다. 재시도·보조 모델·도구 호출의 비용 처리도 목록으로 확인한다.
- 같은 요청의 더블 클릭·네트워크 재전송·동시 실행이 불필요한 모델 중복 호출로 이어지지 않도록 처리한다.
- 실제 사용량 누락·알 수 없는 모델 단가를 무료로 기록하지 않는다. 타임아웃으로 과금 여부가 불명확한 경우도 별도 상태로 관리한다.
- 예산 예약과 정산의 동시성·중복 정산·실패 복구를 확인한다. 비용 제한 저장소 오류 시 제한 없이 유료 호출을 계속하지 않는다.
- 전체 서비스 한도와 세션별 제한을 설정으로 관리하고, 부족할 때는 사용자 입력을 보존한 채 이유와 재시도 가능 여부를 알린다.
- 주소 기반 제한은 배포 프록시의 신뢰 가능한 헤더를 확인할 수 있게 설계한다. 주소 하나만으로 사용자 신원을 판단하지 않는다.
- 운영 예산 금액은 임의로 결정하거나 배포하지 않는다. 추정 예약액만으로 공급자의 실제 청구 상한이 완벽히 보장된다고 설명하지 않는다.

1차 점검: 유료 호출 목록과 보호 목록이 일치하고, 재시도·오류에서도 비용이 빠지지 않는가?  
2차 점검: 가짜 공급자로 중복 요청·429·타임아웃·사용량 누락·예산 초과·동시 요청을 재현한다.

완료 기준: 미보호 유료 경로가 없고, 중복 호출·잘못된 무료 집계 회귀 테스트가 통과한다. 개발 검증에서 실제 공급자 호출은 0회다.

진행 결과: 양쪽 웹 MVP의 활성 유료 경로에 공통 예약/정산/중복 호출 보호를 연결했다. 신규 비용 테스트 30개와 실제 React DOM 비용 안내·중복 클릭 테스트를 포함하여 전체 802개 실행이 통과했다. 실제 모델 호출 0회. [3단계 계약](agent/global-beta/STAGE_3_COST_CONTROL.md)과 [작업로그](WEB_MVP_WORKLOG_2026-09-15_GLOBAL_STAGE3.md)에 검증 범위와 운영 적용 전 조건을 기록했다. 원본 앱의 별도 인증 AI 기능은 이번 웹 MVP 범위에서 변경하지 않았다.

### 4단계 — 해외 언어·시간·요일 설정 완성

목적: 해외 사용자의 생활 시간을 한국 또는 미국 기준으로 잘못 해석하지 않는다.

구현할 내용:

- 화면 언어는 한국어·영어를 지원하되 국가와 시간대는 별도 값으로 관리한다. 브라우저 언어는 국가 거주 사실로 단정하지 않는다.
- 사용자가 언어·국가·시간대·주 시작일을 직접 확인하고 변경할 수 있는 간단한 설정 화면을 제공한다. 추가 가입 질문을 강제하지 않는다.
- 사용자가 저장한 선택을 자동 추정보다 우선하고, 로컬·상위 화면 상태·서버 요청·재접속에 일관되게 반영한다.
- 월요일 우선인 기존 저장 인덱스를 바꾸지 않고, 주 시작일에 맞춰 화면 표시 순서만 안전하게 바꾼다.
- 자정 전후의 오늘 날짜·주간 범위와 서머타임 경계를 검사한다. 여행 등 시간대 변경 시 기존 기록의 날짜 의미를 무단 변경하지 않는다.
- 영어 화면의 한국어 잔여 문구, 날짜·시간 형식, 오류·빈 화면 안내를 정리한다. 통화 표시는 결제 지원과 별개임을 유지한다.

1차 점검: 언어·국가·시간대가 섞이지 않고, 기존 한국어 일정과 요일이 그대로 유지되는가?  
2차 점검: 한국, 미국 복수 시간대, 영국·캐나다·호주 및 언어와 국가가 다른 조합을 로컬 고정 시계로 검증한다. 서머타임·자정·새로고침도 포함한다.

완료 기준: 선택한 지역에 맞는 날짜·요일·안내가 일관되게 표시된다. 영어 AI 답변 품질은 이 완료 기준에 포함하지 않는다.

진행 결과: 루트 웹 MVP와 별도 사이트 작업본에 언어·국가·통화·시간대·주 시작일을 분리한 설정과 공통 지역 컨텍스트 전달을 연결했다. 저장된 요일 인덱스(월요일=0)는 유지하고 화면 순서만 바꾸며, 기록 날짜는 여행이나 시간대 변경으로 이동하지 않게 했다. 자정·서머타임·반복 시각·알림 중복 전송·캘린더 알림의 현지 벽시각을 로컬 테스트로 확인했다. 영어 화면의 주요 빈 상태·오류·일일 점검·주간 회고·계획 생성/수정 안내를 보완하고, 설정 저장 중 다른 탭의 변경을 덮어쓰지 않게 했다. 실제 AI 영어 답변 품질과 외부 캘린더/모바일 알림 클라이언트 호환성은 이 단계의 완료 기준이 아니며 운영 적용도 하지 않았다. [4단계 계약과 검증 범위](agent/global-beta/STAGE_4_REGIONAL_CONTEXT.md)를 참고한다.

### 5단계 — 베타 안내·문의·데이터 제어

목적: 사용자가 어떤 서비스인지 이해하고 자기 정보를 통제할 수 있게 한다.

구현할 내용:

- 무료 베타 범위, AI 답변의 한계, 데이터 처리 안내와 문의·피드백 경로를 한국어·영어로 제공한다.
- 개인정보 안내와 이용 조건의 초안을 만들되, 운영 주체·문의 주소·실제 보관 기간·처리 업체 등 미확정 사실을 임의로 채우지 않는다.
- 익명 세션 자료의 로컬 내보내기와 삭제 기능을 설계한다. 대화·계획·회고·피드백·메모리·로컬 저장소별 포함 범위를 명시한다.
- 다른 사람의 자료를 삭제하지 못하게 하고, 삭제 실패를 완료로 안내하지 않는다. 동기화 큐나 진행 중 요청이 삭제 자료를 다시 저장하는 상황도 막는다.
- 외부 공급자 저장 자료·로그·백업의 실제 삭제 가능 범위와 제한을 조사 목록으로 구분한다. 앱 DB 삭제를 모든 외부 자료의 즉시 삭제로 표현하지 않는다.
- 390px 모바일에서 안내 접근, 확인, 취소, 진행 상태, 오류 복구를 검증한다.

1차 점검: 안내가 실제 구현과 일치하며, 삭제·보존 범위에 빠진 저장소나 과장된 표현이 없는가?  
2차 점검: 가짜 저장소로 내보내기·삭제·실패·중복 요청·삭제 중 저장 경쟁과 세션 간 분리를 확인한다.

완료 기준: 화면과 로컬 테스트가 완료되고, 게시 전 사용자가 확정할 운영 정보가 별도 목록으로 남는다. 법적 적합성 검토와 사실 확정 전에는 안내 게시까지 완료됐다고 표시하지 않는다.

진행 결과: 양쪽 웹에 안내·피드백·현재 세션의 서버/로컬 내보내기와 삭제 제어를 연결했다. 삭제 잠금·다른 탭·전송 대기·실패 재시도와 소유권을 보완하고, 390px 한국어/영어 화면 및 857개 자동 테스트 실행을 포함한 전체 오프라인 검사를 통과했다. 추가 모델 API 비용 $0. [5단계 계약](agent/global-beta/STAGE_5_DATA_CONTROLS.md)과 [작업로그](WEB_MVP_WORKLOG_2026-09-15_GLOBAL_STAGE5.md)에 범위와 게시 전 확정할 사실을 기록했다. 운영 게시/DB 적용 및 실제 AI 품질 검증은 하지 않았다.

### 6단계 — 통합 오프라인 검증·배포 준비

목적: 비용이 드는 검증을 시작하기 전에 개발상 결함과 빠진 요구사항을 최대한 제거한다.

구현·검증할 내용:

- 기존 `npm run verify:offline`에 새 테스트를 연결하고, 외부 네트워크 차단과 소스 지문·검사 로그 저장을 유지한다.
- 가짜 응답으로 첫 방문 → 자유로운 대화 → 목표 기간·현재 수준 확인 → 초안 → 승인 → 주간 계획 → 일일 점검 → 재방문 → 내보내기·삭제를 확인한다.
- 이미 알려준 정보를 다시 묻지 않기, 유동적 일정을 강제로 채우지 않기, 목표 분야만으로 확정 초안을 만들지 않기의 기존 회귀 사례를 유지한다. 실제 모델 판단까지 검증했다고 간주하지 않는다.
- 느린 응답·오프라인·실패·연속 전송·자동 스크롤·재접속·영문 긴 문구를 모바일 크기에서 검사한다. 기존 한국어 경로도 함께 확인한다.
- 번들 경고는 원인을 확인하고 안전한 화면별 지연 로딩 등을 검토한다. 대규모 구조 개편은 끼워 넣지 않고 변경 전후 빌드 결과로 판단한다.
- 프런트·서버 함수·DB 마이그레이션·환경변수 이름·적용 순서·복구 절차를 하나의 배포 체크리스트로 정리한다.
- 보안 경계 변경은 구버전 클라이언트와 캐시가 남는 상황도 고려한다. 화면만 먼저 배포해 정상 사용자가 막히지 않도록 순서를 검토한다.
- 평가 사례를 확정해 실제 영어 품질·해외 접속·운영 설정 검증 항목을 한 번의 후속 평가 계획으로 모은다. 이 단계에서는 실행하지 않는다.

1차 점검: 1~5단계의 요구사항 각각에 구현 파일과 검증 근거가 연결됐는가?  
2차 점검: 고정된 소스 버전으로 전체 무료 검사와 로컬 UI 검사를 실행하고, 실패·미확인·완료를 구분해 기록한다.

완료 기준: 필수 오프라인 검사가 모두 통과하고, 배포 산출물과 후속 실검증 목록이 준비된다. 운영 정보·실제 품질 등 남은 출시에 필요한 조건은 명시하며, 아직 해외 출시 완료로 선언하지 않는다.

진행 결과: 실제 Site 화면과 클라이언트를 쓰는 KR/EN 통합 합성 테스트, 390px/320px 브라우저 확인, 867개 테스트 실행 및 17개 검사 그룹을 통과했다. 루트 웹 지연 로딩, 환경파일 혼입 차단, 영어 진행 지도·횟수·접근성 안내, 긴 행동 제목 줄바꿈을 보완했다. 배포 준비 인벤토리는 검증 전용(`deployable:false`)이며, 실제 배포는 승인된 공개 환경 설정으로 다시 빌드해야 한다. 추가 모델 API 비용 $0, 운영/배포/유료 평가 미실행. [6단계 계약](agent/global-beta/STAGE_6_RELEASE_READINESS.md)과 [최종 작업로그](WEB_MVP_WORKLOG_2026-09-15_GLOBAL_STAGE6.md)에 근거·후속 조건을 기록했다.

## 4. 매 단계 공통 운영 방식

1. 시작 시 이번 단계의 범위와 유지할 기존 기능을 알린다.
2. 요구사항 기준 1차 점검 후 구현한다.
3. 실제 변경 기준 2차 점검과 관련 회귀 검증을 수행한다.
4. 실패나 누락이 있으면 해당 단계에서 보완한다. 외부 확인 없이는 해결 못 하는 것은 이유와 영향을 남긴다.
5. 작업로그에 변경 파일, 테스트 결과, 미확인 사항, 추가 모델 API 호출 수·비용을 기록한다.
6. 필수 완료 기준을 충족한 단계만 완료로 표시한다. 후속 단계로 넘긴 일을 완료한 것처럼 합산하지 않는다.

비용 기록 항목: 날짜 / 단계 / 실행 방식(오프라인·실제 호출) / 공급자 호출 수 / 산정 비용 / 미산정 여부. 실제 사용량을 확인하지 못했다면 0달러가 아니라 미확인으로 기록한다. 공급자 호출을 차단하고 실행하지 않은 개발 검증만 호출 0회로 기록한다.

## 5. 이번에 하지 않을 일

- 실제 AI 대화, 공급자별 A/B 비교, 자동 다회 재평가.
- 더 저렴한 모델로 교체하거나 OpenAI를 제거하는 작업.
- 운영 DB 마이그레이션 적용, 운영 키·예산 변경, 사이트 배포.
- 다국어 무제한 확대, 중국 출시, 유료 구독·국제 결제 구현.
- 새 기능을 계속 늘려 실제 검증 시점을 무기한 늦추는 작업.

## 6. 다음 의사결정 시점

6단계까지 끝나면 **무료로 개발·검증 가능한 보완 완료 보고서**를 제공한다. 이때 다음 항목을 따로 확인한다.

- 운영 정보와 데이터 안내 문구의 사실 확정.
- 실제 평가의 시나리오 수·호출 제한·예산과 중단 조건 승인.
- 영어 대화 품질이 기존 기대 수준을 충족하는지 실제 평가. 미달이면 공개 확대를 보류한다.
- 운영 설정과 해외 접속 검증, 승인된 배포 및 배포 후 확인.
- 이를 통과한 뒤 영어권 사용자 3~5명 무료 테스트.

**진행 순서: 정합성 → 데이터 보호 → 비용 통제 → 지역 설정 → 사용자 안내·데이터 제어 → 통합 검증.**

현재는 1~6단계의 로컬 구현·오프라인 검증을 완료했다. 다음은 운영 정보 확정과 실제 검증 예산·범위 승인이다. 운영 이력 통합·다중 연결 검증·실제 영어 품질·해외 접속·외부 알림 호환성 등 배포 전 조건을 유지하며, 해외 출시나 운영 배포가 끝난 것으로 간주하지 않는다.
