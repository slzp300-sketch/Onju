# 온주 Claude 연결과 코칭 비교 기록

2026년 10월 23일 사용자 요청에 따라 Claude API 연결과 기존 모델의 실제 코칭 비교를 수행했다. 승인된 이번 비교의 한도는 **두 제공자 합산 10달러**다. 매월 받는 Claude 크레딧 100달러 전체를 지출하거나 운영 모델을 즉시 바꾸는 승인으로 확대하지 않는다. 기존 미커밋 작업은 유지한다.

## 연결 방식

- Claude Messages API 변환기를 추가한다. 온주가 사용하는 시스템 지침·대화·함수 호출을 Claude 요청으로 변환하고, 응답을 기존 에이전트 규약으로 정규화한다. 목표·기억·일정 변경은 기존 온주 도구 검증과 승인 절차를 그대로 거친다.
- 서버 환경의 `ONJU_AGENT_PROVIDER=anthropic`, `ANTHROPIC_API_KEY`, `ONJU_CLAUDE_MODEL`로 선택한다. 설정이 없으면 기존 OpenAI 동작을 유지한다. 웹 클라이언트나 요청 본문으로 제공자를 선택하거나 비밀키를 전달하지 않는다.
- 최종 Claude 후보는 `claude-sonnet-4-6`다. 초기 5.5 후보가 온주의 강제 도구 호출 규약을 받지 않는 점을 실검증에서 확인해 변경했다. 한국어 코칭 품질과 비용을 비교한 후 운영 적용 여부를 결정한다. 연결 코드와 가격표는 루트 및 배포용 작업본에 반영한다. 현재 단계는 로컬 구현이며 운영 배포 완료를 의미하지 않는다.
- Claude의 자체 유료 웹 검색은 이번 연결 범위에 넣지 않는다. 지원하지 않는 검색·서버 저장형 대화 체인·잘못된 도구 이력은 전송 전에 차단한다. 운영 Claude 경로의 공개 용어 조회는 미지원으로 처리하며 검색했다고 주장하지 않는다.

## 비용과 키 관리

- 실제 키는 `.env.local` 또는 서버 시크릿에만 둔다. `VITE_` 접두사가 붙는 변수에는 비밀키를 저장하지 않는다.
- 사용자는 키 만료 기간을 30일로 설정했다고 알렸다. 실제 콘솔의 날짜는 별도 확인하지 않았으며 키 값과 만료일을 추정해 기록하지 않는다. 키는 만료 전에 폐기할 수 있고 키 사용 기간과 이번 비교 예산은 별개다.
- 평가 예산은 `logs/claude-coaching-comparison-2026-10-23/budget.json`에 호출 전 예약액과 응답 사용량에 따른 정산액을 남긴다. 두 제공자·프로세스 재시작·후속 실행이 같은 한도를 사용한다.
- 두 제공자에 각각 최대 5달러를 배정해 한쪽만으로 전체 예산을 소진하지 않게 한다. 키가 한쪽만 준비된 경우 `--provider=anthropic` 또는 `--provider=openai`로 해당 측을 먼저 실행할 수 있지만 그 결과만으로 비교 완료를 주장하지 않는다.
- 파일 잠금으로 동시 실행을 차단한다. 응답 유실·인증 오류·사용량 미확인 시 예약액을 유지하고 자동 재시도하지 않는다. 이전 미확인 호출이 있으면 다음 실행도 중단한다. 기록된 HTTP 400 거절은 실행 증거를 확인해 별도 분류할 수 있으나 원래 예약액을 한도에 전액 계속 포함한다. 비용 기록을 지우고 다시 실행해 한도를 초기화하지 않는다.
- 단가는 제공자 사용량을 바탕으로 한 API 비용 추정이다. 크레딧 차감·카드 청구 내역 대사와 구분한다. 이번 승인 범위에서 별도 유료 평가 모델은 호출하지 않는다.

## 비교 설계

실제 배포용 작업본의 `runAgentTurn`과 동일한 도구·검증 로직을 로컬에서 실행한다. 운영 사용자 세션·데이터베이스에는 쓰지 않는다. 기존 모델은 코드 기본값인 GPT-5.6 Sol과 Terra 라우팅을 사용하며 `ONJU_BASELINE_MODEL`, `ONJU_AGENT_FAST_MODEL` 설정으로 명시할 수 있다. 실제 서버 시크릿을 조회한 것은 아니므로 운영 설정과 다르면 평가 전 설정값을 맞춘다.

독서 4턴, 업무 학습 3턴, 미정 조건과 정정 3턴을 두 제공자에 동일하게 입력한다. 제공자 순서는 시나리오마다 교대하고 같은 모델의 각 시나리오는 독립 상태에서 시작한다. 원문은 합성 입력이며 개인 대화는 사용하지 않는다. 공개 용어가 필요할 때는 양쪽 모두 모델의 일반 지식 설명만 사용하고 검색 출처를 만들지 않는다.

평가 기준은 의도·정정 반영, 근거 없는 사실 추가, 불필요한 재질문, 실행 방법·순서·완료 기준, 추천 이유·대안, 기록과 다음 실행의 연결, 미승인 저장·무관한 변경, 가독성이다. 자동 검사 통과나 답변 길이를 실제 코칭 품질 합격으로 바꾸지 않는다. 실제 응답을 읽고 근거 구절과 실패 사례를 보고한다.

관측 사용량이 모두 정산됐지만 `no_valid_agent_reply`로 전달하지 못한 경우 그 사례의 실패를 기록하고 다음 독립 사례를 시도한다. 실패한 같은 턴을 합격할 때까지 재생성하지 않는다. 통신·비용 불확실성이나 예산 소진은 여전히 전체 실행을 중단한다. 평가 결과는 Codex의 내용 검토이며 최종 사용자 검수를 대신하지 않는다.

실행 명령:

```powershell
npm run eval:claude --prefix web-mvp              # 준비 상태만 확인, 유료 호출 없음
npm run eval:claude --prefix web-mvp -- --live    # 이번 승인된 합산 10달러 예산으로 실제 실행
```

## 발생한 문제와 해결

1. **프로토콜 차이:** 기존 에이전트는 Responses 형식의 함수 호출을 사용하고 Claude는 Messages의 `tool_use`·`tool_result`를 사용한다. 요청과 응답만 변환하고 도구 ID 대응과 단일 도구 호출 제약을 검사하도록 했다. 기존의 저장·승인 검증은 교체하지 않았다.
2. **캐시 사용량 차이:** Claude의 입력 토큰은 일반 입력·캐시 읽기·캐시 생성이 별도다. 정규화할 때 총 입력을 합산하고 각 구간을 분리해 중복 과금 계산이나 무료 취급을 방지했다.
3. **기존 평가 도구의 범위:** 기존 일부 평가 실행기는 제공자별 예산을 메모리에만 두거나 통신 실패에 자동 재시도했다. 이번에는 별도 영속 예산을 적용해 두 모델 비용을 합산하고 불확실한 호출 뒤 재시도를 중단한다. 과거 평가의 한도나 결과를 덮어쓰지 않는다.
4. **타입 검사:** 알 수 없는 외부 JSON 값의 토큰 수를 더하는 부분에서 TypeScript 오류가 발생했다. 정수 검증 후 숫자 타입으로 좁혀 사용하도록 수정했다.
5. **인증 준비:** 초기 확인 당시 로컬과 프로세스 환경에는 두 제공자의 비밀키가 없었다. 사용자에게 키를 채팅으로 보내지 않고 로컬 파일에 설정하도록 안내했다. 키 이름·만료일 안내는 사용자의 지속 사용 의도에 맞게 정정했다.
6. **키 저장 위치:** 사용자가 저장했다고 알려준 키가 프로젝트 환경 파일에 없어 경로를 확인했다. 바탕화면은 일반 Desktop 대신 OneDrive Desktop으로 연결돼 있었다. 사용자가 지정한 `claudeapi`, `openaiapi` 파일만 읽어 키 형식을 확인하고 `.env.local`로 안전하게 반영했다. 값은 출력하지 않았고 원본 파일은 보존했다. 두 키 모두 모델 목록 조회 HTTP 200 및 대상 모델 접근을 확인했다. 답변 생성은 하지 않아 이 확인의 모델 호출 비용은 0달러다.
7. **회귀 검사:** 기존 배포용 검사 하나가 fallback 변수의 이전 코드 문자열에 고정돼 Claude의 선택적 fallback 추가를 실패로 보고했다. 기존 OpenAI·Gemini fallback 표현과 비용 중단 조건은 그대로 검증하고, Claude가 평가 경로에서 임의로 선택되지 않는 조건도 추가 확인하도록 검사를 보완했다.
8. **실제 Claude HTTP 400:** 첫 실행에서 기존 모델 독서 4턴은 완료했지만 Sonnet 5.5의 첫 요청이 HTTP 400으로 거절돼 자동 중단했다. 관측 사용량 비용은 $0.218130, 거절 요청의 예약 상한은 $0.281991였다. 무료 `messages/count_tokens` 검증으로 `thinking: disabled`가 5.5에서 거절됨을 확인했고, 공식 문서에서 5.5가 `tool_choice: any/tool`도 받지 않음을 확인했다. 도구 사용을 느슨하게 바꿔 비교하지 않고 해당 규약을 지원하는 Sonnet 4.6으로 후보를 변경했다. 5.5 요청은 이후 로컬에서 전송 전에 차단한다. Sonnet 4.6의 같은 온주 요청은 무료 형식 검사 HTTP 200, 입력 18,360토큰으로 확인했다.
9. **거절 요청 회계:** 원 실행 결과의 HTTP 400·실행 ID·소스 불변 증거를 대조해 해당 작업을 `retained_rejection`으로 분류했다. $0.281991 전액을 한도에 계속 포함하며 0달러로 환불·삭제 처리하지 않았다. 실제 응답 유실이나 시간 초과는 이렇게 분류할 수 없고 계속 추가 호출을 차단한다. 재분류와 한도 보존 회귀 테스트를 추가했다. 초기 실패 자료는 별도 실행 폴더에 보존한다.
10. **strict 옵션 전달 누락:** 첫 Sonnet 4.6 연결 검사에서 일부 초안이 온주 검증을 통과하지 못했고 업무 학습 두 번째 턴은 최대 도구 회수를 소진해 `no_valid_agent_reply`로 중단됐다. 해당 실행은 5개 사용자 턴 전달, Claude 13회 응답·$1.111854였고 이전 실행을 포함한 관측 합계는 $1.329984였다. 실제 응답을 검사하니 도구 정의의 `strict: true`가 변환 과정에서 전달되지 않았다. 기존 Onju 검증은 불일치 초안을 차단했으며 이를 성공으로 바꾸지 않았다. Anthropic의 strict 모드에 지원되는 enum·필수 필드를 보존하고 숫자·길이 제한 등 미지원 항목은 공식 문서의 방식대로 설명에 옮겨 전달하도록 보완했다. 원래 온주 검증 스키마와 검증 코드는 유지했다. 이 실행은 통합 오류 진단 자료로 보존하고 최종 우열 비교에 섞지 않는다.
11. **문법 컴파일 한도:** strict 전달을 보완한 요청은 무료 토큰 계산 API를 통과했지만 실제 생성에서 HTTP 400으로 거절됐다. 출력 1토큰으로 제한한 진단 요청 1회에서 `compiled grammar is too large` 원인을 확인했다. 큰 복합 스키마는 Claude의 native strict 컴파일 한도에 걸리므로 작은 스키마에만 native strict를 사용하고 큰 스키마는 원본 전체를 전달한 뒤 기존 온주 검증을 그대로 적용한다. 어떤 도구가 native strict인지 응답 메타데이터에 기록한다. 스키마를 잘라 필드를 버리거나 검증을 느슨하게 바꾸지 않았다. 이후 같은 생성 진단은 HTTP 200·관측 비용 $0.055149로 확인했다.
12. **오류 관측 보완:** 초기 HTTP 거절의 상세 오류가 보존되지 않아 무료 검사와 별도 제한 진단이 필요했다. 후속 실제 비교는 거절 시 비밀값을 제거한 오류 유형·메시지를 비공개 기록에 남기도록 보완했다. 잘못된 키나 프롬프트 원문이 운영 로그에 출력되도록 바꾸지 않는다.

## 검증과 실행 결과

두 키 모두 인증과 실제 생성을 확인했다. 최종 실행 `dc7964e1-99cf-4ffd-a6fb-6585dfbe847a`에서 두 제공자 각각 10턴을 모두 전달했다. 기존 Sol/Terra 경로는 14회 호출·$0.603369·턴 지연 중앙값 10.916초, Claude Sonnet 4.6은 22회 호출·$1.782780·중앙값 52.737초였다. 최종 실행 동안 코칭 소스와 평가 도구의 해시가 변하지 않았다.

진단과 이전 중단 실행까지 포함한 캠페인 전체는 61회 유료 API 시도, 관측 사용량 비용 **$3.978857**, 거절 예약액 **$1.052369**, 보수적 예산 계산액 **$5.031226 / $10**이다. 미확인·진행 중 호출은 0건이다. 실제 카드 청구나 크레딧 대사는 아니며 미사용 예산을 소진하는 추가 호출은 하지 않았다. API 오류나 검증 실패를 지우고 한도를 새로 시작하지 않았다.

최종 오프라인 검사 30단계, 에이전트 1,823개 검사, 앱 71개 테스트, UI·타입·빌드·ESLint·Knip이 통과했다. 증거는 `logs/offline-development/2026-10-23T06-02-37-766Z/summary.json`에 있다. 루트 production build, Claude·예산 집중 테스트 17개도 통과했고 키가 브라우저 번들에 없는지 확인했다.

**실제 코칭 검토 결론은 기본 모델 유지·Claude 전환 보류**다. Claude는 세부 실행안과 대안이 좋았지만 도구 검증 거절 7회와 긴 대기 시간이 있었다. 기존 모델도 재질문과 검증 거절 2회가 있었다. 양쪽 모두 정정된 가용 시간이 구조화 상태에 충분히 반영되지 않았고, 공통 시간 파싱 오류도 발견했다. 이 미해결 문제는 [실제 응답·비용·상태 비교 결과](CLAUDE_COACHING_COMPARISON_RESULT_2026-10-23.md)에 근거와 함께 기록했다. 운영 배포와 기본 모델 전환은 하지 않았다.
