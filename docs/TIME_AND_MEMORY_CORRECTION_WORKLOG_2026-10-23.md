# 온주 시간 계산·기억 갱신 개선 기록

2026-10-23. [Claude 비교에서 발견한 문제](CLAUDE_COACHING_COMPARISON_RESULT_2026-10-23.md)를 시간 계산 → 구조화 가용 시간 → 기억 갱신 순서로 개선한다. **기존 모델과 제공자 기본값은 유지한다.** 이번 작업은 로컬 코드 개선과 오프라인 검증이며 추가 유료 API 호출·운영 배포·데이터 마이그레이션을 하지 않는다.

## 1. 시간 계산

**문제:** “지금은 한 달에 0권이고, 평일 화요일과 목요일 저녁에 20분씩 가능해”에서 독서량의 월간 기준을 시간 계산에 적용해 주간 한도를 약 4.615분으로 계산했다. “매주”를 생략한 요일 목록과 “월수금”도 일부 해석되지 않았다.

**수정:** 계산용 복사본에서 비시간 측정이 있는 앞 절과 시간 절을 구분한다. 시간·횟수 단위가 있는 절은 임의로 제거하지 않는다. 실행 시간과 연결된 명시적 한국어 요일 목록에 주간 주기를 적용하고, “월수금”은 요일 목록으로 정규화한다. 요일별 서로 다른 시간은 겹치지 않는 날에 한해 합산한다. 저장된 원문은 수정하지 않는다.

**결과:** 최초 독서 화·목 각 20분은 주 40분, 화요일만 10분으로 정정하면 화 10 + 목 20 = 주 30분이다. 월수금 30분은 주 90분이며 수요일 불가로 정정하면 월·금 합계 60분이다.

## 2. 정정과 구조화 상태

**문제:** 모델은 답변에서 새 시간을 설명하면서도 `brief.capacity` 갱신 도구를 생략하거나 근거 검증에 실패했다. 답변과 이후 계획 검사에 쓰는 값이 달랐다.

**수정:** 지원하는 명시적 정정은 모델 응답 전에 서버 코드가 원문과 기존 시간 근거를 대조한다. 특정 요일 시간의 축소·증가, 특정 요일의 시간 없음, 회당 시간을 유지한 주간 횟수 정정을 다룬다. 기존 구조화 시간이 없더라도 직전 사용자 발언에 근거한 현재 목표의 시간 기억이 있으면 복구한다. 모델 응답 후에도 정정을 다시 적용해 오래된 도구 출력이 덮어쓰지 못하게 했다.

최초 시간 원문과 후속 정정 원문을 계약에 함께 보관한다. 다시 불러올 때 이 이력을 재실행해 계산하고 캐시의 숫자를 신뢰하지 않는다. 목표 결과·기간, 확정 목표 카드, 일정 블록을 자동 변경하지 않는다. 정정된 가용 시간과 맞지 않는 예전 초안은 기존 승인 검사에서 계속 차단된다. 과거에 주어진 실현 가능성 동의는 시간 조건이 달라졌으므로 해제한다.

범위를 추측하지 않도록 조건부·질문·인용·타인·미래 시점·정정 취소·충돌하는 숫자는 자동 변경하지 않는다. 서로 다른 목표나 공동 시간도 개인 전체 가용 시간으로 바꾸지 않는다. 현재 자동 처리 문법은 이번에 확인한 한국어 정정에 한정한다. 긴 발언(180자 초과), 범위·요일 추가 등 지원하지 않는 형태는 기존 모델·근거 검증 경로를 유지한다.

## 3. 기억 갱신

**문제:** “주 3회”와 “주 2회로 정정”이 동시에 confirmed 기억에 남았다. 파이썬 기억에는 월수금과 월금이 공존했다. 모델의 `remember/forget` 출력만으로 해결되지 않았다.

**수정:** 정정과 같은 목표·원문에 속한 시간 기억을 최신 값 하나로 정리한다. 새 기억에 사용자 메시지 ID·목표 영역·대체한 기억 ID를 남긴다. 출근 전·퇴근 뒤 같은 기존 실행 맥락을 유지한다. 노트북 보유·처음 배우는 상태처럼 복합 기억의 시간 외 부분은 남기며 다른 목표의 기억도 보존한다. 구조화 상태 갱신과 기억 정리를 모델 호출 전·도구 처리 뒤·최종 반환 전에 적용한다.

저장된 모든 옛 대화를 일괄 변경하거나 사실 정정으로 목표 승인을 대신하지 않는다. 단순히 이번 화요일에 10분 읽었다는 실행 보고를 앞으로의 시간 변경으로 해석하지 않는다.

## 진행 중 생긴 문제와 해결

1. **기준 소스가 다름:** 루트 서버의 목표 모델은 배포용 작업본보다 단순하고 시간 계약 필드도 없다. 무조건 파일을 동기화하면 기능이 깨지므로 실제 비교를 실행했던 `logs/sites/onju-web-mvp/supabase/functions/onju-agent-v2/`의 관련 모듈만 수정했다. 기준은 `docs/DEVELOPMENT_SOURCE_MAP.md`다.
2. **가이드 경로 부재:** AGENTS에 안내된 `~/.Codex/guides/coding.md`, `testing.md`가 현재 환경에는 없었다. 제공된 프로젝트 규칙과 소스 지도·기존 테스트를 기준으로 작업했다.
3. **안전 검사와 실제 정정의 충돌:** 영어의 “아까 주 3번이라고 했는데…”는 이전 자기 발언을 인용한 것으로, 학습의 “주말에 … 가정하지 마”는 가정을 거부한 것으로 해석해야 했다. 처음 구현은 인용·조건부 검사로 둘 다 거절했다. 명시적인 이전 자기 횟수 정정과 부정된 주말 가정을 구분하고, 조건부·타인 인용을 막는 반례도 추가했다.
4. **합성 예시만으로 놓친 기억 형태:** 처음 집중 테스트는 통과했지만 보존된 실제 비교 상태를 재사용하니 Claude의 파이썬 시간이 constraint 대신 context 기억에 들어 있어 복구되지 않았다. 동일 원문에 근거한 context의 가용 시간도 인정하고, 양쪽 제공자의 실제 합성 상태 6개를 고정 회귀 자료로 추가해 모두 확인했다.
5. **기존 주기와 예외 회귀:** 첫 전체 검사에서 테스트 3개와 진단 5개가 실패했다. 요일 정규화가 이미 있는 “매주”를 중복으로 붙였고 “매일 + 특정 요일 0분”의 예외도 잘못 바꿨다. 기존 주기와 매일 예외를 우선 보존하도록 고쳤다. 기존 테스트를 삭제하거나 기대치를 느슨하게 바꾸지 않았다. 해당 집중 검사 314개가 통과했다.
6. **계산 캐시와 출처:** 정정된 합계만 저장하면 새로고침 때 근거를 재현할 수 없었다. 최초 원문 + 정정 이력을 저장하고 매번 재계산하도록 했다. 숫자 캐시가 변조되면 원문 결과를 사용하며, 계산된 출처가 이력과 다르면 미해결 상태로 차단하는 검사도 추가했다.
