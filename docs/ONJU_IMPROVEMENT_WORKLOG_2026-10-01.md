# 온주 전체 점검 후 개선 기록

2026년 10월 1일 점검에서 발견한 문제를 계정 전환 안전성, 오프라인 동기화, 사용자별 조회 캐시, 소스 일치와 검사 실패, 제품 문서 순서로 개선한다. 기존 작업 파일을 보존하며 로컬 코드와 문서를 수정한다. 실제 운영 배포와 데이터베이스 변경은 이 작업의 완료로 간주하지 않는다.

## 1 계정 전환과 지연 응답

- 원인: 프로필 조회와 전체 데이터 조회가 끝났을 때 시작 당시 계정이 여전히 유효한지 검사하지 않았다. 로그아웃 처리는 직접 로그아웃 액션에 의존해 다른 탭에서 발생한 인증 이벤트도 충분히 정리하지 못했다.
- 해결: 인증 이벤트의 최신 버전과 hydrate 세대를 확인한다. 계정 전환 이벤트에서 먼저 진행 중인 hydrate와 설정 타이머를 무효화한 뒤 로컬 데이터와 큐를 정리한다. 이전 계정의 완료 응답은 스토어와 완료 상태에 반영하지 않는다.
- 진행 중 발견: 이전 계정의 저장 요청 완료가 새 큐의 첫 작업을 제거할 수 있었다. 아웃박스 작업에 계정 소유자를 저장하고, 실행 세대와 현재 큐 항목을 확인해 이전 응답의 큐 변경을 차단했다. 기존 큐는 마지막 사용자 식별자가 확인되는 경우에만 소유자를 보완한다.
- 추가 검토: Supabase 요청이 전송 직전에 현재 인증 토큰을 읽는 구조에서는 큐 소유자 검사만으로 전송 중 계정 변경을 완전히 막을 수 없다. 설치된 SDK의 `accessToken` 옵션과 `fetchWithAuth` 구현을 확인해 아웃박스 전송 전용 클라이언트를 시작 세션 토큰에 고정했다. 토큰은 큐나 작업 기록에 저장하지 않는다. 다음 재시도에서는 새로 확인한 세션 토큰을 사용한다. 토큰 고정 회귀 테스트도 통과했다.
- 검증: 프로필·hydrate·저장 응답과 설정 타이머 등 인증·동기화 회귀 테스트 21개 통과. 최종 전체 검사에도 포함한다.

## 2 오프라인 쓰기와 서버 복원 순서

- 원인: 로그인 시 쓰기 큐 전송을 기다리지 않고 서버 조회가 시작돼 저장 전 데이터가 로컬 변경을 덮어쓸 수 있었다.
- 해결: 동시에 호출된 flush는 진행 중인 전송을 함께 기다리며 hydrate는 그 이후 조회한다. 저장 대기 작업이나 설정 디바운스가 남아 있으면 로컬 데이터를 유지한다. 조회 중 로컬 스토어가 바뀐 경우에도 오래된 전체 스냅샷을 적용하지 않는다. 온라인 복귀, 화면 복귀, 큐 전송 완료 때 현재 계정의 미완료 복원을 다시 시도한다.
- 진행 중 발견: hydrate 전체 시간 동안 설정 구독을 차단하면 사용자의 편집도 서버에 저장되지 않았다. 구독 차단은 실제 서버 스냅샷 적용 구간에만 한정하고, 설정 저장 타이머도 복원 전 보호 대상으로 포함했다.
- 검증: 저장 완료 전 조회 방지, 저장 실패 시 로컬 보존, 조회 중 편집 보존, 실패 후 재시도 테스트 통과.

## 3 사용자별 조회 캐시

- 원인: 개인 리뷰와 주차별 리뷰의 조회 키가 계정 ID를 포함하지 않았고 로그아웃 시 TanStack Query 캐시를 정리하지 않았다.
- 해결: 홈·통계·나무 성장에 공통 리뷰 훅을 적용하고 개인 리뷰·주차별 리뷰 키에 사용자 ID를 포함한다. 서버 조회도 해당 사용자 ID로 한정하고 취소 신호를 전달한다. 계정 데이터 정리에서 캐시와 진행 중인 조회를 취소한다. Android 위젯도 현재 사용자 키로만 리뷰를 읽는다.
- 진행 중 문제: Supabase 상세 조회에서 `maybeSingle()` 호출 후에는 `abortSignal()` 메서드를 사용할 수 없어 타입 검사가 실패했다. 필터 → 취소 신호 → `maybeSingle()` 순서로 바꿔 해결했다.
- 추가 발견: 계정 정리에 주간 슬롯 해금 가드와 대기 중 축하 상태가 누락돼 다음 사용자에게 영향을 줄 수 있었다. 해당 필드도 기본값으로 초기화했다.
- 검증: 계정 변경 시 이전 리뷰 미표시, 로그아웃 시 조회 중지, 캐시 정리·지연 응답 취소 테스트 3개 통과.

## 4 소스 일치와 정적 검사

- 원인: 배포용 작업본의 짧은 설정 링크·접근성 라벨과 목표 중심 첫 질문·소개 문구가 로컬 웹 작업본에 반영되지 않았다. 일치 검사가 첫 파일에서 멈춰 다른 차이가 숨겨졌다.
- 해결: 지역 설정 링크와 한국어·영어 공유 카탈로그의 해당 변경을 로컬에 반영했다. 배포용 작업본의 확장 기능을 덮어쓰지 않았다. 일치 검사는 서로 다른 전체 파일 목록을 한 번에 출력하도록 개선했다.
- 진행 중 문제: 링크 수정 후 같은 검사가 번역 카탈로그에서 다시 실패했다. 비교 범위를 공유 파일 전체로 넓혀 제목·소개·첫 질문·첫 안내의 차이를 확인하고 함께 반영했다.
- 정적 검사: 사용자 여정 테스트의 `any` 2개를 목표 카드·실행 관리 상태·앱 상태 타입으로 교체했다. 새 회귀 테스트의 미사용 신호 인자도 제거했다.
- 검증: 지역·언어·알림 검사 6개와 변경 파일 ESLint 통과. 전체 오프라인 검사로 재확인한다.
