## 2. 실제 제품 코드 보완

### 요청한 동작보다 수정 범위가 커지는 결함

기존 코드는 행동 이름에 대상 표현이 포함되기만 하면 회차 전체 변경으로 취급했다. 예를 들어 ‘턱걸이·팔굽혀펴기 A’에서 ‘턱걸이만 줄여줘’라는 요청에도 팔굽혀펴기까지 교체한 응답이 통과했다.

- 변경 전 동일 사례에서 거절되지 않는 현상을 직접 재현했다.
- 회차 전체 변경은 대상이 행동 이름 전체와 일치할 때로 제한했다. 특정 동작이면 다른 단계·시간·반복 계산은 보존한다.
- 특정 동작 수정의 정상 사례와 회차 전체를 명시한 정상 사례도 함께 검사했다.
- 이것은 범위 검사 개선이다. 모델이 사용자 의미에 맞는 대상 표현을 골랐는지, 모든 부정·복합 요청을 정확히 이해하는지까지 증명하지 않는다.

### 변하지 않는 설명은 다시 쓰지 않아도 보존

- 실행 방법만 수정할 때 `coaching_refresh`의 행동별 값·관리 가이드·부가 설명에 `null`을 보내면 서버가 기존 자료를 복사하도록 했다.
- 배열은 기존 행동 순서와 개수를 유지한다. 새 실행 순서는 필요한 행동에만 보내며 기간·주당 횟수·회당 시간 등 기본 조건은 바꾸지 않는다.
- 변경 후 낡은 수치/모순이 생기는 설명은 새 값으로 갱신하도록 도구 설명에 명시했다. 무조건 옛 설명을 유지하는 규칙은 아니다.
- 기간·빈도·시간 등 조건 변경에서는 이 보존 방식을 허용하지 않는다. 그 조건에 맞는 완전한 갱신 자료가 필요하다.
- 모든 내용을 다시 복사해야 하는 부담을 줄였지만 실제 토큰·비용·지연 감소율은 측정하지 않았으며 주장하지 않는다.

### 수칙·관리 설명 변경도 전후 공개

- 실행 단계와 조건부 수칙을 함께 바꾸면 기존 변경 목록에는 단계만 나오던 문제를 수정했다.
- 수칙, 구성 이유, 기간별 진행, 기록·조정·복귀 방법, 부가 조건의 변경/삭제를 각각 전후 목록에 표시한다.
- 기존 활성 계획을 바로 덮어쓰지 않는다. 수정 초안 → 명시적 승인 → 재로딩에서도 새 실행 정보와 보존한 안내를 확인했다.
- 변경 공개는 설명의 전문적 적절성이나 안전성을 대신 검증하지 않는다.
