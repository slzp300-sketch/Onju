# 온주 대화 에이전트 품질 개선 및 검증

2026-09-04 · 한국시간 · GPT-4.1 유지, 대화/저장 구조 개선

## 결론

모델 가격만 높이는 대신, 모델이 잘하는 대화·제안과 코드로 보장할 수 있는 저장·승인·시간 계산을 분리했다. 운영 Supabase의 `onju-agent-v2`, `onju-memory`에 배포했고 로컬 웹 미리보기도 반영했다. 기존 사용자 대화는 지우지 않았다. 커밋·푸시와 웹 호스팅 재배포는 이번 작업에서 하지 않았다.

최종 동일 회귀 사례 9개 × 2회 = 18개 응답 모두 사전 정의 검사를 통과했다. 다만 이 수치는 일반적인 AI 정확도나 고객 만족도 100%를 뜻하지 않는다. 실제 모바일 연속 대화에서 추가 문제를 찾아 수정했고, 아직 남은 정성적 한계도 아래에 기록했다.

## 구현

- 모델 기본값은 `gpt-4.1-2025-04-14`. 환경 설정 `ONJU_AGENT_MODEL`이 있으면 우선한다.
- 모델 도구를 일정 일괄 반영과 최종 응답 두 개로 정리했다. 함께 수행하는 일정 입력을 모으고, 불필요한 단계 전환/확정용 모델 왕복을 줄였다.
- 초안을 별도 `agent_v2_context`에 버전 ID와 함께 저장한다. 제안·거절·수정은 확정 목표의 숫자와 주간 행동을 덮어쓰지 못한다.
- 사용자가 본 동일 카드에서 답변을 렌더링하고, 승인 시 그 카드를 그대로 확정한다. 최신 초안 버튼에는 ID를 전달한다. 바로 직전 초안에 대한 짧고 조건 없는 동의도 처리한다. 부정·수정 조건이 섞인 답변이나 다른 질문에 대한 “응”은 확정으로 취급하지 않는다. 승인 자체는 모델 호출 0회다.
- 서버 메시지 ID를 프런트에서도 보존해 자동 저장 뒤 짧은 동의가 무효화되는 문제를 막았다. 새로고침 시 미확정 초안과 선택 버튼을 복원한다.
- 클라이언트 자동 저장이 v3의 서버 확정 목표를 덮어쓰지 않도록 보호했다. 대화 저장은 `updated_at` 비교로 다른 갱신과 충돌하면 409를 반환한다. 동시성 스트레스 테스트까지 한 것은 아니다.
- 기상·취침은 요일별로 부분 저장한다. 빈 값은 모르는 값이지 임의의 05:00/23:00이 아니다. 사용자가 미룬 주말은 미정 상태로 두고 반복 질문하지 않는다. 일부만 알려진 경우 정확히 빠진 요일·항목을 묻는다.
- 도구 입력의 요일을 한국어 이름으로 받고 서버에서 월=0…일=6으로 바꿔 하루씩 밀리는 실수를 줄였다.
- 금요일 23:00~토요일 01:00은 금요일 23:00~24:00 + 토요일 00:00~01:00으로 보존한다. 일요일→월요일도 지원한다.
- 모델의 “저장 완료” 주장 대신 실제 검증된 변경 내역을 답변으로 표시한다. 실패한 저장을 성공으로 말하지 못하도록 차단한다. 추가 변경 내역이 길어도 질문은 마지막에 둔다.
- 알려진 일정으로 계산한 빈 시간을 명시하고, 모르는/변동하는 생활 리듬의 가용 시간은 만들어내지 않는다. 휴식과 이동을 더 확인해야 한다는 조건을 붙인다.
- 단순 횟수형 목표는 주간 횟수 × 기간과 비교한다. 여러 행동의 명시적 총횟수도 검사하고, 낮은 최소 달성 기준과 계획량을 구별한다. 행동 제목의 시간·매일 표현과 수치 필드가 명백히 충돌하면 모델에 다시 정리하도록 한다. 임의의 자연어 목표 전체를 수학적으로 검증하는 기능은 아니다.
- 기존의 문단·굵기·목록 렌더러와 자동 스크롤을 유지하며 실제 화면을 검증했다. 모바일에서 목표 카드가 입력창을 화면 아래로 밀어내지 않도록 접이식 시간 지도·목표 영역 안으로 옮겼다.

OpenAI Docs의 [함수 호출 가이드](https://developers.openai.com/api/docs/guides/function-calling)를 참고했다. 특히 이미 아는 값과 검증은 코드에 맡기고, 항상 연속 실행하는 작업을 합치는 원칙을 적용했다. 모델을 파인튜닝하거나 ChatGPT의 비공개 데이터를 가져온 작업이 아니다.

## 반복 검증에서 발견한 문제

초기 재검증은 16/18이었다. 모델이 평일을 숫자 1~5로 보내 화~토에 저장한 문제를 요일 이름 도구로 변경했다. 중간 18/18 결과도 그대로 완료로 판단하지 않았다. 원문과 모바일에서 복수 목표의 총횟수 오산, 행동 이름의 시간 충돌, 질문 뒤에 추가 일정 내역이 붙는 문제, 새로고침 후 선택 소실, 메시지 ID 불일치, 모바일 입력창 밀림을 발견해 수정했다.

중간 결과 JSON도 보존했다. 최종 결과와 혼동하지 않도록 실행 ID로 구분한다.

## 모바일/영속 저장 검증

사용자 원래 5173 세션과 분리한 5189의 합성 세션, 390×844 뷰포트에서 확인했다. 실제 모바일 기기를 테스트한 것은 아니다.

1. 평일 06:00/23:00, 주말 미정 입력 → 주말 반복 질문 없이 다음 일정으로 진행.
2. 이동·근무·금요일 밤 모임 입력 → 실제 시간 지도와 빈 시간 안내 확인.
3. “일정은 여기까지” + 세 분야 목표 요청 → 초안과 미확정 표시.
4. 축소 요청 → 새 초안 표시. 새로고침 후 초안 및 선택 버튼 복원.
5. “응”으로 승인 → 보던 조건 그대로 확정. 새로고침 후에도 확정 답변 보존.
6. 수요일 종료 정정 → 다른 평일 시간 보존, 새 응답 뒤 스크롤 하단 간격 0px.
7. 목표 변경 초안 요청 → 제안 상태로 표시, 새 응답 뒤 하단 간격 0px.
8. 버전형 승인 버튼 → 동일 조건 확정, 하단 간격 0px 확인. 새로고침 후 ‘함께 정한 목표’와 활성화된 ‘이 목표로 주간 계획 만들기’ 버튼을 확인했다. 주간 계획 생성 자체는 실행하지 않았다.

문단·굵기·목록, 가로 넘침 없음(문서 폭 390px), 입력창 하단 약 792.5px < 뷰포트 844px를 확인했다. 이전 대화로 스크롤하면 ‘최신 대화로’가 표시되고, 클릭하면 하단 간격 0px이었다. 초기 접근성 노드 조작 중 한 차례 맨 위로 이동한 현상이 있었으나 일반 DOM 버튼 클릭으로 반복한 일정 정정·초안 요청에서는 재현되지 않았다. 실기기 키보드/접근성 포커스 변화까지 해결됐다고 단정하지 않는다.

## 남은 한계 / 다음 검증

- 아직 ChatGPT와 동등한 자유 대화 품질을 입증하지 않았다. 낯선 표현·긴 대화·실제 사용자 완주율 평가가 필요하다.
- ‘가벼운 초안’에 60분 업무가 제안된 사례가 있어 개인별 부담 조절은 더 개선할 여지가 있다. 현재 숫자 검증은 자연어 전체의 의미 일관성을 증명하지 않는다.
- 모바일 변경 초안에서 “회고 횟수만 줄여줘”라는 요청에 결과 최소 횟수까지 같이 낮춘 제안이 나왔다. 확정 데이터는 승인 전까지 보존되지만, **변경 초안의 요청하지 않은 조건까지 보존하는 품질은 추가 검증 대상**이다. 변경 전후 차이 강조도 다음 개선 후보다.
- 명시적 연기 여부의 근거 확인은 대화 전체 표현을 참고하므로 완전한 요일별 근거 추적은 아니다.
- 과거 텍스트로만 남은 초안은 버전 카드로 다시 보여주고 한 번 확인받는다. 이미 저장된 과거 답변의 문구는 소급 수정하지 않았다.
- 이번 범위는 `/setup` 대화 설계·시간 지도·목표 합의다. 별도 주간 계획 생성/수정 모델의 전면 평가, 스트리밍, 장기 기억 검색, 다중 탭 동시성 부하 검증은 하지 않았다.
- 공개 고객 모집 전에는 익명 세션 소유권 보호, 서버 요청별 비용/속도 제한, 사용량 관측 등 별도 보안·운영 점검이 필요하다. 이번 단위/회귀 검사를 출시 준비 완료로 해석하지 않는다.
- 개발 서버에서 기존 다중 Supabase 클라이언트 인스턴스 경고가 관찰됐다. 이번 대화/승인/복원 테스트는 성공했지만 클라이언트 단일화는 별도 정리 대상으로 남겼다.
