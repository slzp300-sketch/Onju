### 하루 한도와 시간 지도는 별개

사용자에게 요일별 생활 시간표를 완성하도록 요구하지 않는다. 이미 말한 ‘평일 하루 20분’ 같은 제한만 검증한다. 주간 합계 100분이 맞더라도 60분짜리 단일 행동은 거절한다. 평일 10분·주말 20분이라면 20분 행동 2회는 가능하지만 3회는 불가능하다. 각 행동의 선호 요일도 적용한다.

검사는 기존 제한된 배치 탐색을 재사용한다. 계산 한도를 넘으면 가능하다고 단정하지 않고 미확정으로 처리한다. 실제 시계 시간에 일정을 배치하거나 모든 일정 충돌·휴일을 해결한 것은 아니다. 미측정 여건과 서술형 여건은 기존의 첫 주 측정 경로를 유지한다.

### 대화 흐름 보존

잘못된 시간 후보만 제출되면 도구에 명확한 거절을 돌려주되, 단순히 저장할 정보가 없는 대화는 기존의 안전한 무변경·추가 질문 경로를 유지한다. 한 요청에 유효한 기간과 잘못된 시간 후보가 섞이면 독립적으로 확인된 정보는 보존한다. 응답 템플릿·고정 선택지·프롬프트·모델·공급자 설정은 변경하지 않았다.

## 변경 파일

제품 8개:

- `goalEvidenceScope.ts`: 주체·시점·목표/실적·가정/결정 및 문장 경계 보호.
- `goalBrief.ts`: 현재 가용 시간 검증을 권위 있는 저장 함수에 적용.
- `agent.ts`: 잘못된 시간 후보 거절과 무변경 대화의 구분.
- `goalDays.ts`, `goalQuantity.ts`: 공통 일간 기준 사용.
- `goalCapacity.ts`: 복합 시간·이중 한도·내부 요일별 예산. 기존 공개 결과 필드 형태 유지.
- `goalFeasibility.ts`, `goalEffort.ts`: 하루·회당·주간 제한 적용, 선호 요일이 없는 최소 입력 처리.

검사:

- `web-mvp/scripts/goal-intake-round8.test.mjs` 신규 87개. 경계·정상 대조·근거 범위·재로딩·불변성 검사이며 가상 사용자 수가 아니다.
- 기존 `goal-intake-authority.test.mjs`, `goal-intake-boundaries.test.mjs`, `goal-intake-meaning.test.mjs`의 4개 일간 예산 사례 정정. 이전 기대는 하루 한도를 주간 합계 한 번으로 몰아서 써도 된다고 취급했다. 이제 명시한 하루 범위로 나눈 정상 실행안은 허용하고, 몰아서 실행하는 안은 거절한다.

실제 `runAgentTurn`에 모의 응답을 주입한 완결 경로 3개도 신규 검사에 포함했다. 평일 하루 5분 입력에서 10분 초안을 거절하고 수정된 5분 초안만 노출한다. 기존 확정 목표·수집 정보·입력 객체가 그대로임도 검사했다. 실제 모델이 스스로 같은 수정 답변을 생성한다는 검증은 아니다.
