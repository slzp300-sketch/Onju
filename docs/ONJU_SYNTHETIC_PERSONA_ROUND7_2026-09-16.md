# 온주 7차 가상 사용자 30명 추가 진단·작업로그

작성: 2026-09-16 · 사용자 요청: “30명 가상 사용자 추가해서 검증 다시 진행하자”

> 후속 업데이트: 사용자 보완 승인으로 아래 14개 유형을 로컬 Site에 수정했다. 원래 신규 조건 1,074/1,074, 누적 125명 조건 4,328/4,328, 테스트 1,501개와 무료 검사 25개 묶음이 최종 동일 소스로 두 번 통과했다. [보완 작업로그](WEB_MVP_WORKLOG_2026-09-16_PERSONA_ROUND7_FIXES.md). 아래 본문과 원시 실패 로그는 수정 전 진단 기록으로 보존한다. 유료 API 호출·배포는 하지 않았다.

## 결론

한국어 15명(KR-51~65), 영어 15명(US-46~60), 20~49세의 새 가상 설정 30명을 추가했다. 기존 ID와 중복되지 않는다. **누적 가상 설정 125명, 실제 참여자 0명**이다.

새 조건 **1,074개 중 1,007개 통과·67개 실패**가 동일 소스에서 두 번 재현됐다. 중복된 원인과 검증 위치를 구분해 **14개 보완 유형**으로 정리했다. 실패 단언 67개는 독립 결함 67개 또는 실제 사용자 실패율을 뜻하지 않는다. 새 설정 중 22개에서 하나 이상의 조건이 실패했지만, 이 역시 모집단 비율이 아니다.

이번에는 **검사 자료·실행 도구·로컬 기록만 추가했다. 제품 수정, 유료 API 호출, 배포, 운영 DB 변경, 커밋·푸시, 노션 등록은 하지 않았다.** 기존 검사와 기대값은 변경하지 않았다.

가장 먼저 보완할 부분은 **철회된 결정의 저장, 미래 예상 실적의 현재 기록화, 분수 기호 시간의 과대 계산**이다. 시간 표현 중 일부는 해석하지 못해 초안을 안전하게 차단하는 지원 공백이며, 한도 초과 초안을 허용한 경우와 구분해야 한다.

## 검증 방식과 해석 범위

- 직업·연령·문제 상황은 이번 검사 목적으로 작성한 허구다. 실제 면담, 설문, 시장 통계 또는 실사용자 데이터가 아니다.
- 기본 수집 여정은 기간 → 현재 수준 → 목표 → 실행 여건이다. 다중 목표의 우선순위와 중단·복원 여정을 포함해 작성 발언은 **122개**다. 상당 부분 공통 템플릿을 공유하므로 독립적인 자연 대화 122건이 아니다.
- 별도 정보 저장 검사 **60개**, 실제 에이전트 코드의 모의 응답 기반 capture 경로 **13개**, 구조화 시간 예산 **13개**, 수량 계산 **1개**, 초안 실행 한도 **12개**를 검사했다.
- 직접 저장 검사는 사람이 작성한 정상 후보·잘못된 모델 후보·대조 후보를 상태 갱신에 넣어 원본 불변성, 저장 후 재로딩, 다음 질문 단계, 계산 결과를 확인한다. 실제 모델이 그 후보를 생성했다는 뜻이 아니다.
- 모의 에이전트 경로는 실제 도구 스키마를 검증한 응답을 주입한다. 13개 모두 실제 capture 처리 결과를 읽은 뒤 의도적으로 중단했다. 완결된 사용자 턴이나 실제 모델의 대화·질문 품질 검사가 아니다.
- 모의 요청 콜백 33회 중 고정 모의 응답 반환은 20회다. 나머지 13회는 capture 결과 관찰·중단이다. **실제 공급자 호출은 0회**이며 이 숫자를 모델 호출 횟수로 세지 않는다.
- 초안 검사는 유효한 작성 초안에 대한 `goalFeasibilityIssue` 검사다. 최종 승인 전체 경로에는 다른 검사도 있으므로, 이 함수가 통과했다고 운영 목표가 실제 확정됐다고 단정하지 않는다.
- 외부 네트워크 차단을 적용했다. 첫 실행 전에 기대값을 작성했으며, 실행 이후 기대값 변경·테스트 작성 오류 정정은 **0건**이다.
- 실제 모델 추출 정확도·자연스러운 대화·응답 속도·만족도·유지율·지불 의사는 측정하지 않았다. 이 계층 검사의 통과율을 모델 성능으로 표현하지 않는다.

### 중요한 구분

- 8·9·11·13번의 초안 실패는 `goal_capacity_conflict` 대신 `goal_capacity_unresolved`로 차단한 **6개 조건**이다. 한도 초과 실행을 허용한 실패가 아니라 수치 이해·오류 분류 공백이다.
- 12번은 다르다. 주 90분이어야 할 한도가 120분으로 계산돼 **주 100분 초안이 이 검사에서 통과**했다. 먼저 수정할 계산 보호 문제다.
- 격일 20분의 70분/주는 **장기 주간 평균**이다. 실제 달력 한 주의 실행 횟수는 시작일에 따라 3회 또는 4회일 수 있다. 시작일 없는 현재 스키마에서 평균만 계산하며, 날짜별 배치까지 검증한 것은 아니다.
- 14번에서 `20 minutes every 2 days`는 계산 함수 자체로는 주 70분을 올바르게 반환한다. 그러나 짧은 근거 문구를 수집 단계에서 거부한다. 계산 지원과 저장 허용이 서로 일치하지 않는 사례다.

## 코드 검토로 확인한 원인

1. `goalEvidenceScope.ts`의 근거 범위가 후보의 절 중심이다. 뒤의 일반적인 취소·철회와 미래완료 시제가 충분히 반영되지 않는다. 알려진 주체 사전 밖의 집단 정보와 일부 부정·의심 표현도 현재 사실로 판정된다. 문구를 더 추가하는 것과 함께, **현재 사실 / 예상 / 조건 / 미결정 / 철회 상태가 필드별 저장 권한에 일관되게 반영되는지** 재정리할 필요가 있다.
2. `goalBrief.ts`에서 목표 결과에는 `goalResultIsDecided`를 쓰지만 가용 시간·우선순위는 같은 결정 보류 검사를 거치지 않는다. 시간 선택을 아직 하지 않았다는 후속 절을 놓치는 등 필드 간 보호 차이가 있다.
3. `goalDays.ts`는 포함/제외 집합은 계산하지만 `월요일부터 금요일까지`를 연속 범위로 인식하지 못한다. 지원하지 않는 범위를 끝점만 합산하지 않도록 막아야 한다.
4. `goalCapacity.ts`에서 `1½`의 NFKC 결과는 `11⁄2`다. 수량 정규식이 분모 쪽 `2 hours`만 읽어 120분을 만든다. 정규화 뒤 숫자 표현 전체를 소비했는지 확인하는 보호가 필요하다.
5. 회당 지시어·격일·서로 다른 요일 예산·지정 요일의 문법 지원이 제한적이다. 지원하지 않는 표현은 현재 대체로 안전하게 차단하지만 재질문으로 이어질 수 있다.
6. `goalIntakeEvidence.ts`의 `capacityEvidenceMatches`는 짧은 근거만 검사한다. 보조 읽기 전용 실험에서 US-56/59 세 사례의 근거를 **동일 사용자 원문의 전체 문장 `I can spend ...`**으로 넓히면 모두 저장됐다. 최초 67개 실패 기대값은 바꾸지 않았다. 이는 모델이 매번 실패한다는 증거가 아니라 근거 인용 길이에 민감한 계약 문제다.

## 정상 동작도 확인한 항목

- 명시적인 현재 기간·목표·수준 정정, `able to spare`의 긍정 표현.
- 완료하지 않았다고 한 성과와 현재 성과의 구분, 과거 실적과 `Now` 현재 실적 구분.
- 삭제 요청 뒤 명시적으로 유지한 목표 보호, 목표 복원 후 오래된 세부 정보 자동 재주입 방지.
- 올바른 기간 변경과 잘못된 목표 후보를 한 번에 보냈을 때 부분 저장하지 않는 원자성.
- 최소 시간만 아는 경우 최대 한도로 단정하지 않음.
- 주간 총 60분을 회당 60분으로 중복 계산하지 않음.
- `2일마다`, `every 2 days`의 계산, 소수 `1.5 hours`의 90분 계산.
- 저장 후 재로딩 및 입력 객체 불변성, 한국·미국 날짜와 주 시작일.

## 권장 보완 순서

1. **저장 권한**: 마지막 정정·철회, 조건부·미래·미결정·타인/집단의 상태를 필드별로 일관되게 확인한다. 예전 값 보존 및 한 번에 보낸 후보의 원자성은 유지한다.
2. **수치 안전성**: 혼합 분수와 요일 범위를 부분적으로만 읽어 확정 수치로 만들지 않게 한다. 이해 못한 수치와 이해한 수치를 구분해, 불명확하면 확인하되 틀린 한도를 만들지 않는다.
3. **입력 지원과 대조 검증**: 격일·회당·지정 요일·요일 묶음별 시간을 공통 구조로 해석하고, 짧은/넓은 근거 인용에 따라 불합리하게 결과가 달라지지 않게 한다.
4. 수정 후 이번 고정 기대값과 기존 125명 전체 조건을 재실행한다. 실제 모델의 자연어 대화 품질은 별도 비용 승인·평가 범위에서 확인한다.

이번 요청은 검증이므로 위 제품 수정은 아직 진행하지 않았다. 검사가 계속 새 문제를 찾는 것은 이전 통과가 전체 자연어 지원을 보장하지 않는다는 뜻이다. 문구별 추가만으로 완전한 해결을 약속할 수 없다.
