## 작업 요약

별도 배포한 온주 웹에서 첫 생활리듬 대화 오류를 수정하고, AI 답변에 빠른 타이핑 표시를 추가했다. 목표 설계는 **기간 → 기간 안에 이루고 싶은 구체적 결과 → 하루·주간 실행 가이드** 순서로 변경했다.

현재 [온주 웹](https://onju-web-mvp.slzp300.chatgpt.site/setup)에 Sites **버전 4**까지 배포 완료했다. 기존 모바일 앱/Vercel 배포는 유지했다.

이전 기록: [목표 실행 기준·응답 속도·문구 일관성 개선](https://app.notion.com/p/3d1d9f3bd74f8135aa4feca91f3e0c38)

## 1. 첫 대화 흐름 수정

- 첫 입력에서 생활리듬을 말했는데 존재하지 않는 “기존 확정 목표를 바꾸지 않았다”는 문구가 나오던 오류를 수정했다.
- “주말은 변동이 많아”를 불규칙한 생활리듬으로 인정하고, 모르는 시간을 임의로 확정하지 않는다.
- 일정 저장 오류와 목표 초안 오류를 구분하며, 실제 저장 성공/실패에 맞는 답변을 제공한다.
- 생활시간을 묻는 이유를 설명한다. 현실적인 빈 시간에 목표와 루틴을 배치하기 위한 과정임을 첫 화면과 대화에서 안내한다.
- 실제 API 확인: 평일 05:30 기상·22:30 취침 저장, 주말 미정·변동 유지, 목표/초안 없음, 다음 질문은 이동·근무 시간 한 가지로 이어졌다.
- 과거 대화에 저장된 잘못된 답변은 기록 보존을 위해 일괄 변경하지 않았다.

## 2. AI 답변 타이핑 표시

- 생활시간·목표 대화와 주간 계획 수정의 새 AI 답변을 빠르게 순차 표시한다.
- 약 초당 180자, 긴 답변은 최대 약 2.2초로 표시한다. 이는 **완성된 응답을 받은 뒤 적용하는 화면 효과**이며 실제 API 스트리밍은 아니다.
- 모델, 응답을 기다리는 서버 시간, API 비용은 이 표시 효과로 변경되지 않는다.
- 완성된 Markdown 구조를 유지해 굵은 글씨·목록·문단이 표시 중에도 깨지지 않도록 처리했다.
- 한글·결합문자·복합 이모지를 글자 묶음 단위로 표시한다. 모델이 보낸 HTML은 실행하지 않는다.
- 기존 대화·초기 안내·오류는 즉시 표시한다. “전체 답변 보기”로 애니메이션을 건너뛸 수 있고 선택 버튼은 답변 표시 후 나타난다.
- 자동 스크롤은 유지하되 이전 대화를 읽는 사용자를 강제로 아래로 내리지 않는다. 동작 줄이기 설정에서는 즉시 표시한다.

## 3. 기간 기반 목표 설계

### 설계 원칙

1. **기간 설정:** 얼마 동안 진행할지 먼저 정한다. 기간 추천은 선택을 돕는 후보이며 검증된 최적 성취 기간으로 주장하지 않는다.
2. **구체적 결과 설정:** 그 기간 안에 각 분야에서 이루고 싶은 수치·완성물·완료 조건을 정한다. 분야 이름만으로 초안을 만들지 않는다.
3. **실행 가이드 제안:** 중간 진도와 하루 실행 순서, 완료 증거, 바쁜 날 최소 행동, 주간 점검 방법으로 나눈다.

### 구현 내용

- 서버 컨텍스트에 기간·분야·분야별 결과를 기억한다. 이미 알려준 값을 다시 묻지 않으며 여러 분야의 결과를 누적 수집한다.
- 결과를 먼저 말한 경우에도 기억하고 빠진 기간만 묻는다.
- 기간·결과가 미정이면 도구 스키마와 서버 검증에서 새 초안 생성을 제한한다. AI 제안이나 예시를 사용자 확정 의도로 저장하지 않는다.
- 기간만 답하면 추가 모델 호출 없이 구체적 결과 질문으로 넘어가는 경로를 추가했다.
- 사용자의 결과 목표를 임의의 실행률 80%로 대체하지 않는다.
- 월 단위 기간은 주간 계획을 위해 근사 환산하고 이를 알린다. 예: 3개월 ≈ 13주.
- 실행 가이드에 목표와 연결된 2~3개 행동 순서, 중간 진도, 실제 수행량에 따른 조정 방법을 포함한다.
- 총 분량·현재 수준·실행 속도가 미정이면 첫 주에 확인하도록 안내한다. 작은 시작량만으로 최종 목표 달성을 보장하지 않는다.
- “목표를 다시 정할게”는 확정 목표가 없는 경우 미승인 초안을 초기화하는 데 사용할 수 있다. 확정 목표와 일정은 자동으로 삭제하지 않는다.
- 기존 목표 저장 형식과 사용자 기록을 보존했다. 모델은 gpt-4.1-2025-04-14를 유지했으며 파인튜닝이나 모델 교체 작업은 아니다.

### 실제 API 대화 검증

별도 테스트 세션에서 다음 흐름을 확인했다. 사용자 브라우저 대화·확정 목표는 변경하지 않았다.

1. “독서 목표를 세우고 싶어” → 기간 질문, 초안 없음.
2. “3개월” → 구체적 결과 질문, 초안 없음, 추가 모델 호출 0회.
3. “책 3권 완독” → 약 한 달에 1권이라는 중간 진도, 첫 주 분량·속도 확인 후 조정, 주 3회·15분 시작안, 실행 순서·완료 기준·최소 행동 제안.

주 3회·15분은 해당 테스트에서 나온 조정 가능한 시작 제안이며, 모든 독서 목표에 충분한 양이나 사용자의 확정된 가용 시간이라는 뜻이 아니다. 초안은 승인 전까지 미확정 상태다.

- 배포 후 /setup과 최신 JS 요청 HTTP 200, 최신 목표 안내·실행 전략 코드 제공 확인.
