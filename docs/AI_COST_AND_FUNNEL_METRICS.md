# 온주 AI 비용·전환 측정 기준

작성일: 2026-09-15  
적용 범위: 웹 MVP의 설정 대화, 주간 계획 생성, 데일리 실행 루프

## 목적

온주의 대화 품질을 유지하면서 국가·언어·모델 공급자별 실제 운영 효율을 비교한다. 호출 횟수만 보지 않고 입력·캐시 입력·출력 토큰, 재시도, 지연, 도구 사용을 분리하며 목표 설계가 첫 실행과 일일 점검까지 이어지는지도 함께 측정한다.

사용자의 대화 원문, 목표 내용, 일정 내용, 이름·연락처 같은 개인 식별 정보는 측정 테이블에 저장하지 않는다.

## 비용 원장

`web_mvp_ai_usage_events`는 성공한 AI 호출 한 건마다 한 행을 기록한다.

- 구분: 국가, 언어, 표시 통화, 화면, 작업, 공급자, 모델
- 사용량: 일반 입력, 캐시 입력, 출력 토큰
- 안정성: 재시도 횟수, 호출 지연
- 비용: USD 백만분의 1 단위 추정값과 가격표 버전
- 완전성: `estimated`, `partial`, `unpriced`

`partial`은 토큰 비용은 계산했지만 웹 검색처럼 별도 도구 비용이 남아 있다는 뜻이다. `unpriced`는 모델·공급자의 단가가 없거나 입력·출력 사용량이 누락/비정상인 경우다. 비용을 0으로 간주하지 않고 `null`로 남긴다. 공급자 청구서가 최종 정산의 기준이며, 이 원장은 제품 의사결정을 위한 추정치다.

현재 등록된 텍스트 토큰 가격은 2026-09-15 공식 모델 문서를 기준으로 한다.

- GPT-5.6 Sol 프로모션 가격: 입력 $4.00, 캐시 입력 $0.40, 출력 $20.00 / 100만 토큰 (공식 안내상 최소 2026-11-21까지)
- GPT-4.1: 입력 $2.00, 캐시 입력 $0.50, 출력 $8.00 / 100만 토큰
- GPT-4o Mini: 입력 $0.15, 캐시 입력 $0.075, 출력 $0.60 / 100만 토큰

가격을 바꿀 때는 기존 행을 수정하지 않는다. `onjuMetrics.ts`에 새 가격과 새 `pricing_version`을 추가하여 이후 호출부터 적용한다.

## 전환 이벤트

`web_mvp_product_events`는 다음 상태 전환을 기록한다. 일일 점검·실험은 목표 설계 순서와 독립적으로 발생할 수 있다.

1. `session_started`: 새 익명 세션이 처음 저장됨
2. `conversation_turn`: 사용자 메시지 한 건이 처리되고 상태가 저장됨
3. `goal_intake_started`: 목표를 구체화하는 대화가 실제로 시작됨
4. `goal_draft_created`: 필요한 정보가 모여 승인 가능한 초안이 생성됨
5. `goal_confirmed`: 사용자가 표시된 초안을 명시적으로 확정함
6. `plan_generated`: 확정 목표로 주간 계획 생성에 성공함
7. `first_action_completed`: 세션에서 처음으로 실행 완료가 기록됨
8. `daily_checkin_completed`: 아침 또는 마감 점검 한 회가 완료됨
9. `trial_started`: 반복 실패의 전제조건을 바꾸는 14일 실험이 시작됨

같은 요청이 재전송되어도 `(session_id, event_name, source_id)` 또는 `(session_id, source_id, call_index)` 고유키로 중복 기록하지 않는다.

## 운영 조회

일별 동향은 service role 전용 뷰인 `web_mvp_ai_cost_daily`, `web_mvp_funnel_daily`에서 확인할 수 있다. 정확한 기간·고유 세션·순차 전환 리포트는 원본 이벤트의 동일한 **[시작 시각 이상, 종료 시각 미만)** 범위를 읽는다. 일별 집계 뷰의 세션 수를 합치거나 서로 다른 세션 그룹의 단계별 숫자를 나눠 전환율을 계산하지 않는다.

### 무료 개발용 실행

```powershell
cd web-mvp
npm run verify:offline
npm run report:demo
npm run report:metrics -- --input=../logs/exported-metrics.json --from=2026-09-01 --to=2026-09-16 --country=KR --locale=ko-KR --json
```

- 기본 `report:metrics` 실행은 사용법만 표시한다.
- `--demo`는 고정된 가상 이벤트로 리포트를 만들며, 가상 비용을 실제 지출로 표시하지 않는다.
- `--input`은 로컬 JSON의 `usageEvents`와 `productEvents` 배열을 집계한다. DB 필드명 그대로 `id`, `session_id`, `occurred_at`와 각 비용·이벤트 필드가 필요하다. 잘못된 숫자·날짜·누락된 배열은 오류로 처리한다.
- `verify:offline`은 에이전트/앱 테스트, 웹 및 비용 모듈 타입 검사, 웹 빌드, ESLint/knip, 리포트와 평가 계획 생성을 실행한다. 외부 네트워크 요청을 차단하고 각 결과·소스 지문을 `logs/offline-development/<실행시각>/`에 저장한다.
- 결과 리포트에는 세션 ID·대화 원문·자격증명이 포함되지 않는다.
- `--out`은 기존 파일을 덮어쓰지 않는다. 새 파일명을 사용한다.

### 운영 데이터 조회

실제 DB 조회를 할 때만 `--live`를 사용한다. 키는 운영자 로컬 환경의 `SUPABASE_SERVICE_ROLE_KEY`, URL은 `SUPABASE_URL` 또는 `VITE_SUPABASE_URL`을 사용한다. service role 키를 `VITE_` 변수나 브라우저 코드에 넣지 않는다.

```powershell
npm run report:metrics -- --live --days=30 --out=../logs/metrics-30d-new.md
```

현재 사용자 방침에 따라 이번 작업에서는 실DB 조회와 유료 평가를 실행하지 않았다. 조회 코드는 모의 HTTP 응답으로 검증했다. DB 조회 자체는 모델을 호출하지 않지만 기존 인프라 사용량은 발생할 수 있다.

- 시각과 ID로 안정적으로 정렬하고 실제 반환된 페이지 길이를 따라 조회한다.
- 서버가 요청한 1,000개보다 적게 반환해도 정확한 전체 건수까지 읽는다.
- 조회 중 건수 변화·페이지 누락·잘못된 응답·시간 초과는 불완전한 성공 리포트로 처리하지 않는다.
- HTTP 오류 응답 본문과 키를 출력하지 않는다.

### 지표 해석

1. **원가:** 모든 기록의 토큰 비용이 산정됐을 때만 총 추정액·평균을 표시한다. `partial`이나 `unpriced`가 있으면 산정 가능한 금액 합계를 별도로 표시하고 전체 추정액과 평균은 `null/미산정`으로 둔다. 기록이 없다는 사실은 비용 0을 의미하지 않는다.
2. **재시도율:** 추가 시도 횟수를 호출 수로 나누지 않는다. 재시도를 한 번 이상 수행한 호출 수 ÷ 기록된 호출 수로 계산한다. 추가 시도 총횟수는 별도로 표시한다.
3. **전환율:** 기간 안에 목표 설계를 시작한 세션을 대상으로 초안→확정→계획→첫 실행의 시각 순서를 확인한다. 기간 중 실행만 한 재방문 세션은 해당 전환 분자에 섞지 않는다. 동일 시각에 저장된 연속 전환은 인정한다.
4. **독립 활동:** 전체 이벤트 횟수와 고유 세션을 별도 활동 표로 표시한다. 일일 점검·실험은 여기에서 확인한다.
5. **국가·언어:** 같은 필터를 비용과 전환에 모두 적용하며 모델·작업별 비용도 국가·언어별로 나눈다.
6. **단위:** 모델 호출은 사용자 메시지 한 건과 다르다. 한 메시지 처리 중 여러 모델 호출이 발생할 수 있다. 익명 브라우저 세션 수는 사람 수와 다르다.
7. **관측 한계:** 기록 도입 전 지출, 기록 실패, 응답을 받지 못한 청구, 삭제·만료된 세션의 측정 행은 빠질 수 있다. 전 기간 총 청구액이나 확정 수익으로 표현하지 않는다. 기간 말에 시작한 세션은 후속 전환이 아직 관측되지 않을 수 있다.

## 품질·수익 판단 규칙

- 비용 절감 실험은 언어별 대화 품질 평가를 통과한 경우에만 채택한다.
- `partial_cost_calls`와 `unpriced_calls`가 1건이라도 있으면 총비용을 완전한 값으로 표현하지 않는다.
- 재시도율과 평균 지연이 상승하면 단가 절감과 별도로 사용자 경험 회귀로 본다.
- 목표 확정률만 보지 않고 `first_action_completed`와 `daily_checkin_completed`까지 연결해 실제 가치를 판단한다.
- 국가별 순매출이 연결되면 AI 비용 비율 30% 이하를 1차 운영 가드레일로 사용한다.

1. `0020_web_mvp_metrics.sql` 마이그레이션 적용

4. `partial`·`unpriced` 호출이 누락 비용으로 표시되는지 확인
5. [x] 운영자용 로컬 리포트의 기간별 원본 이벤트 집계·모의 조회 검증 구현 (실DB 리포트 대조는 별도)

함수를 먼저 배포하더라도 측정 쓰기는 대화·계획·체크인을 실패시키지 않지만, 그 사이의 지표는 유실될 수 있다. 따라서 마이그레이션을 먼저 적용한다.
