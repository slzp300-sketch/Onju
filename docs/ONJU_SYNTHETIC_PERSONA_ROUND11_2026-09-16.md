# 온주 — 11차 가상 사용자 20명 추가 진단·작업로그

작성: 2026-09-16 · 요청: “좋아 그러면 가상이용자 추가해서 다시한번 검증해보자”

후속 수정 완료: 아래는 수정 전 진단 기록이다. 이후 [1~6번 및 제약 구조 보완](WEB_MVP_WORKLOG_2026-09-16_STRUCTURAL_CONSTRAINTS.md)에서 입력·기대값을 유지한 채 878/878 조건을 통과했다. 실패 51개는 0개가 됐으며, 기존 차수를 포함한 7,402조건·테스트 2,188개·전체 29개 검사 묶음을 동일 소스로 두 번 통과했다. 실제 모델 품질 검증·배포는 수행하지 않았다.

## 결론

21~47세, 한국어 10명·영어 10명의 가상 설정을 추가했다. 기존 185명과 ID가 겹치지 않는 누적 가상 설정 205명이다. 실제 참여자는 0명이다.

신규 **878개 조건 중 827개 통과·51개 실패**가 동일 소스·동일 기대값으로 두 번 재현됐다. 12개 프로필에 실패 조건이 있고 8개 프로필은 모두 통과했다. 실패 51개는 독립 결함 51개나 사용자 실패율이 아니라, 같은 원인을 저장·재로딩·계산·처리기 경로에서 확인한 조건 수다. 의미·원인별로는 **6개 보완 유형**으로 정리한다.

기존 1~10차 조건 6,524개와 테스트 2,057개는 모두 통과를 유지했다. 이번에는 진단만 했으며 제품 코드를 수정하지 않았다. 기존 검사에서 확인되는 회귀는 없지만, 모든 미검사 표현에 회귀가 없다고 증명한 것은 아니다.

## 방법과 범위

- 새 데이터: `web-mvp/qa/persona-pilot/round11-personas.mjs`.
- 새 실행 도구: `web-mvp/qa/persona-pilot/run-round11.mjs`.
- 10개 상황 유형을 한국어·영어로 짝지은 20개 가상 설정이다. 공통 초기 수집 순서를 재사용하므로 독립적인 실제 대화 연구 20건으로 해석하지 않는다.
- 초기 목표/기간 순서를 번갈아 배치하고, 뒤에 정보 정정·예산 변경·미측정 복귀·잘못된 추출 후보·정상 대조를 붙였다.
- 기대값과 도구 후보를 실행 전에 작성했다. 모델이 스스로 정보를 추출한 결과가 아니라 작성된 후보가 실제 제품 경계를 통과하는지 검사한다.
- 작성된 여정 발언 84개, 별도 저장 경계 30개, 모의 응답을 사용한 실제 수집 처리기 경로 22개, 예산 파서 검사 12개, 초안 검사 후보 24개다.
- 처리기 22개 중 5개는 인라인 답변까지 반환했고 17개는 수집 도구 결과를 확인한 시점에 의도적으로 종료했다. 실제 모델 완결 대화 22건이 아니다.
- 초안 후보 24개 중 23개는 실행 제약 검사에 도달했다. 영어 격주 예산 1개는 수집 경계에서 안전하게 거절되어 초안 검증에 도달하지 않았다.
- 초안 검사는 유효한 카드에 대한 `goalFeasibilityIssue` 검사다. 여기서 충돌을 놓쳤다고 운영 환경의 모든 승인 경계를 통과했다는 뜻은 아니다.
- 모든 진단은 네트워크 차단 상태다. 공급자 API, 운영 DB, 실제 세션, 배포는 사용하거나 변경하지 않았다.

### 1. 반복 요일 약어

KR-96의 월·수·금 표현은 단위·총량 일부만 인식되어 `weeklyMinutes: 20`, 일별 제한 없음으로 남는다. 이 상태에서 화요일 5분 카드의 충돌 결과는 `null`이다. 단순히 사용자에게 재확인하는 안전한 실패가 아니라 **부분 해석 후 제한 누락**이므로 먼저 막아야 한다. US-91의 약어는 미해석으로 차단되므로 같은 유형 안에서도 위험 양상이 다르다.

전체 요일 이름을 쓴 대조는 통과했다. 근거 코드: `goalDays.ts`의 `dayToken`은 온전한 요일 이름만 인식한다. 숫자가 파싱되었다는 이유만으로 요일 조건까지 모두 해석했다고 취급하지 않는 경계가 필요하다.

### 2. 남은 분량

KR-102와 US-97은 완료 3개와 남은 5개가 함께 있는 발언이다. 잘못 추출한 5개 후보가 직접 저장과 실제 수집 처리기 양쪽에서 통과했다. US-97의 저장 후 계산은 `current: 5`, `target: 8`, `remaining: 3`이다. 실제 발언은 남은 수량이 5개이므로 계획 부담을 작게 계산할 수 있다.

`goalFactBinding.ts`는 `remaining`, `unfinished`, `진행 중` 등을 구분하지만 이번 `남았어`, `left to do`를 명시적 미완료 의미로 묶지 못해 `unspecified`가 된다. 수량의 역할을 **목표 총량·완료량·남은량·진행량**으로 구분하고, 역할이 불명확한 후보를 완료량으로 쓰지 않는 방향이 필요하다. 정상 후보인 완료 3개 대조는 통과했다.

### 3. 목표별 예산의 적용 범위

KR-99·US-94에서 한 목표의 80분을 전체 예산 `capacity.summary`에 저장하는 후보가 받아들여진다. 원문에는 80분과 25분이 함께 있어 계약은 `unresolved`가 되고 실제 초안에는 느슨한 80분 허가로 쓰이지 않는다. **잘못된 요약 저장과 대화 정체** 문제이지, 이번 결과만으로 모든 목표에 80분이 실제 확정 배치됐다고 주장하지 않는다.

현 계약의 시간 적용 범위는 목표별로 분리되지 않는다. 전체 예산인지 특정 `goalId`의 예산인지 표현하고, 부분 예산을 전체 필드에 쓰는 후보는 거절하거나 적절한 목표 필드로 분리해야 한다.

### 4. 독립적인 상한의 결합

KR-98·US-93의 주 60분과 하루 20분은 서로 충돌하지 않는 두 제한이다. 현재 별도 제약 결합 경로는 회당 시간 등이 있어야 동작하므로 이 조합은 미해석으로 남는다. 주간 총량 60분과 하루 상한 20분을 동시에 만족시키는 20분×3일은 허용하고, 하루 30분 또는 20분×4일은 거절해야 한다.

가용량을 한 개의 시간 숫자로 강제 변환하지 말고 주간 총량·일별 상한·횟수·회당 제한을 서로 독립된 제약으로 평가하는 방향이 필요하다.

### 5. 설명용 명사와 실제 단위 분리

인용 사례 KR-101·US-96에서는 **친구·동료의 시간 저장은 올바르게 거절**했다. 문제는 사용자의 진짜 15분도 원문 계약에서 미해석이 된다는 점이다. KR-105의 전체 시간 설명 문장도 같은 문제다.

`goalCapacity.ts`는 소비하지 못한 `시간`, `time` 같은 문자열이 남으면 부분 수량일 수 있다고 보고 차단한다. 숫자에 결합된 미해석 단위와 문장의 일반 명사를 구분하지 못한다. 제한을 보호하는 검증 자체를 제거하기보다, 수량 구간과 설명 구간을 구분하는 보완이 필요하다.

### 6. 사람의 공동 소유와 목표의 합산 분리

US-94·US-100의 `both goals combined`는 한 사람이 두 목표에 합쳐 쓸 시간이다. `goalFactBinding.ts`의 `collective` 판정이 `combined` 단어만으로도 참이 되어 `capacity_not_decided`로 거절한다. 부부·가족의 합산 시간을 본인 시간으로 저장하지 않는 기존 보호는 유지하되, **누가 쓰는 시간인지**와 **어떤 목표에 나누는 시간인지**를 분리해야 한다.

## 통과를 유지한 대조

- 격주 90분/중간 주 0분을 매주 45분으로 만들지 않았다. 달력·주별 구조가 없는 현재 검증 범위에서 미해석 또는 수집 거절로 안전하게 막았다. 격주 계획 지원을 완료했다는 뜻은 아니다.
- 미측정으로 돌아갈 때 과거 시간 한도가 남지 않고, 목표·기간은 유지했다.
- 같은 발언의 60분 철회와 30분 정정을 구분했다.
- 평일 10~15분·주말 20~30분의 범위와 일별 상한을 유지했다.
- 인용한 다른 사람의 3시간을 본인의 시간으로 저장하지 않았다.
- 전체 요일 이름과 실제 완료 3개 후보는 정상 처리했다.
- 기존 10차에서 수정한 747개 조건도 모두 통과를 유지했다.

## 진단 코드 자체 오류의 정정 이력

첫 탐색 결과는 [866조건·802통과·64실패](../logs/persona-pilot-round11/2026-09-16T08-18-22-291Z/results.json)에 그대로 보존한다. 아래는 제품 수정이 아니라 잘못 작성한 진단의 정정이다.

1. **즉시 반환하는 수집 결과 누락:** 다음 모의 모델 호출에서만 도구 결과를 읽던 진단기를 보완해, 인라인 답변 반환 시 실제 `record_goal_brief` 이벤트도 읽는다. 정상 경로를 실행 미도달·미수락으로 잘못 센 8개 실패가 제거됐다. 저장 상태에 대한 기대는 바꾸지 않았다.
2. **미측정 계약 객체의 존재:** 객체가 없어야 한다는 기대는 기존 계약과 달랐다. 실제 적용 제한이 `unspecified`이고 주간 시간·횟수·회당 시간 모두 비어 있는지로 변경했다. 잘못된 실패 4개가 제거됐고, 총 조건은 12개 늘었다.
3. **격주 예산의 조기 거절:** 초안 경계 전 `capacity_requires_grounded_measurement`로 거절하는 것도 동일한 안전 결과다. 이 1개를 제품 실패에서 제외하되, 초안 검사에 도달하지 않았음을 보고서에 별도로 남겼다.

최종 878개 조건의 데이터·진단기를 동결한 후 두 번 실행했다. 실제 제품 실패를 없애기 위해 입력 문장을 쉬운 표현으로 바꾸거나 상태 기대값을 완화하지 않았다. 수정 이력은 데이터 파일의 `round11FixtureCorrections`와 JSON에도 보존했다.
