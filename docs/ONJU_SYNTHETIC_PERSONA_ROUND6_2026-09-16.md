# 온주 6차 가상 이용자 30명 추가 진단·작업로그

작성: 2026-09-16 · 사용자 요청: “30명 가상 이용자 추가해주고, 검증 다시 진행해”

> 후속 업데이트: 사용자 보완 승인으로 아래 9개 유형을 로컬 Site에 수정했다. 새 조건 1,080/1,080, 누적 95명 조건 3,254/3,254, 테스트 1,345개 및 전체 검사 24개 묶음이 최종 동일 소스에서 두 번 통과했다. [보완 작업로그](WEB_MVP_WORKLOG_2026-09-16_PERSONA_ROUND6_FIXES.md). 아래 본문은 수정 전 진단 기록이며 실패 결과를 보존한다. 유료 API 호출·배포는 하지 않았다.

## 결론

새 가상 설정 **30명**을 추가했다. 한국어 15명(KR-36~50), 영어 15명(US-31~45), 20~49세이며 기존 ID와 중복되지 않는다. 누적 가상 설정은 **95명**, 실제 참여자는 **0명**이다.

새 검사 **1,080개 조건 중 1,034개 통과·46개 실패**가 같은 코드와 데이터로 두 번 재현됐다. 실패 조건은 **9개 보완 유형**으로 묶었다. 기존 65명의 2,174개 조건, 기존 회귀 테스트 1,204개 및 전체 무료 검사 23개 묶음은 모두 다시 통과했다.

이번 요청에 맞춰 **진단만 진행했다. 제품 코드 수정·배포·커밋·푸시·운영 DB 변경은 하지 않았다.** 새 검사와 원시 결과, 로컬 작업로그를 저장했다. 공급자 API 호출 0회, 이번 추가 모델 API 비용 $0이다.

기존에 수정한 입력이 다시 실패한 것은 아니다. 같은 의미를 다른 문법·어순·주체·시간 단위로 전달할 때의 추가 공백이다. 단, 기존 검사 통과를 새 30명의 조건까지 전부 통과했다는 뜻으로 해석하면 안 된다.

## 검증 방식과 증거 범위

- 가상 상황은 대학생, 취업 준비, 야근, 교대근무, 육아·돌봄, 매장 운영, 프리랜서, 이직 등으로 구성했다. 실제 면담이나 설문 자료가 아니다.
- 공통적인 목표 설정 흐름 4개 발언을 각 사례의 출발점으로 사용했다. 목표 복원 여정 2개 발언을 더해 **작성 발언 122개**다. 이 기본 발언은 상당 부분 템플릿을 공유하며 서로 독립적인 실제 대화 122건을 뜻하지 않는다.
- 별도 상태 검사 **60개**: 의도한 정상 추출, 잘못된 모델 후보, 비교용 명확한 표현을 구분했다.
- 실제 에이전트 처리 함수의 수집 경로 **11개**: 도구 인자의 실제 스키마를 검사하고 모의 응답을 주입했다. 모델을 실제로 부르지 않았다.
- 추가 계산 검사: 구조화 시간 예산 **7개**, 빈도 정규화 **2개**, 유효한 작성 초안의 한도 검사 **12개**.
- 저장 전후의 상태, 원본 상태 불변, JSON 재로딩, 빠진 정보와 다음 단계, 계산 결과를 기록했다.
- 실제 에이전트 11개 경로는 모두 수집 결과를 관찰한 직후 의도적으로 종료했다. 완성된 실제 대화 턴, 최종 초안 승인, 운영 웹 E2E 검사가 아니다.
- 모의 콜백 진입 29회, 작성한 응답 반환 18회다. 나머지 11회는 수집 결과를 읽은 뒤 종료하는 경계다. 실제 API 호출은 0회이며 도구 스키마 등 검사 데이터 오류도 0건이다.
- 동일한 근본 원인이 직접 저장·에이전트 경로·여러 필드에서 중복 집계된다. 46개는 독립된 제품 결함 수가 아니다.
- 16개 가상 설정에서 실패가 관찰됐다. 일부러 표현 경계를 탐색한 표본이므로 이를 “이용자 53% 실패” 같은 서비스 실패율로 환산할 수 없다.
- 원래 데이터와 기대값은 첫 실행 후 수정하지 않았다. 실패를 통과시키기 위한 기대값 변경, 제품 수정, 이전 진단 덮어쓰기는 없었다.

## 9개 보완 유형

### 1. 간접 거절을 확정으로 저장 — P1 · 6개 실패 조건

- KR-36: “책 6권까지 읽겠다는 뜻은 아니었어. 기존 목표를 유지해줘.” → 기존 책 3권이 6권으로 바뀐다.
- US-31: “I am not committing to 6 books. Keep my existing goal.” → 기존 3권이 6권으로 바뀐다.
- 둘 다 직접 저장과 실제 수집 처리 경로에서 잘못된 후보를 허용했다. 명시적 긍정 변경 대조군은 정상이다.

원인: 부정 표현 검사가 일부 정해진 동사·어미 형태에 의존한다. “아니었어”, “am not committing”처럼 같은 거절을 다른 문법으로 표현하면 놓친다.

보완 기준: 값이 있다는 사실이 아니라 **그 값에 대한 사용자의 확정·거절 의도**를 보존해야 한다. 거절 수치를 후보로 추출했더라도 저장 시점에는 차단해야 한다.

### 2. 강사·멘토를 본인으로 오인 — P1 · 6개 실패 조건

- KR-37: “강사는 글 8편을 완성했어. 나는 글 1편이야.” → 본인 기록이 8편으로 바뀐다.
- US-32: “My mentor finished 6 projects. I have finished 1 project.” → 본인 기록이 6개로 바뀐다.
- 자기 기록을 명확하게 바꾼 비교 사례는 정상이다.

원인: 타인 역할 이름 목록에 없는 강사·mentor는 본인이 아닌 주체라는 의미를 잡지 못한다.

보완 기준: 역할 이름을 계속 늘리는 것에 그치지 않고 **주체와 수치의 연결**을 다룬다. 누구의 결과인지 불확실한 정보는 본인 데이터로 확정하지 않는다.

### 3. 문장 뒤의 조건을 무시하고 기간 변경 — P1 · 6개 실패 조건

- KR-38: “기간을 12주로 늘릴게, 야근이 끝나면. 그전에는 바꾸지 마.” → 즉시 8주에서 12주로 바뀐다.
- US-34: “Change the period to 12 weeks only after my shifts settle down. Keep 8 weeks for now.” → 즉시 12주로 바뀐다.
- 지금 즉시 늘리겠다는 대조군은 정상이다.

원인: 조건이 변경 동사 앞에 오는 패턴에 치우쳐 있다. 조건절이 뒤에 오는 경우와 그전까지 유지하라는 관계가 충분히 반영되지 않는다.

보완 기준: 변경 내용과 함께 **실행 시점·조건 충족 여부·현재 유지 의도**를 판단한다. 아직 성립하지 않은 변경을 예약 또는 적용했다고 말하지 않는다.

### 4. 같은 절의 타인 정보 때문에 본인 정보도 버림 — P2 · 3개 실패 조건

KR-40: “남편은 책 5권이고 나는 책 2권이야.”에서 본인 책 2권 후보를 차단하고 기존 1권으로 남긴다. 직접 저장과 에이전트 수집에서 확인했다. “남편은 책 5권이야. 나는 책 2권이야.”처럼 문장을 나누면 정상 반영된다.

원인: 같은 절에 타인 주체가 있으면 절 전체를 타인 정보로 보는 보호가 과도하다.

보완 기준: **저장하면 안 되는 정보 차단**과 **정상적인 본인 정보 수용**을 한 세트로 검사한다. 문장 단위 차단이 아니라 후보별 주체 범위가 필요하다.

### 5. not 뒤의 큰 시간 예산을 저장 — P1 · 3개 실패 조건

US-33: “I only have 30 minutes per week, not 2 hours per week.”에서 잘못된 후보 “2 hours per week”를 넣으면 그대로 저장한다. 같은 원문에서 올바른 “30 minutes per week” 후보는 정상 저장된다.

원인: “don't have” 같은 동사 부정은 검사하지만 **작은 값, not 큰 값**이라는 수치 대조를 검사하지 못한다.

보완 기준: 같은 문장 속에서 긍정된 수치와 부정된 수치를 분리해야 한다. 후보 원문이 정확히 존재한다는 이유만으로 저장을 허용하면 안 된다.

### 6. “아직 설정하지 마”가 가리키는 앞의 목표를 확정 — P1 · 3개 실패 조건

US-35: “5 books sounds good, but don't set it yet. I need to think about it.” → 기존 3권을 5권으로 바꾼다. 지금 설정하라는 대조군은 정상이다.

원인: “haven't decided yet”는 다루지만 “don't set it yet”가 앞의 목표를 가리키는 연결은 다루지 못한다.

보완 기준: 수치가 없는 뒷문장도 **앞의 후보를 유보하거나 취소하는 말**이면 함께 검증해야 한다. 별개 일정의 미정과는 구분해야 한다.

### 7. 주말 제외를 포함 요일로 잘못 계산 — P2 · 6개 실패 조건

- KR-41: “매일 1편, 주말은 제외” → 기대 주 5편, 실제 주 2편. 8주 전망이 40편이 아니라 16편이다.
- US-37: “1 article per day except Saturday and Sunday” → 기대 주 5편, 실제 주 7편. 8주 전망이 40편이 아니라 56편이다.
- “평일 매일 1편”, “1 article each weekday” 대조군은 주 5편으로 정상 계산한다.

원인: 주말 단어의 존재만으로 주말 포함을 판단하고, except/제외의 방향을 계산하지 못한다.

보완 기준: **포함 요일 집합 - 제외 요일 집합**으로 주간 빈도를 계산한다. 국가별 공휴일까지 반영했다는 주장은 이번 범위에 포함하지 않는다.

### 8. 자연스러운 복합 시간 표현을 해석하지 못함 — P2 · 8개 실패 조건

| 사례 | 표현 | 기대 계산 | 실제 |
|---|---|---|---|
| KR-43 | 주당 1시간 30분 | 주 90분 | unresolved |
| KR-44 | 주당 30분~1시간 | 주 30~60분 | unresolved |
| US-38 | three 20-minute sessions per week | 주 3회 × 20분 = 60분 | unresolved |
| US-40 | half an hour per day | 하루 30분 × 7 = 주 210분 | unresolved |

각 사례에서 구조화 예산 검사 1개와 초안 오류 종류 검사 1개씩 실패했다.

**안전상 중요한 구분:** 이번에는 해석 실패를 무제한으로 취급하지 않았다. 네 경우 모두 초안을 `goal_capacity_unresolved`로 차단했다. 기대했던 `goal_capacity_conflict`와 오류 종류가 달랐고, 사용자가 이미 이해 가능하게 말한 값을 다시 확인해야 하는 불편이 남은 것이다. 한도 초과 초안이 운영에서 실제 승인됐다고 주장하지 않는다.

보완 기준: 혼합 단위의 합, 서로 다른 단위의 범위, 형용사형 시간, 반 시간 표현을 공통 구조로 변환한다. 뜻이 불명확한 입력을 임의로 계산하지 않는 보호는 유지해야 한다.

### 9. 영어의 명시적인 목표 유지 선택을 거절 — P2 · 5개 실패 조건

US-43: 현재 주 1편, 목표 8주 32편으로 높은 강도를 확인한 상태에서 “I understand the extra effort and choose to keep this target for the first week.”라고 선택해도 저장하지 못하고 feasibility 단계에 남는다. 직접 상태 검사와 에이전트 처리 모두 동일하다. “Should I keep this target?”라는 질문을 동의로 저장하지 않는 대조군은 정상이다.

원인: `feasibility_acceptance`는 근거를 확인한 뒤 “유지·도전·진행” 등 한국어 표현을 요구한다. 영어의 명시적 선택을 위한 의미 검사가 없다.

보완 기준: 명확한 선택과 단순 질문을 언어에 관계없이 구분하고, 영어 사용자도 다음 단계로 갈 수 있어야 한다. 높은 목표 유지 동의가 확정된 시간 상한을 무시하는 권한이 되어서는 안 된다.

## 정상 동작을 확인한 범위

- 기본 여정 122개 발언의 상태 조건 634개 및 명확한 대조 조건 103개 전부 통과.
- 한국어 미결정 목표 보호와 별도 일정의 미결정 구분, 곡선 따옴표의 영어 부정 처리.
- 평일 하루 20분 → 주 100분, 주당 2회 총 40분과 회당 20분 구분.
- 영어 회당 10~20분 범위 × 주 2회 → 주 20~40분.
- 실행 기록 0회와 가용 시간 0분의 차이, 현재 수준 미측정과 가용 시간 미측정의 차이.
- 명시적 목표 제외, 존재하지 않는 날짜 차단, 새로운 마감일 변경.
- 목표 복원 후 옛 세부 정보 자동 재주입 방지, 새로 말한 현재 수준 기록.
- 잡담으로 전환하거나 다시 돌아온다는 발언만으로 목표가 바뀌지 않음. 실제 모델이 자연스럽게 잡담에 답하는지는 별도 검증 대상이다.
- 예시라고 명시한 가상 완료량을 실제 완료량으로 저장하지 않음. 모든 가정 표현이 안전하다는 일반화는 하지 않는다.

## 반복되는 문제에 대한 판단과 다음 우선순위

이번 증거는 실제 모델의 성능이 저하됐다는 뜻이 아니다. 실제 모델은 부르지 않았다. **잘못된 추출 후보를 상태 변경으로 받아들이는 방어와, 정상 표현을 받아들이지 못하는 방어의 과잉**을 함께 확인한 것이다.

현재처럼 역할·부정어·접속사 목록만 계속 추가하면 다음 표현 조합에서 또 공백이 생길 수 있다. 이후 보완은 아래 순서가 적합하다. 이번 요청에서는 구현하지 않았다.

1. 후보별 **값·주체·확정 여부·시점·조건·연결된 정정/유보 근거**를 함께 다루는 저장 검증 기준을 정리한다.
2. 거절·유보·타인 값을 막는 검사와 정상 본인 값은 받아들이는 검사를 짝으로 유지한다. 애매하면 기존 상태를 보존한다.
3. 시간·빈도는 수학적 구조를 별도로 계산한다. 요일 포함/제외, 단위 변환, 합·곱·범위를 구분한다.
4. 영어 명시 선택의 처리 공백을 없앤다. 한국어 문구 유무가 기능 진행 조건이 되지 않게 한다.
5. 위 보완 뒤 같은 95명 데이터를 재검증한다. 실제 추출 품질·대화 자연스러움은 이후 별도 비용 승인을 받은 모델 평가로 확인한다.

## 비용과 한계

외부 네트워크 차단 장치 아래 실행했으며, 실제 고객 정보나 연락처·API 키를 가상 데이터에 넣지 않았다. 실제 공급자 호출 0회 / 이번 추가 모델 API 비용 **$0**다. Codex 구독료·개발 시간·기존 인프라·과거 청구액을 포함하는 금액이 아니다.

실제 모델의 추출 오류 빈도, 자연스러움, 응답 속도, 사용자 만족도, 지속 사용, 결제 의향, 매출을 측정한 결과가 아니다. 지역·직업·연령은 가상 맥락이며 대표성 있는 모집단 표본이 아니다. 6차 운영 브라우저 E2E·최종 초안 전체 승인 경로도 검사하지 않았다.

**현재 상태: 새 30명 진단 완료, 9개 보완 유형 확인, 아직 미수정.** 노션 등록·운영 DB 변경·배포·커밋·푸시 없음. 이 문서와 로컬 원시 로그가 이번 작업 기록이다.
