# 온주 — 70% 확신 조건과 유료 평가 보류

작성: 2026-09-17. 제품 코드는 로컬 빌드 22 유지. 이번 변경은 평가 절차이며 답변 생성 모델/프롬프트/공개 서비스 변경이 아니다.

## 사용자 조건과 현재 판정

사용자 요청: 실답변 품질 개선에 70% 이상 확신할 수 있을 때만 유료 호출하고, 그렇지 않으면 무료로 보완한다.

현재 판정은 **보류**다. `confidencePercent`는 `null`이다. 측정하지 않은 확률을 60%, 70%, 80% 등으로 만들지 않는다. 70%의 기준을 테스트 통과율, 문서 길이, 점수 평균으로 대체하지 않는다. 평가 스크립트의 숫자 검사는 기록된 검토 판단을 확인할 뿐 그 판단을 과학적으로 증명하지 않는다.

현재 증거:

- 이전 실제 전달된 첫 3턴에서는 사용자 조건 반영, 필요한 정보 묶음 질문, 모르는 참조를 추측하지 않는 동작을 확인했다.
- 상세한 실행법·이유·기록·조정 설명은 모델이 실제 생성했지만 앱이 거절한 후보 안에 있었다. 정상 전달된 최신 계획으로 세지 않는다.
- 이전 4번째 턴은 HTTP 409로 끝났고 실제 후속 수정 응답은 없다. 원래 후보의 모호한 조정 설명, 일부 시간 구성 문제도 발견됐다.
- 로컬 빌드 20~22의 구조 보완과 작성한 대조 자료의 통과는 확인했지만, 그것을 최신 모델의 새 응답 성공으로 분류하지 않는다.
- 새 실답변의 이해력·깊이·전달 안정성을 비용 없이 직접 증명할 수는 없다. 이번 조건을 충족하지 못한 상태에서 확인 목적의 유료 호출을 먼저 하지 않는다.

## 무료로 보완한 부분

1. 저장 응답 검사 결과를 두 갈래로 분리했다. `structuralChecksPassed`와 `paidEvaluationDecision`은 별도다. 대조 사례가 모두 통과해도 `HOLD_PENDING_REAL_RESPONSE_QUALITY_REVIEW`를 유지한다.
2. `docs/agent/coaching-paid-review.json`에 의도 이해·근거·질문 적절성·깊이·실행 명확성·맥락 유지·답변 전달·후속 수정의 8개 검토 항목을 기록했다. 부분 근거/거절 후보/미검증을 구별했다.
3. `web-mvp/scripts/coaching-paid-gate.mjs`를 추가했다. 기본 거절이며 명시적 근거 검토, 확신 판단, 제품 소스 일치, 남은 예산, 미해결 문제 여부를 확인한다. 통과하더라도 `statisticalConfidenceEstablished`와 `liveQualityValidated`를 true로 만들지 않는다.
4. 원문 재현용 유료 진입점 3개에 검사를 연결했다. 환경 키·세션 토큰을 읽거나 새 실행 기록을 쓰기 전에 중단한다. 과거 후속 검사 2개는 오래된 예산 승인을 재사용하지 않도록 중단시켰다. 새로 실행하려면 새 범위/예산 검토가 필요하다.
5. 유료가 아닌 원문 입력 확인(dry run)은 계속 가능하다. 원문 사용자 입력 3개를 정확하게 읽고 모델 호출 0으로 종료되는 것을 확인했다.

이 차단은 해당 원문 재현 검사 도구에 적용된다. 서비스 전체의 API 키를 비활성화하거나 외부 사용자의 대화를 막는 변경은 아니다. 기존 별도 품질 평가기의 사용자 최종 검수 요건도 낮추지 않았다.

- 새 차단 검사 15개 + 기존 품질 근거 검사 18개 = 33개 통과.
- 전체 무료 검사 30개 그룹 PASS, 2,352개 테스트 = 루트 1,789 + Site 477 + 앱 53 + 세션 UI 25 + 여정 UI 8.
- 결과: `logs/offline-development/2026-09-17T07-52-31-399Z/summary.json`.
- 소스 지문: `2acf80a3c63a9cfed66caa78bd997539a8b3bcde62670a0eaf936b85c18a4857`, 666개 파일, 검사 중 소스 변경 없음.
- 첫 전체 실행에서 새 검사 코드의 작업 디렉터리 의존성을 발견했다. 저장소 절대 경로 기준으로 수정하고 하위 디렉터리에서 직접 검사한 뒤 전체 재실행했다.
- 저장 응답 재검사: `logs/reference-replay/saved-audit-2026-09-17T07-50-59-375Z/summary.json`. 대조 사례 8개 통과, 원본 증거/비용 기록 불변, 구조 검사 통과와 유료 보류를 함께 기록했다.
- 제품 함수 소스 지문은 이전 빌드 22와 동일: `72f956470490bf54c857288768cc04f9d32a649262d77b28379d0a564651a423`.
- 통과 수는 모델이 새 답변을 생성한 횟수나 품질 성공률이 아니다.

## 비용·다음 판단

추가 제품 모델 API 호출 0, 추가 비용 $0. 기존 총 승인 $3 중 예산상 잔여 $0.484389이며, 확인 응답 기반 추정 $0.996804와 미확인 예약 $1.518807은 그대로다. 예약은 실제 청구 확정액이 아니며 청구서 대조도 하지 않았다. 기존 예산이 남아 있다는 이유만으로 최신 품질 조건을 무시하지 않는다.

배포·커밋·푸시·Notion 쓰기 없음. 이번 보완만으로 답변 품질이 더 좋아졌다고 주장하지 않는다.

다음 근거 검토에서는 상세 계획의 실제 전달, 모호하지 않은 조정 방법, 후속 수정의 의미/조건 보존, 반복 질문·재작성·지연을 함께 본다. 새 유료 응답 없이 확인할 수 없는 부분은 미검증으로 남긴다. 조건을 변경하려면 제한된 탐색 검사를 별도로 명시적으로 허용받아야 하며, 현재는 그런 예외 승인을 가정하지 않는다.

OpenAI Docs 스킬과 [공식 평가 지침](https://developers.openai.com/api/docs/guides/evaluation-best-practices)을 참고해 자동 검사와 내용 검토를 구분했다. 구체적 사례/원문 근거 없이 '잘될 것 같다'는 판단만으로 통과시키지 않는 방향을 적용했다.
