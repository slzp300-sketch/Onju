## 근거와 수정

1. **설명 문장의 합계 오류:** 10월 23일 실제 응답은 서버 상태가 주 30분·8주인데 400분(6시간 40분)이라고 설명했다. `goalReplyArithmetic.ts`가 현재 원문 계약에서 주당 시간을 다시 계산하고 기간을 곱한다. 단일 개인 목표·known·고정 주간 분량·정수 주 단위 기간일 때만 계산한다. 캐시된 숫자 limits를 신뢰하지 않는다. 명시적인 동일 계획 기간의 시간 합계 주장은 전달·저장 전에 240분(4시간)으로 보정하고 `reply_arithmetic_grounding`에 횟수를 남긴다. 모델 입력에도 서버 계산값을 제공한다. 실행 행동·주간 30분·16세션·목표·승인은 바꾸지 않는다.
2. **범위를 벗어난 계산 방지:** 미정·추정·시간 범위·여러 목표·팀 공동 예산·날짜 마감은 정확한 기간 합계로 만들지 않는다. 과거 수행 기록, 사용자 인용, 질문, 기존/수정 비교, 다른 기간 대안은 보정 대상에서 제외한다. 현재 처리의 범위는 명시적인 한국어 계획 시간 합계이며 모든 자연어 산술을 해결했다고 주장하지 않는다. 합계는 가용 시간의 계획상 상한이며 실제 실행량·독서 속도·목표 달성을 보장하지 않는다.
3. **문단 길이로 인한 재호출:** 실제 학습 응답의 990자·961자 문단에 이미 빈 줄 경계가 있었다. 기존 경계에서만 900자 이하 문단으로 다시 묶는다. 표시 문장을 다시 합치면 원문과 같고, 글·수치·학습 단계 삭제가 없다. 900자·8문단·6,500자 제한은 유지한다. 빈 줄 없이 긴 단일 문단이나 분리 후 문단 수 초과는 계속 거절한다.
4. **이미 반영한 시간 정정을 다시 저장하는 반복:** 서버가 정정을 검증·반영한 같은 턴에서 모델의 근거 없는 중복 시간 후보가 거절되면, 다시 쓰기 도구를 호출하지 않고 응답만 가능한 경로로 전환한다. 거절한 후보를 성공으로 표시하거나 저장하지 않는다. 기존 확정 목표·일정은 그대로 두며, 다른 유효한 신규 사실이 함께 있으면 기존 기록 경로를 유지한다. `capacity_correction_reply_only` 이벤트로 남긴다.

## 진행 중 발생한 문제와 해결

- 첫 원본 응답 재생은 Claude 어댑터의 실제 생성 경로 대신 저수준 변환 함수만 사용해 기존 시간 요약 정규화를 빠뜨렸다. 그 결과 실제 운영 경로와 다른 근거 오류가 났다. 네트워크가 차단된 가짜 fetch를 사용해 실제 `createAnthropicMessagesAdapter.generate` 경로로 재생하도록 수정했다. 이후 재생이 통과했다.
- 학습 사례의 원본 분야 목록은 비어 있어 단일 분야 전체 합계 계산을 하지 않는 것이 올바른 동작이었다. 테스트에서 합계 계산 객체를 무조건 참조해 실패했다. 기대를 느슨하게 바꾸는 대신, 그 테스트의 목적에 맞춰 원문에서 재계산한 주간 한도 60분과 기존 기간 6주·미승인 상태를 직접 확인하도록 수정했다.
- 추가 코드 검토에서 `9시간 30분` 같은 복합 단위의 일부만 치환하면 남은 분 표현이 붙을 수 있음을 확인했다. 시간·분·괄호 단위를 하나의 덩어리로 처리하고 소수 시간도 검사했다. `목요일 총 20분`, `30분 / 주`, `10분씩` 같은 주간·회당 문장은 기간 전체 합계로 바꾸지 않는 회귀 검사도 추가했다.
- 저장된 원 응답은 합성 대화만 포함한다. 휴대 가능한 회귀 fixture에는 해당 합성 사례의 필요한 응답·근거만 복사했다. 비밀 API 키·운영 사용자 대화를 포함하지 않는다.
