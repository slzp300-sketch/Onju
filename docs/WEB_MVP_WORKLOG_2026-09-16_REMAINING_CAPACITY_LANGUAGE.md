# 온주 — 남은 실행 여건 표현 4유형 보완

작성: 2026-09-16 · 요청: “남은것까지 개선하자”

후속 상태: 아래는 10차까지의 보완 완료 기록이다. 이후 [11차 신규 가상 설정 진단](ONJU_SYNTHETIC_PERSONA_ROUND11_2026-09-16.md)에서 기존 검사는 통과를 유지했지만, 새 표현·조합에 관한 51개 실패 조건(6개 보완 유형)이 추가로 확인됐다. 이 파일의 과거 완료 범위와 새로운 미해결 범위를 구분한다.

## 범위

[목표 사실·실행 제약 구조 개선](WEB_MVP_WORKLOG_2026-09-16_STRUCTURAL_GOAL_FACTS.md) 이후 남아 있던 10차 진단의 네 표현 유형, 22개 실패 조건을 보완했다. 새로운 가상 인원을 만들거나 진단 기대값을 낮추지 않았다. 질문 순서·고정 답변·모델·공급자는 변경하지 않았다.

대상은 `logs/sites/onju-web-mvp/supabase/functions/onju-agent-v2/`의 Site 제품이다. 기존 앱과 루트 Edge Function의 다른 미커밋 변경은 보존했다. 배포·운영 DB 변경·커밋·푸시·노션 등록은 하지 않았다.

## 보완한 동작

| 유형 | 예시 | 보존하는 제약 |
|---|---|---|
| 평일·주말별 하루 횟수 | 평일 하루 한 번; 주말 하루 두 번 | 주 9회, 평일 하루 1회·주말 하루 2회. 회당 시간은 임의 생성하지 않음 |
| 특정 요일의 0분 예외 | 매일 20분, 단 수요일은 0분 | 주 120분, 수요일 배치 금지, 나머지 하루 최대 20분 |

일별 제한을 주간 합계로 요약해도 원래 제약은 별도 계약에 남는다. 새 저장과 재로딩뿐 아니라 원문이 남아 있는 옛 기록도 동일하게 검증한다. 기존 생성·수정·승인의 공통 실행 한도 검사로 연결되며, 허용하지 않은 요일의 초안은 확정 상태를 바꾸지 않고 거절한다.

### 구현

- `goalNumberNotation.ts`: 실행 여건 전용 숫자 정규화. 영어 0~99 단어·복합 수량과 한글 20~99 계열을 단위가 붙은 경우에 처리한다. 목표 결과량의 숫자 인식 범위를 무작정 넓히거나 저장 원문을 치환하지 않는다.
- `goalDays.ts`: 요일 단수·복수 표현을 공유하고, 명시적인 요일별 0분/0회 제한을 별도로 추출한다.
- `goalCapacity.ts`: 겹치지 않는 평일·주말 하루 횟수를 합산하고 일별 배열을 유지한다. 정확한 일별 예산에서 0 제한을 반영한 뒤 주간 합계를 다시 계산한다.
- `web-mvp/scripts/verify-offline.mjs`: 10차 진단을 상시 오프라인 검사에 편입했다. 이제 1~10차를 별도 실행 누락 없이 검사한다.

## 지원 경계와 안전성

- 횟수만 말하면 시간은 미정이다. 주 9회라는 말에서 주 90분 등 가상의 시간을 만들지 않는다.
- 서로 겹치는 요일 그룹, 대안 표현, 혼합된 미확인 단위, 그룹마다 서로 다른 회당 시간은 단일한 느슨한 한도로 합치지 않는다.
- 요일별 0 제한은 일별 예산이 확인된 경우에 계산한다. 주간 총량만 있거나 일별 범위의 최솟값 배분을 알 수 없는 경우에는 원문을 유지하고 미해석 상태로 남긴다.
- 공휴일처럼 달력 범위가 확인되지 않은 예외, 조건부·부정된 0 제한은 임의로 특정 요일에 적용하거나 삭제하지 않는다.
- 특수 하이픈은 파싱 사본에서 처리한다. en dash는 숫자 범위로 다루며, 역전된 범위나 지원하지 않는 혼합 수량은 뒷부분 숫자만 읽지 않고 미해석 상태로 처리한다.
- `twenty to thirty minutes`는 20~30분 범위를 유지한다. `twenty to 30 minutes`, `스무~서른 분`처럼 이번에 완전한 정규화 범위를 정의하지 않은 혼합/글자 범위는 안전하게 미해석 처리한다. 모든 자연어 수량 표현을 지원한다는 뜻이 아니다.
- 다른 사람·공동 시간, 미래 예상, 부정된 가용 시간을 본인의 현재 시간으로 저장하는 것은 기존 근거 검증이 계속 차단한다.
