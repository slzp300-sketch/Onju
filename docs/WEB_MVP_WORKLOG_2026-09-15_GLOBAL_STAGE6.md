## 범위와 보존

사용자의 “다음 진행하자”에 따라 [무료 보완 계획](ONJU_GLOBAL_BETA_NO_COST_PLAN_2026-09-15.md)의 6단계를 진행했다. 기존 원본 앱 `src/`, 모델 선택, 운영 API 설정과 DB, 현재 배포 사이트는 변경하지 않았다. 루트 웹과 별도 Site의 기존 미커밋 변경은 보존했다. 유료 평가, 실제 공급자 호출, 커밋·푸시·배포는 하지 않았다.

## 구현 및 발견한 문제 해결

1. 루트 웹의 큰 단일 화면 파일을 `App.tsx`(랜딩/라우팅), `Header.tsx`, 지연 로딩되는 `ProductApp.tsx`로 분리했다. 라우트별 기존 상태와 완료 콜백은 유지했다. 미사용 import와 기존 언어팩 소스 검사도 통과하도록 마무리했다.
2. 오프라인 빌드가 실행 환경의 키를 제거해도 Vite가 `.env.local`을 다시 읽을 수 있었던 경로를 막았다. 양쪽 Vite 설정에서 `ONJU_OFFLINE=1`일 때 환경파일을 비활성화하고 공개 API URL/키를 빈 값으로 고정한다.
3. Site 배포 빌드의 여러 상위/하위 `.env.local` 자동 탐색을 제거했다. 명시한 단일 파일 또는 프로세스 환경만 사용하며 예상 백엔드 호스트를 확인한다. 허용하지 않은 VITE 변수, 서비스/secret key, URL 내 자격증명·경로 등을 거절한다. 서버용 자격증명은 하위 빌드에 넘기지 않는다. 실제 환경파일/키를 이번 작업에서 읽거나 출력하지 않았다.
4. 실제 Site App·라우팅·SSE 클라이언트·화면·저장 경로를 사용하는 합성 통합 테스트를 만들었다. 모의 전송 응답은 실제 모델/DB와 분리했고, 잘게 나눈 UTF-8 SSE, 지연, 중복 전송, 예산 실패 재시도, 계획 저장 실패를 재현한다.
5. 영어 초안/계획의 분야명, 주간 실행 횟수, 기본 진행 지도, 피드백 선택지, 재연결 문구를 보완했다. 피드백 옵션을 모듈 최초 로드 시 번역하던 문제를 렌더링 시 번역으로 바꿔 언어 전환을 반영한다. 이미 저장된 사용자 목표·마일스톤 원문과 완료 ID는 변경하지 않는다.
6. 390px에서 긴 행동 제목이 한 줄 입력칸에 잘리던 것을 발견했다. 자동 높이 텍스트 영역으로 바꾸고 제목/창 크기/폰트 로드에 맞춰 높이를 갱신한다. 기존 blur/Enter 저장 동작은 유지했다. 요일별 행동·완료 기준·작은 대안의 스크린리더 이름도 영어로 제공한다.
7. 전체 검증에 통합 UI·배포 인벤토리를 추가했다. 인벤토리는 빌드 파일, 서버 소스, 두 migration 집합의 파일 크기/SHA-256과 환경변수 이름만 담는다. **검증 산출물에는 API가 비어 있으므로 `deployable:false`**로 표시했다. 실제 배포 전 동일 소스에서 승인된 공개 설정으로 재빌드해야 한다.
8. [6단계 배포 준비 계약](agent/global-beta/STAGE_6_RELEASE_READINESS.md)에 1~5단계 요구사항별 근거, 운영 사실 확인, migration ledger 충돌, DB→서버→프런트 적용 순서, 구버전 캐시·복구 방침, 한 번에 모은 후속 실제 평가를 정리했다.

## 두 번의 검토

- 1차: 단계별 요구사항과 실제 코드/테스트를 대조했다. 비용·세션·지역·삭제 계약의 경계를 유지하고, 모델 품질 평가 없이 할 수 있는 범위만 구현했다.
- 2차: 통합 테스트와 실제 로컬 모바일 화면을 확인하며 영어 잔여 문구/접근성 이름/긴 제목 잘림을 발견해 수정했다. 수정 후 다시 전체 검사를 통과시켰다. 초기 실패/중간 통과 실행도 로그에 남겼으며 **아래 최종 실행만 완료 근거**로 사용한다.

합성 데이터의 `pending_plan`과 현재 확정 계획을 구분하고 입력 자료 필드를 실제 계약에 맞춘 뒤, 새 계획에 허위 수정안·업그레이드 안내가 나타나지 않는 것도 테스트한다. 합성 데이터 보정은 운영 버그 해결 건수로 세지 않는다.
