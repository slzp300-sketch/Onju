### 공통 구조

- `goalEvidenceScope.ts`: 후보 값 주변의 주체·시점·거절·조건·미결정 검사를 공통화했다. 대화 답변을 고정 문구로 바꾸지 않았다.
- `goalIntakeEvidence.ts`: 기간·목표 제외/복원에도 같은 조건부·미결정 보호를 적용했다.
- `goalQuantity.ts`: 평일/주말 빈도와 같은 차원의 단위 비교를 제공한다. 화면용 원래 단위는 보존한다.
- `goalCapacity.ts` 신규: 주간 시간, 주간 횟수, 회당 시간의 최소·최대 구조와 `bounded` / `unresolved` / `unspecified` 상태를 반환한다.
- `goalFeasibility.ts`: 상담 중 계산과 초안 한도 검사가 동일한 시간 예산을 사용한다. 명시적인 수치 예산을 해석하지 못하면 무제한으로 통과시키지 않고 확인하도록 한다.

숫자 없는 유동적 일정은 사용자가 잘 모른다는 상태를 유지한다. 반대로 뒤집힌 범위·음수·최소값만 있는 예산·불명확한 주기·해석하지 못한 수량은 확정된 상한으로 간주하지 않는다. 0분 가용 시간과 현재 실행 이력 0회는 기존처럼 구분한다.

## 중간 검사에서 확인·해결한 사항

1. 초기 거절 검사가 `무리하지 않고`와 `동안 진행`을 잘못 차단했다. 한국어 동사와 부정어의 경계를 좁혀 정상 표현을 복구했다. 이 회귀 때문에 5차 중간 실행 한 번은 필요한 초기 목표가 없어 종료됐다. 이를 통과로 집계하지 않는다.
2. 저장 권한 보완 후 [중간 결과](../logs/persona-pilot-round5/2026-09-16T02-43-07-732Z/results.json)는 719/730이었다. 남은 11개 조건은 시간·빈도·단위 계산이었다.
3. 계산 구조 적용 후 [초기 수정 결과](../logs/persona-pilot-round5/2026-09-16T02-44-48-392Z/results.json)는 730/730이었다.
4. 새 변형 검사에서 한국어 접속사만 별도 절이 되는 경우와 영어 회당 `each`를 달력 주기로 오인하는 경우를 추가 수정했다.
5. 새 검사 작성 중 0분 예산에도 0분짜리 초안을 허용해야 한다는 기대 2개가 기존 계약과 충돌했다. 기존 0분 보호를 바꾸지 않고, **양의 실행안은 보류·확인**해야 한다는 검사로 정정했다. 원래 5차 730개 기대값에는 변경이 없다.
6. 후속 자체 검토에서 공백을 넣은 음수와 지원하지 않는 영문 수량을 명시적 예산으로 다루는 보호를 추가했다.
