# 추가 가상 사용자 진단 결함 보완 — 2026-09-16

## 요청과 범위

사용자 승인: “개선하고, 문제가 없을 때까지 이 작업을 반복하자. 우선 개선하자.”

앞선 10명 합성 진단에서 발견한 **6개 결함 유형**을 로컬 Site 에이전트에 수정했다. 답변 문구를 추가하는 대신, 사실의 정정·정보 대상·수량 비교·목표 제외를 처리하는 저장 경계를 보완했다. 가상 사용자 설정은 실제 인터뷰나 시장 통계가 아니다.

- 변경 대상: `logs/sites/onju-web-mvp/supabase/functions/onju-agent-v2/`와 오프라인 검사.
- 루트의 구형 에이전트·기존 모바일 앱·다른 미완료 변경을 덮어쓰지 않았다.
- 배포, 운영 DB 변경, 커밋·푸시, 외부 메시지 발송, 유료 모델 요청 없음.
- 확인 범위 내 실패가 없을 때까지 수정 → 변형 검사 → 전체 검사 → 재실행했다. 모든 자연어 표현이나 실제 모델 품질의 무결함을 의미하지 않는다.

## 1. 기간 정정과 과거 정보 구분

- 기존 기간이 있다는 이유로 새 기간을 무조건 버리던 실제 `record_goal_brief` 경로를 수정했다.
- 현재 사용자가 명시적으로 정정한 기간은 반영한다. 예: `Change the timeframe to 8 weeks.`, `8주로 할게.`, `Not 4 weeks, but 8 weeks.`.
- 같은 기간을 문장형으로 다시 보내도 기존의 간결한 라벨을 유지한다.
- 과거 발언의 기간·미정 후보는 기존 기간을 덮어쓰지 못한다.
- 원문의 명확한 기간과 정규화한 기간이 다르면 저장하지 않는다. 8주를 13주로 잘못 환산한 후보, 부정한 4주를 확정값으로 보내는 후보를 검사했다.
- 한국어 자동 기간 저장도 같은 변경 기준을 적용하여, 과거 기간 언급 때문에 턴이 실패하거나 상태가 바뀌는 것을 막았다.

## 2. 알려진 현재 수준 보호

- `측정`이라는 단어가 있다는 이유만으로 미측정 상태로 바꾸던 판정을 제거했다.
- `측정한 점수는 65점`, `I am not a complete beginner.` 같은 사실·부정 문장을 잘못된 `unmeasured` 후보가 덮어쓰지 못한다.
- 실제 모름/측정 경험 없음은 여전히 미측정으로 기록한다. 중립적인 첫 주 측정 안내는 한국어·영어 언어 설정을 유지한다.
- 도구 인자 검증과 실제 에이전트의 후보 필터가 같은 기준을 사용한다.

## 3. 현재 수준과 가용 시간의 대상 분리

- 현재 질문이 가용 시간 단계라는 이유만으로 무관한 발언을 시간 정보로 저장하지 않는다.
- `현재 기록 수준은 잘 모르겠어`, `My score is not measured.`, `I do not know the deadline.`는 시간 여건이 아니다.
- `모르겠어`, `I don't know.` 같은 짧은 생략 답변은 실제 가용 시간 단계에서 받을 수 있다.
- 명확한 시간 여건, 짧은 시간·횟수 답변, 다른 대상을 설명하는 문장을 구분한다. 질문 순서가 원문의 대상을 덮어쓰지 않도록 했다.

## 4. 유동적인 영어 시간 여건 보존

- `Some weeks I only get two 15-minute windows.` 등 짧게 나뉜 가용 시간을 현재 수준보다 먼저 말해도 보존한다.
- 일부 주에 가능한 시간을 매주 고정 30분이나 특정 요일·시각으로 확정하지 않는다. 원문과 추정 상태를 유지한다.
- 같은 사실을 정해진 형식으로 다시 입력해야만 저장되던 차이를 줄였다.

## 5. 한영 수량·속도 비교와 미확인 상태

- `goalQuantity.ts`로 값·단위·주간 속도의 공통 표현을 분리했다. 기존 한국어 단위와 영어 단위가 같은 기준으로 비교된다.
- 현재 주 1편 → 4주 동안 12편이라는 같은 수치는 두 언어 모두 주당 3편이 필요한 조정 검토 상태가 된다.
- 수량을 해석하지 못하거나 단위가 다르면 `ready`로 내려가지 않고 `needs_rate`로 남긴다. 이 상태는 첫 주 측정이 필요하다는 뜻이며 목표 달성이 불가능하다는 판정이 아니다.
- 범위·복수 단위·서로 다른 기준 기간 등 모호한 표현을 억지로 하나의 값으로 변환하지 않는다. 지원하지 않는 복합 수량도 확인 필요 상태로 처리한다.

## 6. 목표 하나만 제외하고 명시적으로 복원

- `record_goal_brief` v1.2.0에 `area_changes: [{ area, action: remove | restore, evidence }]`를 추가했다. 변경이 없으면 빈 배열이며 기존 `areas`는 계속 추가 목록이다.
- 현재 원문의 명시적 요청을 확인한 뒤 지정한 분야만 제외한다. 해당 분야의 수준·완료 기준을 정리하고, 남은 목표·기간·시간 여건은 유지한다.
- 남은 분야에 유효한 우선순위는 보존한다. 제거된 분야가 최우선이거나 범위가 새로 늘어난 경우처럼 재확인이 필요한 우선순위만 무효화한다. 아직 이름을 받지 않은 요청 분야 수도 잃지 않는다.
- 제외 목록을 저장하여 과거 대화의 도구 후보가 같은 목표를 다시 추가하지 못하게 한다. 복원은 현재의 명시적 요청이 필요하며 삭제했던 세부 정보를 자동 부활시키지 않는다.
- 빈 배열·부분 배열, “삭제하지 마”, “잠시 보류”, 방법 설명 요청, 불확실한 후보는 삭제 명령이 아니다. **보류를 삭제로 구현하지 않았으며**, 별도 보류 워크플로 전체를 새로 만든 것은 아니다.
- 구조화된 변경 필드를 쓰지 않은 구형 후보도, 현재 원문에 특정 목표의 명백한 제외 명령이 있을 때만 호환 처리한다. 동결된 최초 기능 공백 검사도 그대로 유지했다.
- 도구 기록에는 변경 건수와 규약 버전만 남기며 분야 이름·근거 문장을 추가로 노출하지 않는다.

OpenAI Docs 스킬과 [공식 함수 호출 문서](https://developers.openai.com/api/docs/guides/function-calling)를 참고해 새 입력 객체를 strict 형식에 맞췄다. 객체의 추가 속성을 금지하고 정의된 필드를 필수로 두는 검사를 추가했다. 실제 공급자 API 호환 호출을 실행했다는 뜻은 아니다.
