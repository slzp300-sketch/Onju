## 확인된 원인

말투만의 문제가 아니었다. T02 지침은 누락 항목을 현재 물어볼 유일한 정보로 지정했고, 저장 직후 reply·일반 respond·턴 종료의 세 경로가 모델 질문을 고정 질문으로 대체했다. 실행량이나 기간이 있는 설명을 제거하는 필터, 준비된 필드만으로 초안 생성을 강제하는 조건도 있었다. 답변 문단과 질문 길이 제한은 상세한 설명을 어렵게 했다.

## 구현 내용

1. **대화 판단과 저장 검증 분리**
   - 누락 항목 때문에 고정 질문을 생성·치환하는 경로와 고정 요약 대체를 제거.
   - 필드가 찼어도 필요한 안전·자원 확인이나 설명이 가능하도록 초안 생성을 선택 가능하게 변경.
   - 정보 부족 초안, 근거 없는 값 저장, 승인 없는 활성화를 막는 기존 검증은 유지.
   - 이미 해결된 질문은 제거할 수 있지만 다른 고정 질문을 대신 삽입하지 않음. 저장 검증에서 버린 분야를 인용하는 응답은 실제 도구 결과를 읽고 다시 작성하게 함.
2. **맥락 기반 코칭 규칙**
   - 목적·현재 상태·선호·제약의 의미를 먼저 설명하고, 실제 계획에 영향을 주는 정보만 질문.
   - 기본 질문 하나, 필요하면 관련 질문 최대 세 가지. 하나씩 질문해 달라는 선호를 존중.
   - 조건부 예시·추천은 설명할 수 있으나 사용자 결정으로 저장하지 않음.
   - raw 원문 대신 일반화한 원칙을 사용. 개인 건강 수치·장비·기간을 가정하거나 알림 기능을 과장하지 않도록 명시.
3. **기억·후속 맥락**
   - 목표 정보 저장과 동일 호출의 reply에도 근거 기반 remember/forget을 연결.
   - 주제 키워드가 없어도 목표 관련 제약·동기를 전달하고 영어 선호 저장 경로를 보완.
   - 묶음 질문이 저장·새로고침 때 180자로 잘리지 않도록 workflow의 길이 한도를 답변 질문 한도에 맞춤.
4. **명확한 표시**
   - 서버 스키마와 렌더링 제한을 같은 계약으로 통합.
   - 소제목·굵게·빈 줄·번호 목록과 관련 질문 묶음을 보존. 총 출력 상한은 유지.
   - 기본 초안은 간단하게 유지하고 상세 요청에는 검증된 행동별 실행 순서·완료 확인·짧은 기록 방법을 추가.
   - 상세 요청일 때만 더 큰 기존 초안 수준의 출력 예산을 허용. 모델이나 호출 경로를 유료로 실행하지 않음.
