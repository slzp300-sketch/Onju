# 온주 — 원문 수준의 대화 품질 구현 계획

## 목표와 범위

사용자가 제공한 운동 관리 대화의 **의도 이해 → 필요한 정보 요청 → 근거 있는 해석 → 명확한 실행안 → 짧은 기록과 조정**을 제품의 품질 기준으로 삼는다. 문장 복사나 모든 사용자에게 동일한 설문·운동 계획을 주는 것이 아니다. 모든 상황에서 100% 동일 품질을 보장할 수는 없으며, 코드 검증과 실제 모델 응답 평가는 별개다.

이번 작업은 로컬 개발과 네트워크 차단 검증까지다. 유료 모델 호출, 배포, 모델 교체, 학습·파인튜닝, 원문 외부 업로드는 하지 않는다. 기존 앱과 사용자 데이터는 유지한다.

## 원문에서 채택할 것 / 개선해서 적용할 것

- 목표의 의미를 해석한다. 운동이라면 외형뿐 아니라 체력·움직임 등 사용자가 말한 목적을 구별한다.
- 현재 실력·선호 환경·제약이 질문과 제안에 실제 영향을 주게 한다. 알려준 정보를 재질문하지 않는다.
- 정보를 왜 묻는지 짧게 설명하고, 같은 판단에 필요한 질문은 최대 세 개까지 묶을 수 있다. 한 번에 하나를 원하는 사용자의 선호는 우선한다.
- 방향 설명과 조건부 예시는 정보 수집 중에도 가능하다. 기간·빈도·장비를 사용자가 확정한 사실처럼 저장하지 않는다.
- 실제 계획은 목표·현재 위치·기간·실행 여건을 근거로 작성한다. 상세 설명은 제목·문단·목록으로 표현하고, 첫 화면 핵심은 목표와 행동이다.
- 기록은 짧은 자연어로 받고 다음 조정을 제안한다. 예약 도구 없이 자동 알림을 약속하지 않는다.
- 원문의 임의 기간·빈도, 확인 전 장비 가정, 개인별 건강 수치 단정, 과도한 질문 수는 그대로 복제하지 않는다. 체지방률을 모른다는 이유로 진행을 막지 않는다.

## 구현 단계와 두 차례 점검

| 단계 | 구현 | 1차 점검: 요구 충족 | 2차 점검: 회귀·오용 |
| --- | --- | --- | --- |
| 1. 대화 판단권 | 누락 항목에 따른 고정 질문 치환·강제 후속 질문 제거, 현재 의도 중심 지침 통일 | 모델이 선택한 관련 질문·질문 없는 설명이 유지되는가 | 정보 미수집 계획 생성·승인·가짜 저장이 차단되는가 |
| 2. 맥락과 정보 수집 | 기존 근거 기반 기억 재사용, 선호·제약의 관련성 개선, 최소 질문 기준 | 사용자 수준·환경·거절을 반영할 수 있는가 | 개인 사실 추정·중복 질문·분야 혼합이 발생하지 않는가 |
| 3. 설명과 실행안 | 짧은 답변 기본값 유지, 요청 시 구조화된 상세 설명, 제한된 질문 묶음 | 제목·굵게·줄바꿈·실행 순서가 보존되는가 | 무한 출력·HTML 실행·지나친 설문을 차단하는가 |
| 4. 품질 검증 | 원문에서 일반화한 오프라인 대화 회귀와 전체 기존 검사 | 실제 핸들러가 대화 내용을 훼손하지 않는가 | 고정 모의 응답 검사를 실제 모델 품질 검증으로 오해하지 않는가 |

## 이후 실제 모델 평가 기준 — 이번에는 실행하지 않음

동일 모델·설정에서 변경 전후 동일 입력을 비교한다. 원문 운동 사례 외 독서·이직·학습, 거절·정정·주제 전환·영어·일정 유동 사례를 포함한다. 각 대화는 여러 턴으로 평가하고 질문 순서를 고정 정답으로 두지 않는다.

사례마다 ① 의도 반영 ② 사실·추천 구분 ③ 필요한 질문만 요청 ④ 현재 조건에 맞는 실행안 ⑤ 가독성 ⑥ 기록·수정 연결을 각 0~2점으로 채점한다. 이미 답한 질문 반복, 개인 조건 날조, 승인 없는 활성화, 불가능한 도구 약속은 점수와 무관하게 실패다. 이 기준은 내부 출시 기준이지 검증된 품질 인증이 아니다.

실제 생성 품질의 최종 판정은 승인된 소규모 모델 비교와 사용자 검수로 한다. 오프라인 검사는 구조·계약의 통과만 증명한다. 비용 추정과 한도를 별도로 합의한 뒤 실행하며 기존 무비용 원칙을 자동 해제하지 않는다.

원문은 개인 참고 자료이며 웹 번들·운영 프롬프트에 원본을 포함하지 않는다.

## 현재 완료 상태

후속 검증(같은 날): 상충하는 도구/캐시 지침과 질문 선호 정정·일반 텍스트 검사 누락을 추가 수정했다. 최신 오프라인 결과는 **30/30 그룹, 2,231개 자동 테스트 통과**다. 실제 평가용 10개 흐름/24턴과 증거 판정 장치를 준비했지만 유료 모델 생성은 아직 실행하지 않았다. 최신 내용은 [추가 검증 기준](ONJU_REFERENCE_COACHING_VERIFICATION_2026-09-17.md)과 [작업로그](WEB_MVP_WORKLOG_2026-09-17_COACHING_VERIFICATION.md)를 따른다.

아래는 후속 검증 전 최초 구현 시점의 결과다.

1~3단계의 로컬 구현과 4단계 오프라인 검증을 완료했다. 원문 수준의 실제 모델 응대는 **아직 검증 전**이다. 새 검사 20개(실제 핸들러·계약 17, UI 렌더링 3)를 포함해 자동 테스트 2,208개가 통과했다. 전체 검사 그룹 29/29 통과, 유료 모델 호출 0회. 상세 근거는 [작업로그](WEB_MVP_WORKLOG_2026-09-17_REFERENCE_COACHING.md)에 남겼다.

## 실제 대화 검수 순서

아래는 아직 실행하지 않은 비교 평가 시나리오다. 정답 문장을 고정하지 않고 같은 목적을 달성했는지 판정한다.

| 사례 | 사용자 흐름 | 필수 관찰 | 실패 조건 |
| --- | --- | --- | --- |
| 운동 목표 탐색 | 좋은 몸을 원함 → 집 선호·현재 동작 기록·지구력 어려움 제공 | 외형과 실제 체력 목표 구별, 이미 말한 수준 보존, 가능한 시간·환경의 핵심 조건만 질문 | 첫 발언만으로 12주·주4회·체중 목표 확정 |
| 관리 요청 | 같이 관리해 달라는 요청 → 상세 계획 요청 | 핵심 행동·실행 방법·짧은 기록 방법, 승인 전 미확정 | 실제 기능 없이 매일 먼저 연락한다고 약속 |
| 선택 정보 모름 | 체지방률이나 정확한 최근 기록을 모름 | 선택적 수치 재요구 없이 유효한 현재 정보로 진행 | 같은 수치를 반복 요구, 모르겠다는 말을 0으로 저장 |
| 안전·자원 미확인 | 일반 필수 정보는 있지만 장비·피해야 할 동작이 불명확 | 해당 조건을 확인하거나 그 조건에 의존하지 않는 대안 | 필드가 찼다는 이유만으로 장비·능력을 가정 |
| 추천과 결정 | 기간 추천 요청 → 일부 조건만 승인 | 추천과 확정 사실 분리, 승인한 항목만 반영 | 예시의 기간·횟수가 자동 저장됨 |
| 충분한 정보 | 기간·현재 상태·결과·실행 여건을 한 번에 제공 | 이미 제공된 내용을 모두 활용하고 불필요한 설문 없이 초안 제시 | 표현만 바꿔 반복 질문, 선호 질문을 끝없이 추가 |
| 거절·유동 | 일정은 유동적, 숫자는 말하고 싶지 않음 | 거절·유동 상태 유지, 가능한 범위 설명 | 고정 시각·숫자를 억지로 채움 |
| 정정 | 집 운동 대신 다른 환경으로 변경 | 최신 조건 사용, 요청하지 않은 목표·기간은 유지 | 오래된 기억과 새 조건을 혼합 |
| 실행 보고 | 한 일과 어려움만 짧게 보고 | 한 실행을 정확히 기록하고 필요한 조정만 제안 | 목표 설문 재시작, 미기록을 실패 처리 |
| 다른 분야·언어 | 독서·이직·학습, 한국어·영어로 같은 의도 전달 | 운동 대본에 갇히지 않고 동일한 판단 원칙 적용 | 고정 분야·언어에만 유효한 응대 |

각 사례를 변경 전·후 같은 설정으로 비교하고, 사용자 검수에서 더 낫다고 평가되는지 확인한다. 실패한 대화는 회귀 사례로 추가한다. 검사 개수가 늘어났다는 사실만으로 품질이 좋아졌다고 판정하지 않는다.
