# 온주 개발 소스와 검증 기준

온주는 기존 루틴 관리 모바일 앱과 AI 코칭 웹 MVP를 함께 개발한다. 모바일 앱은 실행 기록과 공동체 경험을 제공하고, 웹 MVP는 대화로 계획을 설계하고 실행·점검·조정을 연결한다. 각 제품의 실행 위치와 검증 범위를 구분해 로컬 변경을 실제 배포와 혼동하지 않도록 한다.

## 소스 위치

| 위치 | 역할 | 적용 기준 |
| --- | --- | --- |
| `src/`, `android/` | 기존 모바일 웹·PWA·Android 앱 | 루트 `package.json`의 개발·빌드·테스트·gc 명령 |
| `web-mvp/` | 로컬 AI 코칭 웹 MVP와 전체 오프라인 검사 도구 | `npm run dev --prefix web-mvp`, `npm run verify:offline --prefix web-mvp` |
| `supabase/functions/`, `supabase/migrations/` | 루트 작업본의 서버 함수와 마이그레이션 | 함수별 검사와 마이그레이션 원장 확인. 파일 존재는 운영 적용의 증거가 아님 |
| `logs/sites/onju-web-mvp/` | 별도 Git·Sites 설정을 가진 배포용 작업본 | 최근 배포 기록의 커밋·소스 지문을 대조. 디렉터리 이름과 달리 현재 배포 작업 소스이며 단순 로그 복사본이 아님 |
| `logs/offline-development/` | 오프라인 검사 산출물과 결과 | 실행 시각별 `summary.md`, `summary.json`, 개별 검사 로그 |

배포용 작업본에는 `PlanWorkspace`, `PlanApproval` 등 로컬 웹 작업본에 없는 기능도 있다. 모든 파일을 한쪽으로 복사해 맞추지 않는다. 기능별 기준 소스와 사용 화면을 확인한 뒤 필요한 파일만 반영한다. 장기적으로 작업본을 통합하려면 실행·목표 관리 기능과 배포 설정까지 비교하는 별도 이전 작업이 필요하다.

## 공유 파일 변경

지역 설정, 날짜 처리와 기본 번역 카탈로그는 `web-mvp/scripts/regional-site.test.mjs`에 열거된 두 작업본의 공유 파일이다. 변경할 때 두 경로를 비교하고 기존 동작을 보존해 반영한다. 일치 검사는 실패한 전체 파일 목록을 출력한다.

배포용 제품 확장 문구는 `siteCopy.ts`, `siteExtraCopy.ts`처럼 배포용 작업본의 별도 카탈로그에 둔다. 공유 파일의 불일치를 단순히 무시하거나 검사를 삭제해 통과시키지 않는다.

## 검증 순서

1. 수정한 동작의 회귀 테스트를 실행한다. 계정 전환·지연 응답·오프라인 편집은 정상 응답만으로 검증할 수 없다.
2. 루트 `npm run build`, `npm test`, `npm run gc`를 확인한다. `gc`는 ESLint와 Knip 모두 exit 0이어야 한다.
3. AI 코칭 작업은 `npm run verify:offline --prefix web-mvp`로 두 웹 작업본·서버 로직·UI·전체 정적 검사를 확인한다. 빌드가 출력 파일을 교체하는 동안 ESLint를 동시에 실행하지 않는다.
4. 생성된 요약에서 전체 통과와 검사 중 소스 지문 불변 여부를 확인한다. 검사 도중 소스를 수정하면 해당 결과를 최종 검증 근거로 쓰지 않는다.

오프라인 UI 테스트는 가짜 서버 응답으로 화면과 상태 연결을 검증한다. 실제 모델의 자연어 품질·속도, 운영 데이터베이스 설정, 390px 실화면과 Android 실기기 검증을 대신하지 않는다. 실제 AI 평가 시에는 비용 한도와 기록 기준을 기존 평가 문서에 따라 확인한다.
