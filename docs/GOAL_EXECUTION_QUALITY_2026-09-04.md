# 목표 설계 추가 개선 — 완료 기준·점검·최소 실행

2026-09-04 · KST · GPT-4.1 유지

후속 처리: 이 기록에서 남겼던 반복 생성 지연과 보조 문구 불일치는 [응답 지연·문구 일관성 개선 기록](AGENT_LATENCY_AND_COPY_FIX_2026-09-04.md)에서 수정·재검증했다. 아래 내용은 당시의 실행 결과를 보존한 기록이다.

## 범위와 적용

이전 [목표 설계 개선](GOAL_DESIGN_REFINEMENT_2026-09-04.md)에서 남긴 모호한 달성률, 기간 밖의 점검 주기, 행동별로 구체적이지 않은 최소 실행을 보완했다. 주간 시간표 배치는 진행하지 않았다.

새 목표 초안은 `execution`에 행동별 완료 조건·최소 행동·최소 시간을 구조화해 저장한다. 서버와 웹이 같은 내용을 표시하며, 승인한 카드를 그대로 확정한다. 기존 JSONB 안에 저장하므로 새 DB 마이그레이션은 없다. 기존 기록을 일괄 수정하거나 삭제하지 않았다. 새 세부 기준은 **새로 생성하는 초안부터** 적용되며, 과거 목표는 기존 조건대로 읽고 승인할 수 있다.

## 변경 사항

1. **달성률의 분모와 완료 횟수**
   - 루틴 실행률은 시험 기간 동안 계획한 기본 실행 횟수의 합계를 분모로 한다. 필요 완료 횟수는 올림한다.
   - 예: 주 3회 × 2주, 80% 기준 → 기본 실행 6회 중 5회 이상 완료.
   - 같은 회차는 한 번만 세고, 바쁜 날 최소 실행은 별도 기록으로 구분한다. 이번에는 기준을 설계한 것이며 실제 체크인 집계 기능을 구현한 것은 아니다.
   - 소설 분량·매출·체중처럼 실제 결과를 측정하는 목표는 루틴 실행률로 바꾸지 않는다. `custom_outcome`으로 원래 결과 기준을 보존한다.
2. **점검 주기**
   - 점검 간격을 숫자로 저장하고 시험 기간을 넘으면 수정하도록 한다. 마지막 점검은 시험 종료 시점에 표시한다.
   - “2주 시험인데 4주마다 조정” 같은 기존 기본 문구는 새 초안에서 생성하지 않는다.
   - 기간을 줄이면 필요한 점검 간격·종료 점검 문구 변경을 별도 관련 조건으로 승인받는다.
3. **행동별 완료 기준과 최소 실행**
   - 각 주간 행동마다 완료 증거를 하나씩 적고 기본 실행 시간은 코드에서 붙인다. 문장에 오래된 시간 수치가 남지 않도록 한다.
   - 최소 행동은 1~2분이며 기본 행동보다 길지 않아야 한다. 후보/아무거나/가능한 만큼/또는 같은 모호한 선택지를 거절한다.
   - 기존의 한 줄 최소 실행은 새 구조에서 생성하고, 대화와 목표 카드에서는 행동별 목록으로 표시한다.
4. **수정과 자연어 표현**
   - “일주일에 한 번”, “오 분” 등 흔한 한글 수 표현을 지원한다. “5분 말고 7분”에서 앞의 거절된 숫자를 사용하는 변경은 거절한다.
   - 실행률·점검 간격·최소 행동·최소 시간·완료 기준을 개별 필드로 수정할 수 있다. 기존의 다른 조건은 보존한다.
   - 단일 행동의 목표 문장에 반복된 시간·빈도도 관련 변경으로 보여준다. 예: 매주 3회 문구가 주 1회 수정 후 그대로 확정되지 않도록 한다.
5. **실패 시 안내**
   - 초안 검증 오류를 한 번에 전달해 불필요한 모델 왕복을 줄인다.
   - 검증 재시도 한도에 걸리면 기존 목표를 보존하고, 초안을 아직 맞추지 못했다는 안내와 시작할 행동 하나를 묻는다. 이 경우를 일반 연결 오류로 안내하지 않는다. 성공한 초안으로 집계하지도 않는다.

OpenAI Docs의 [함수 호출 가이드](https://developers.openai.com/api/docs/guides/function-calling)를 참고해 제안은 모델, 수치 계산·검증·저장 확정은 코드에 맡겼다. 모델 변경이나 파인튜닝은 하지 않았다.

- 자동 검사 통과는 의미 전체의 정확도나 ChatGPT 수준의 자유 대화 품질을 뜻하지 않는다. 원문을 별도로 읽어 단위·기간·최소 행동과의 관계를 확인한다.

### 최종 실행

실행 ID `2026-09-04T04-30-27-696Z`: **20/20 통과**. [고정 원본](evals/agent-goal-execution-2026-09-04T04-30-27-696Z.json), [최신 결과](evals/agent-goal-execution-2026-09-04.json). 각 사례 1회로 표본은 작다. 이전 실행 기록을 덮어쓰지 않았다.

- 원문 정성 검토에서 선택 필드 `tinyStart`에 “매일 한 분야씩” 같은 보조 제안이 남은 사례가 있었다. 이번 검증은 구조화된 실행 기준에 집중했으며, 선택 필드까지 포함한 모든 자연어의 일관성을 증명한 것은 아니다. 실제 결과 목표의 회차별 산출량이 사용자에게 적절한지도 별도 사용성 검증이 필요하다.

## 한계

- 최소 행동이 해당 행동과 의미상 관련 있는지, 개인에게 실제로 1분 안에 가능한지까지 기계적으로 증명하지 않는다. 숫자 범위·문구의 일부 패턴과 필드 구조를 검증한다.
- 한글 숫자는 흔한 표현만 지원한다. 임의의 복합 부정, 조건부 변경, 범위 수치, 긴 대화의 철회/재정의는 완전하지 않다.
- 기존 구조화되지 않은 목표를 새 실행 기준으로 자동 전환하는 기능은 없다. 이전 조건을 보존하기 위한 호환 경로와 새 초안 경로를 구분했다.
- 기본 실행과 최소 실행의 기록 분리, 비율 계산은 이번에 제안하는 설계 기준이다. 실제 일일 실행 저장·중복 회차 제거·주간 통계 기능은 후속 작업이다.
- 구체적인 완료 증거를 추가하는 만큼 답변이 길어질 수 있다. 접이식 카드와 목록을 사용하지만, 긴 대화를 줄이는 요약/스트리밍과 실기기 키보드 평가는 남았다.
- 명시적 실행률 추출은 실행률/실천율/완료율 같은 표현에 한정된다. 실제 성과 측정과 루틴 실행률을 모델이 잘못 분류할 가능성은 추가 평가 대상이다.
- 현재 공개 고객 모집에 필요한 익명 세션 보안·비용/속도 제한·장기 대화 관측을 완료한 것은 아니다.

커밋·푸시·Notion 업로드는 이번 요청 범위에 포함하지 않았다.

## 배포와 정리

운영 `onju-agent-v2`에 최종 코드 배포 완료. 임시 평가 함수는 별도 난수 토큰과 2시간 만료를 적용했고 토큰 없는 요청 403을 확인한 뒤 삭제했다. JWT 검증 해제 옵션은 사용하지 않았다. 로컬 생성 함수·임시 토큰도 삭제했으며, 필요하면 검증 실행기의 prepare로 재생성할 수 있다. 응답과 평가 기록은 보존했다.

검증용 5192 서버와 탭을 종료하고 뷰포트를 복원했다. 원래 사용자 5173 `/setup` HTTP 200 확인. DB 영속성 확인에 쓴 합성 세션은 앱의 30일 유효기간을 가진 별도 기록이며 원래 사용자 세션을 변경하지 않았다.
