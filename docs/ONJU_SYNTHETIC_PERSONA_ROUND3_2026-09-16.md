# 온주 3차 가상 사용자 10명 진단·작업로그

작성: 2026-09-16. 사용자 요청: “추가로 10명의 데이터를 더 만들어서 한 번 더 진행해보자.”

## 결론

**새 가상 사용자 10명, 작성 여정 발언 48개, 별도 상태 검사 8개, 실제 에이전트 경로의 모의 응답 검사 4개**를 추가했다. 총 338개 조건 중 **306개 통과, 32개 실패**가 동일 소스로 두 번 재현됐다. 중복·후속 실패를 묶으면 **7개 보완 유형**이다.

가장 먼저 고칠 것은 **과거 사실이 최신 상태를 덮어쓰는 문제**와 **과거 실행 기록을 가용 시간으로 저장하는 문제**다. 나머지는 문장 안의 대상·시점·의도 범위를 구분하지 못하거나 특정 표현만 허용하는 제약이다. 격주 속도 해석은 보수적으로 확인 필요 상태에 머무르는 지원 공백이며, 틀린 값을 확정한 사례와 구분한다.

이번에는 데이터·진단 실행 도구·보고서만 추가했다. 제품 코드 수정, 유료 API 요청, 배포는 하지 않았다.

## 자료의 성격과 검사 범위

- 한국어 6명·영어 4명, 24~47세. 앞선 15명과 ID·생활 상황을 구분하여 **누적 가상 설정은 25명**, 실제 참여자는 0명이다.
- 직장·자취·교대근무·육아·돌봄·이직·자영업에서 일어날 법한 **가정**이다. 해당 연령층의 대표성이나 실제 문제 발생 빈도를 주장하지 않는다.
- 각 발언에서 기대하는 상태와 도구 입력 후보를 먼저 작성하고 로컬 제품 코드에 넣었다. 후보와 회복 답변은 실제 온주 모델이 생성한 응답이 아니다.
- 보통 여정, 잘못된 후보 차단, 표현 비교용 대조군, 실제 에이전트 조립 경로를 구분했다.
- 실제 에이전트 검사에는 이전 사용자 원문을 순서대로 넣었다. 특히 오래된 근거를 재사용하는 문제를 확인하기 위해서다. 실제 사람과 주고받은 완전한 대화 기록은 아니다.
- 사용자 만족도·재방문·지불 의향·실행률·대화 자연스러움은 측정하지 않았으며 데이터에도 `null`로 남겼다.
- 32개 실패 조건은 32개의 독립 버그가 아니다. 9개 가상 설정에 실패가 있었지만 이를 실제 사용자의 90%가 실패한다는 통계로 해석하면 안 된다.

## 7개 보완 유형

### 1. 오래된 근거로 최신 현재 수준을 되돌릴 수 있음 — P1

- 사례: US-10. 처음 `0 projects`라고 말한 뒤 `1 project`를 완료했다.
- 최신 발언: `I have 1 project done now. Please use my latest progress.`
- 주입한 잘못된 후보: 이전 발언의 `0 projects`를 근거로 현재 수준을 다시 0개로 저장.
- 기대: 최신 1개 기록 유지. 실제: **0개로 되돌아감**. 하위 저장 함수와 실제 `runAgentTurn` 경로에서 모두 재현됐다.
- 원인: [goalBrief.ts](../logs/sites/onju-web-mvp/supabase/functions/onju-agent-v2/goalBrief.ts)의 `hasEvidence`는 과거 어느 발언에라도 근거가 있으면 허용한다. 현재 수준 교체 시 근거의 최신성·정정 의도를 따로 확인하지 않는다.
- 개선 기준: 과거 근거는 빠진 정보 보충에만 사용하고, 이미 확정된 최신 값을 바꾸려면 현재 턴의 명시적 정정이 필요하다. 필드별 근거 턴·변경 이력을 남겨야 한다.
- 제한: 실제 모델이 이런 후보를 낸 비율을 측정한 것이 아니라, 잘못된 후보가 들어왔을 때 서버가 막지 못하는 경계를 확인했다.

### 2. ‘하루’가 있는 과거 운동 기록을 가용 시간으로 잘못 저장 — P1

- 사례: KR-12. `내 주간 운동 기록은 하루 몇 번 했는지 아직 모르겠어.`
- 기대: 과거 실천 횟수에 대한 모름으로 해석. 가용 시간은 계속 미확인.
- 잘못된 후보를 보냈을 때 실제: 이 문장을 **가용 시간 `unmeasured`로 저장**. 실제 에이전트 경로도 동일했다.
- 원인: [goalIntakeEvidence.ts](../logs/sites/onju-web-mvp/supabase/functions/onju-agent-v2/goalIntakeEvidence.ts)의 `capacityEvidenceMatches`가 `하루` 같은 시간 단어를 먼저 인정해, 문장의 실제 대상이 실행 이력인지 가용 시간인지 확인하기 전에 통과시킨다.
- 개선 기준: 시간 단어 존재보다 **과거 수행량 / 앞으로 투입할 여건**의 의미 구분이 먼저다. 잘못된 한 필드는 버리되, 다른 유효한 사실은 보존해야 한다.

### 3. 목표 확정 뒤 별도 질문을 붙이면 목표 변경까지 거절 — P2

- 사례: KR-10. `목표는 기록 10일 완료로 줄일게. 주말은 쉬어도 될까?`
- 기대: 목표 20일→10일은 저장하고 주말 실행 질문에 답하기.
- 실제: `result_not_decided`로 거절되어 목표는 20일로 남았다. 다음 발언에서 질문을 빼고 10일 변경만 말하면 저장됐다.
- 원인: [goalBrief.ts](../logs/sites/onju-web-mvp/supabase/functions/onju-agent-v2/goalBrief.ts)의 목표 확정 검사가 해당 근거가 아닌 **사용자 발언 전체의 물음표**를 검사한다.
- 개선 기준: 확정·질문·후보를 발언 전체가 아니라 해당 사실이 있는 절 단위로 구분한다. “확정한 내용 저장 + 별도 질문 답변”을 함께 처리한다.

### 4. 과거 점수와 현재의 모름을 한 근거에 담으면 현재 상태 저장 거절 — P2

- 사례: KR-11. `작년에 측정한 점수는 65점이었고, 지금 수준은 모르겠어.`
- 기대: 과거 65점은 과거 사실이며 지금 수준은 미측정으로 기록.
- 실제: 전체 문장을 근거로 보내면 `baseline_not_decided`로 거절. `지금 수준은 모르겠어.` 부분만 근거로 보내는 대조군은 통과했다.
- 원인: [goalIntakeEvidence.ts](../logs/sites/onju-web-mvp/supabase/functions/onju-agent-v2/goalIntakeEvidence.ts)가 근거 안의 측정 수치를 먼저 발견하면, 과거인지 현재인지 구분하지 않고 미측정을 차단한다.
- 개선 기준: **사실의 대상과 시점**을 함께 관리하고, 현재 수준을 나타내는 절을 근거로 분리한다. 이전에 고친 “현재 점수가 알려져 있는데 미측정으로 덮어쓰기” 차단은 유지해야 한다.

### 5. 복합 목표 명령에서 행동과 대상을 연결하지 못함 — P2

- KR-13: `영어와 독서를 제외해줘.` → 두 분야를 하나의 제외 동작 대상으로 보내도 거절. 포트폴리오만 남지 않았다.
- US-08: `Keep reading and remove sketching.` → 남길 대상의 `keep` 때문에 제외할 대상 `sketching`까지 변경이 막혔다. 실제 에이전트 경로에서도 저장이 거절되고 모의 회복 응답으로 끝났다.
- 대조: `Remove sketching.`처럼 한 동작으로 말하면 통과했다. 한국어 단일 제외·복원도 통과했다.
- 원인: [goalIntakeEvidence.ts](../logs/sites/onju-web-mvp/supabase/functions/onju-agent-v2/goalIntakeEvidence.ts)의 이름 기준 문장 절단과 전체 절의 `keep` 차단이, 병렬 대상과 서로 다른 동작을 구분하지 못한다.
- 개선 기준: **행동 → 대상 목록**을 명시적으로 연결하고 각 동작의 근거 범위를 검증한다. 제외하지 말라는 문장·보류·방법 질문 차단은 유지한다.

### 6. 같은 기간 변경 의도도 표현에 따라 거절·무시 — P2

- KR-15: `그러면 6주로 늘릴게.` → 4주가 유지됨. `기간을 6주로 변경할게.`는 6주로 반영됨.
- US-07: `Move the deadline to November 30, 2026.` → 8주가 유지됨. `Change the deadline ...`는 마감 2026-11-30, 미국 현지 기준 약 11주로 반영됨.
- 실제 에이전트 경로에서도 `Move` 변경 후보가 버려졌다. 도구 요청 자체가 실패하지 않고 기존 기간이 남는 조용한 누락이다.
- 원인: [goalIntakeEvidence.ts](../logs/sites/onju-web-mvp/supabase/functions/onju-agent-v2/goalIntakeEvidence.ts)의 `periodUpdateIsExplicit`가 제한된 동사 목록에 의존한다.
- 개선 기준: 문자열을 하나씩 추가하기보다, 현재 사용자가 **기존 기간/마감 값을 변경하기로 결정한 의미**를 검증한다. 추천·미정·과거 기간을 확정하지 않는 보호는 유지한다.

### 7. 격주 빈도를 주간 속도로 비교하지 못함 — P2, 지원 공백

- 사례: US-09. 현재 `2 articles every 2 weeks`, 목표 4주에 12편, 가용 시간 주 1시간.
- 원하는 계산: 현재 주 1편, 목표에 필요한 주 3편 → 기존 조정 검토 정책과 동일하게 `strained`.
- 실제: `needs_rate`이고 다음 강제 조정 단계는 없음. 사용자가 `1 article per week`로 다시 표현하면 `strained`를 판정한다.
- 원인: [goalQuantity.ts](../logs/sites/onju-web-mvp/supabase/functions/onju-agent-v2/goalQuantity.ts)는 매주·매월 등을 인식하지만 `every 2 weeks`의 수치 기준 기간은 정규화하지 않는다.
- **안전 구분:** 이미 수정한 불확실성 보호가 작동해서 `ready`라고 잘못 확정하지는 않았다. 이는 보수적인 대체 처리에 머무르는 지원 공백이며, 가용 시간 오기록·최신 값 훼손과 위험도가 다르다. 실제 모델이 과도한 계획을 제시했다는 증거도 아니다.
- 개선 기준: 값·단위뿐 아니라 **기준 기간의 값·단위**를 저장해 `2편/2주 = 1편/주`를 공통 계산한다. 모호하거나 여러 기준이 섞인 입력은 계속 확인 필요로 남긴다.

## 이번에 정상 처리된 범위

- 지역 날짜와 주 시작일: 한국·미국 4개 시간대에서 모두 예상값 일치.
- 모든 상태 변경은 입력 상태를 직접 변이하지 않았고 저장·복원 경계가 유지됐다.
- 단일 목표 제외·복원에서 나머지 목표와 기간이 유지됐다.
- 보류·삭제하지 말라는 명령을 삭제로 실행하지 않았다. 이 검사는 **비삭제**만 확인하며 보류 상태 UI·예약 재개를 완성했다는 의미는 아니다.
- 정해진 형식으로 다시 말한 기간 변경, 현재 점수 갱신, 목표량 축소, 유동적인 가용 시간은 해당 조건에서 통과했다.

## 왜 이전 검사 통과 후에도 발견됐나

직전 수정의 같은 입력 401개는 이번에도 통과했다. 하지만 이번에는 **과거 근거를 최신 값에 재사용**, **확정과 질문이 한 발언에 공존**, **한 행동에 여러 대상**, **서로 다른 행동이 같은 문장에 공존**, **수치가 있는 기준 기간**을 추가했다.

따라서 이전 검증 결과가 무효라는 뜻은 아니다. 다만 특정 문장 형태의 통과를 전체 자연어 이해의 완성으로 확대하면 안 된다는 점은 더 분명해졌다. 근본 보완은 문구 목록을 계속 늘리는 것이 아니라 **필드별 최신성 + 사실의 대상·시점 + 동작별 근거 범위**를 명확히 하는 방향이어야 한다.

## 다음 보완 순서 제안 — 이번에는 구현하지 않음

1. 최신 사실 보호: 필드별 근거 턴/시점 기록, 과거 근거의 현재 값 덮어쓰기 차단.
2. 의미 대상 분리: 현재 수준·과거 실행 이력·앞으로의 가용 시간 분리. 시간 단어만으로 저장하지 않기.
3. 혼합 발언 처리: 확정/질문, 과거/현재, 유지/제외를 각각의 근거 범위에 연결.
4. 기간 변경과 목표 범위 변경을 명시적 동작으로 검증. 병렬 대상과 동의어 처리 시 기존 부정·미정 차단 유지.
5. 숫자가 있는 빈도 기준 기간 정규화. 모르면 확인 필요로 남기기.
6. 기존 25명 설정을 모두 보존해 재검사하고, 이후 별도 예산 승인 범위의 실제 모델·실사용 테스트 진행.

고정 응답을 더 늘리거나 사용자에게 더 긴 입력 양식을 요구하는 것이 해결책은 아니다. 현행 모델 요청 안에서 의미 후보를 추출하고 서버가 최신성·근거·변경 권한을 검증하는 경계를 개선하는 제안이다. 추가 모델을 매번 한 번 더 호출하는 안을 실행하지 않았다.
