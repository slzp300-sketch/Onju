# 온주 코칭 안내 보존·시간 일관성 보완

작성: 2026-09-17. 로컬 빌드: `2026-09-17-coaching-preservation-21`.

## 결과

저장 응답 재검사에서 확인한 세 결함을 보완했다. 동일 오류 사례를 재검사해 정상 차단/보존을 확인했고, 전체 무료 검사 30개 그룹·2,323개 테스트가 통과했다. **알려진 결함의 구조 보완 완료이지 새 모델 답변의 문서급 품질 합격은 아니다.** 이번에는 유료 호출·평가 함수 배포·공개 배포·커밋·푸시를 하지 않았다.

## 변경 1 — 실제 수행 단계와 조건부 수칙 분리

- 새 초안 스키마에 행동별 `conditionalRules` 배열을 요구한다. 조건이 없으면 빈 배열을 명시한다.
- 준비·실행·휴식·전환·기록은 `steps`와 `stepMinutes`, 조건 발생 시 적용하는 수칙은 `conditionalRules`에 저장한다. 수칙 자체를 실행 시간에 더하지 않는다.
- 문장 첫 단어에 의존하던 검사를 제거했다. “만약”, “먼저”, 숫자, 영어 접두어를 붙인 조건부 중단 문장도 검사한다. 이는 구조 필드의 잘못된 사용을 보완하는 제한적인 내용 검사다.
- 정상 휴식/기록, “쉬면서” 같은 연결어, “화면” 같은 명사를 조건문으로 오인하지 않는 사례를 추가했다.
- 구형 저장 카드는 그대로 읽고 승인할 수 있다. 새 초안만 새 필드를 요구한다.
- 조건부 수칙은 대화와 초안·확정 계획의 상세 화면에 표시된다. 계획 변경 시 새 수칙을 다시 검토하도록 요구해 예전 수칙을 무조건 재사용하지 않는다.

## 변경 2 — 표시 시간의 기준 통합과 명시적 충돌 차단

- 단계별 시간 표시는 `stepMinutes`를 기준으로 공통 렌더러에서 만든다. 대화·초안·확정 계획·수정안이 같은 값을 사용한다.
- 설명에 해당 단계 예산보다 긴 분/초/시간, 시간 범위, 이어 쓴 복합 시간(20분 30초 등)이 있으면 거절한다. 전체 단계 시간이라고 명시한 값은 배정 시간과 일치해야 한다.
- 기존 숫자 배열의 회당 시간 합계 검사도 유지한다. 사용자 가능 시간을 몰래 늘리거나 설명을 강제로 바꾸지 않는다.
- 반복 횟수·세트 수는 시간으로 취급하지 않는다. 단계 안의 짧은 인터벌·세트 휴식은 전체 단계 시간과 같을 필요가 없다.
- “25분 조깅”을 “20분 실행”에 넣었던 오류 변형은 `coaching_text_time_conflict`로 차단된다.

검사 범위의 한계: 임의 자연어로 표현한 모든 반복 횟수×구간 시간 계산, 실제 운동 소요 시간, 장기 진행의 적합성을 완전 증명하는 엔진은 아니다. 이 부분은 실제 답변 검토와 수행 기록을 통한 보정이 필요하다.

## 변경 3 — 중요한 설명을 저장·표시·수정 경로에서 보존

- `coachingGuide`가 있다는 이유로 `paragraphs` 전체를 버리던 분기를 없앴다.
- 모델이 작성한 별도 문단과 항목은 `execution.contextNotes`로 함께 저장한다. 구조화 가이드와 완전히 같은 블록만 중복 제거한다. 일부 겹치는 문단은 고유 조건을 잃지 않도록 보존한다.
- 전체 답변 길이가 상한을 넘으면 설명을 잘라내지 않고 중복 정리를 요청한다.
- 저장 후보에 있던 “근력 회차 사이에는 가능하면 하루 이상 쉬세요.”가 최종 답변에 남는다.
- 핵심 목표/행동은 앞에 유지한다. 상세 화면에서도 부가 설명을 확인할 수 있고, 간결한 대화 모드도 고유한 부가 안내를 버리지 않는다.
- 승인과 재로딩에서 정보가 유지된다. 계획 수정 시 기존 부가 설명의 중요 조건도 새 실행량에 맞춰 유지·수정하도록 요구한다.
- 새로운 한국어 UI 레이블에 영어 번역을 추가했다.

## 검증 — 원본과 작성한 사례를 구별

### 수정하지 않은 저장 응답

- 사용자 참고 문서의 첫 3개 입력과 기존 평가 입력의 일치를 확인했다.
- 완료 저장 응답 6개를 수정하지 않고 재생했다. 1~3턴 표시 결과는 과거와 같다. 3턴은 원래 인용 오류와 수정 응답을 모두 재생했으며 첫 시도 성공이라고 바꾸지 않았다.
- 4턴의 원래 상세 후보는 조건부 수칙에 시간을 배정했으므로 여전히 거절된다. 원본을 억지로 통과시키지 않았다.
- 결과 불명의 7번째 호출 응답은 만들지 않았다.

### 별도의 작성 사례

- 정상 사례 1개: 저장 후보의 조건부 안전 문장을 별도 수칙으로 옮기고, 실제 실행 시간은 5+20+5분으로 작성했다. 새 필드도 명시했다. **새 모델이 생성한 답변이 아니라 작성한 시험용 변형이다.**
- 오류 사례 5개: 접두어를 붙인 조건부 수칙, 본문 시간 초과, 숫자 합계 초과, 임의 목표 연결, 근거 없는 장비. 각각 의도한 오류로 거절됐다.
- 정상 사례는 미승인 초안으로 표시되고, 사용자의 명시적 승인 후 실행 정보와 목표 4개가 재로딩까지 보존됐다. 승인에는 모델 호출이 없었다.
- 중요한 휴식 안내의 최종 표시와 저장, 조건부 수칙 표시, 수정 시 재검토를 별도 회귀 테스트로 확인했다.
- 네트워크 차단을 실제 확인했다. 원본 문서·이전 평가 자료·비용 원장 해시는 바뀌지 않았다.

### 전체 검사

- 1차 전체 검사에서 기존 제목 정규화 시험용 예시 하나의 시간 모순이 발견됐다. “20분”이 붙은 제목을 0.25분 준비 단계로 복사하는 테스트 헬퍼 조합이었다. 제품의 시간 검사를 완화하지 않고, 해당 테스트의 실행 순서/배정 시간을 명시했다. 실패한 기록은 보존했다.
- 최종 30개 그룹 모두 통과: 루트 에이전트 1,760 + Site 에이전트 477 + 앱 53 + 세션 UI 25 + 사용자 여정 UI 8 = **2,323개**.
- 가상 사용자 상태 검사 11개 그룹, 타입 검사, 웹 빌드, ESLint, Knip도 통과했다.
- 검사 도중 소스 변경 없음. 새로운 실브라우저 시각 검사는 이번 범위에 포함하지 않았다. UI 자동 회귀와 공통 렌더링 검사를 수행했다.

## 유료 검사 진입 판정과 남은 확인

이전에 보류한 세 결함에 대한 무료 검사는 통과했다. 현재 상태는 **예산 검토 후 제한된 새 응답 검사를 고려할 수 있음**이며, `liveQualityValidated`는 계속 `false`다.

새 모델이 변경된 구조를 실제로 잘 따르는지, 원문과 같은 입력을 이해하고 충분히 깊은 답변을 내는지, 첫 시도 성공/지연/비용이 적절한지는 유료 새 응답 검사에서 확인해야 한다. 운동 처방의 전문적 안전성은 이 코드 검사로 입증하지 않는다. 후속 실행 기록에 맞춰 조정하는 실제 대화도 아직 이 자료로 검증한 것은 아니다.

이번 모델 API 호출 **0회 / 추가 API 비용 $0**. Codex 자체 사용량과는 구분한다. 승인 평가 총 한도 $3, 완료분 사용량 추정 $0.996804, 미확인 예약 보류액 $1.518807, 보수적 잔여 $0.484389로 변동 없다. 미확인 보류액을 실제 청구액으로 단정하지 않으며 계정 전체 누계도 아니다. 다음 유료 검사는 호출별 최대 예약액이 이 잔여 한도 안에 들어가는지 먼저 확인해야 한다.
