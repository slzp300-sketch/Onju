# 온주 5차 가상 사용자 20명 추가 진단·작업로그

작성: 2026-09-16. 사용자 요청: “좋아 가상사용자 20명 더 추가해서 검증해보자.”

후속 상태: 사용자 보완 승인 후 10개 유형을 로컬에서 수정했고, 원래 730개 조건과 누적 65명의 2,174개 조건을 통과했다. [보완·검증 작업로그](WEB_MVP_WORKLOG_2026-09-16_PERSONA_ROUND5_FIXES.md)를 참고한다. 아래 본문과 실패 로그는 **수정 전 진단 기록**으로 보존하며, 운영 배포는 하지 않았다.

## 결론

한국어 10명·영어 10명, 22~49세의 새 가상 설정 20명을 구성했다. 기존 ID와 중복 없이 **KR-26~35 / US-21~30**을 사용했다. 누적 가상 설정은 **65명**, 실제 참여자는 **0명**이다.

이번 새 검사 **730개 조건 중 698개 통과, 32개 실패**가 동일 소스에서 두 번 재현됐다. 실패는 **10개 보완 유형**으로 묶었다. 기존 45명의 **1,444개 조건**, 기존 전체 테스트 **1,104개** 및 무료 검사 **22개 묶음**은 재실행에서도 모두 통과했다.

이전 보완을 되돌린 회귀가 아니라, **이전 시험에 없던 표현과 계산 범위의 공백**이다. 특히 ‘읽지 않을래’, ‘시간이 없다’, ‘팀원/자녀’, ‘지난달’, ‘조건이 된 뒤’와 같은 의미를 다른 표현으로 전달했을 때 저장 방어가 충분하지 않다. 이번 결과만으로 실제 모델이 이런 실수를 얼마나 자주 하는지 알 수는 없다.

**제품 코드 수정·배포 없음. 공급자 API 호출 0회, 이번 추가 모델 API 비용 $0.**

## 무엇을 검사했나

- 작성한 기본 여정 발언 **82개**: 기간 → 현재 수준 → 목표 결과 → 가용 시간/우선순위. 목표 삭제·복원 후 새 정보 수집 여정 포함.
- 별도의 상태 경계 입력 **40개**: 정상 의도 후보, 잘못 추출한 후보, 비교용 대조 사례.
- 실제 에이전트 수집 처리 경로 **9개**: 도구 응답만 수동 작성한 모의 공급자로 대체하고 `runAgentTurn`의 실제 저장 처리를 검사.
- 가용 시간 초안 검사 **9개**: 유효한 수동 작성 초안에 `goalFeasibilityIssue`를 적용. 무리한 실행량과 그 이하 대조군, 동일 예산의 명확한 표현 대조군 포함.
- 수량 정규화 직접 검사 **4개**: 평일 빈도·천 단위 표기.

## 발견한 10개 보완 유형

### 1. 부정 동사가 바뀌면 거절 값 저장 — P1, 6개 실패 조건

- KR-26: `책 2권은 읽지 않을래. 지금 목표를 유지해줘.` → 기존 3권을 2권으로 바꾼다.
- US-21: `I don't have 3 hours per week. Please keep the current budget.` → 주 1시간에서 주 3시간으로 바꾼다.
- 두 사례 모두 직접 저장 함수와 실제 에이전트 수집 경로에서 잘못된 변경이 재현된다.
- 긍정적인 새 분량·새 시간 입력 대조군은 정상 저장된다.

원인: `goalEvidenceScope.ts`의 부정 검사가 제한된 동사 목록에 의존한다. `읽지 않을래`, `don't have`는 현재 방어 범위 밖이다. 원문에 숫자가 있고 금지 목록에 안 걸렸다는 이유로 확정으로 간주한다.

개선 기준: 단순 동사 추가만으로 종료하지 말고, **부정이 어느 값·행동에 적용되는지** 확인하는 공통 검증과 의미가 같은 표현 묶음의 회귀를 만든다. 기존 값 유지 요청도 변경 후보와 충돌하는 근거로 확인한다.

### 2. 팀원·자녀의 정보가 본인 정보로 저장 — P1, 6개 실패 조건

- KR-27: `팀원은 시안 6개를 끝냈어. 나는 시안 1개야.` → 본인 1개를 팀원 6개로 덮어쓴다.
- US-22: `My daughter has read 5 books. I have read 1 book.` → 본인 1권을 자녀 5권으로 덮어쓴다.
- 직접 저장과 에이전트 수집 경로 모두 재현. 본인의 새 진도만 말한 대조군은 정상이다.

원인: 타인 판정에 ‘동료’, ‘친구’, ‘colleague’ 등 일부 명칭은 있으나 ‘팀원’, ‘daughter’는 없다. 주체를 확인했다기보다 일부 타인 단어만 차단하는 구조다.

개선 기준: 후보의 소유 주체를 먼저 구분하고 **본인 정보인지 불확실하면 기존 본인 값을 보존**한다. ‘나는/내’, ‘my’가 나타났다는 이유만으로 같은 메시지의 타인 수치를 본인 것으로 채택하지 않는다.

### 3. ‘지난달’ 회고가 최신 기록 덮어씀 — P1, 3개 실패 조건

KR-28: `지난달에는 영상 0편이었어. 그때는 입사 준비로 바빴지.` → 현재 2편을 0편으로 되돌린다. 직접 저장과 에이전트 수집에서 재현된다. 명시적인 현재 정정은 정상 처리된다.

원인: 과거 검사에는 ‘작년/예전/과거/당시’가 있지만 ‘지난달’은 없다. 현재 발언 안에 있다는 것과 현재 사실이라는 것을 구분하지 못하는 범위가 남았다.

개선 기준: 시간 표현과 회고/현재 갱신을 별도 판단하고, 과거 기준을 현재 수준에 덮어쓰지 않는다. 과거 이야기를 차단하는 것이 아니라 현재 상태 갱신 권한을 제한해야 한다.

### 4. 주당 횟수 × 소수 시간 예산 누락 — P2, 1개 실패 조건

KR-29: `주 2회 각 0.5시간 가능해.`는 총 60분인데, 주 2회 × 45분 = 90분 초안에 시간 제약 오류가 반환되지 않는다. 40분 초안은 허용되고, 같은 예산을 `주 2회 각 30분`으로 정정한 대조군에서는 90분 초안이 정상 차단된다.

원인: `capacityLimits`의 회차별 시간 패턴은 정수 중심이다. 일반 수량 파서는 복수 수량을 계산식으로 조합하지 않으므로 주 2회와 0.5시간을 함께 해석하지 못한다.

개선 기준: 횟수·회당 시간·단위를 구조화해 곱셈하고, 소수도 분 단위로 통일한다.

### 5. 평일만 하는 빈도 누락·부풀림 — P2, 6개 실패 조건

- KR-33: `평일 매일 1편` → 주 7편, 4주 예상 28편으로 계산. 기대는 주 5편·20편이다.
- US-28: `1 article each weekday` → 빈도를 해석하지 못해 현재 속도와 예상량이 비어 있다. 기대는 주 5편·20편이다.
- 주당 5편으로 다시 표현한 양쪽 대조군은 정상이다.

원인: ‘매일’의 주 7회 규칙이 ‘평일’ 제약을 반영하지 않고, 영어 weekday 빈도도 지원하지 않는다. 영어는 잘못된 누적량으로 저장하지 않는 보수적 보호는 유지되지만 필요한 비교가 누락된다.

개선 기준: 일 단위 빈도에 적용 요일 범위를 함께 반영한다. 이번 사례의 평일은 월~금·주말 휴식이라는 가상 설정이며, 국가 공휴일 계산을 검증한 것은 아니다.

### 6. 가용 시간 범위를 모르면 상한 검사 생략 — P2, 1개 실패 조건

KR-34: `주당 30~60분 가능해.` → 상한 60분을 넘는 90분 초안도 해당 시간 제약 검사를 통과한다. 30분 초안은 정상 허용되고, `주당 최대 60분` 대조군은 90분을 차단한다.

원인: 수량 파서는 범위를 단일 숫자로 축소하지 않기 위해 null을 반환한다. 시간 예산 함수는 이 null을 ‘확인할 한도 없음’으로 취급한다.

개선 기준: 범위는 최소·최대 구조로 보존한다. 초안이 최대 한도를 넘으면 차단하며, 시작량을 정할 때는 최소 여유와 변동성을 함께 고려한다. 파싱 불가와 무제한은 구분해야 한다.

### 7. when 조건의 미래 변경을 즉시 적용 — P1, 3개 실패 조건

US-23: `When my shifts settle down, change the period to 12 weeks. Keep the current period until then.` → 기존 8주를 바로 12주로 바꾼다. 직접 저장과 에이전트 수집 모두 재현. `Change the period to 12 weeks now.` 대조군은 정상 변경된다.

원인: 조건 검사에 if/unless는 있지만 when 구문과 ‘until then’의 현재 유지 관계가 반영되지 않는다.

개선 기준: **실행 시점과 조건 충족 여부**가 현재인지 따로 확인한다. 아직 성립하지 않은 조건의 변경을 예약했다고 거짓 안내하거나 즉시 저장하지 않는다.

### 8. 뒤에 이어진 미확정 발언을 놓침 — P1, 3개 실패 조건

US-24: `I would like to finish 5 books, but I haven't decided yet.` → 기존 3권을 5권으로 바꾼다. 직접 저장과 에이전트 경로에서 재현. `I have decided to finish 5 books.`는 정상 대조군이다.

원인: 후보 수치가 있는 절에만 근거 범위를 좁히면서, 뒤의 같은 목표에 대한 미결정 발언을 버린다. 별도 질문을 분리하려던 보호가 연결된 유보 의도까지 잘라낸다.

개선 기준: 후보 절 밖의 모든 문장을 무시하지 말고, **해당 후보를 수정·철회·유보하는 연결 발언**은 함께 판단한다. 별개의 질문은 여전히 확정을 방해하지 않아야 한다.

### 9. 영어 복합 시간 예산 누락 — P2, 1개 실패 조건

US-25: `I can spend two sessions of 20 minutes per week.` → 총 40분인데 90분 초안에 해당 시간 제약 오류가 없다. 30분 초안은 허용되고 `I can spend 40 minutes per week.` 대조군에서는 90분이 차단된다.

원인: 한국어 회차×시간 패턴 외의 구조를 계산하지 못하고, 일반 파서는 sessions와 minutes라는 두 수량을 복합식으로 연결하지 못한다.

개선 기준: 언어별 문장은 동일한 횟수·회당 분량·주간 총량 구조로 정규화하고, 이후 제한 계산은 공통 함수로 처리한다.

**4·6·9번의 증거 범위:** 유효한 작성 초안에 대한 `goalFeasibilityIssue` 함수의 검증 공백이다. 다른 실행량·일정·승인 검사가 최종적으로 막을 수 있으므로, 운영에서 90분 초안이 실제 확정됐다고 주장하지 않는다.

### 10. 분·시간의 호환 단위 비교 누락 — P2, 2개 실패 조건

US-26: 현재 `30 minutes per week`, 목표 `1 hour per week`, 가용 `2 hours per week` → 같은 차원의 시간량인데 비교하지 못해 needs_rate, 비교 결과 0개로 남는다. 목표를 `60 minutes per week`로 바꾸면 ready, 비교 결과 1개다.

원인: `assessGoalFeasibility`가 단위 문자열이 다르면 즉시 비교를 포기한다. 가용 시간 상한 계산에는 시간→분 변환이 있지만 목표 진도 비교에는 없다.

개선 기준: 같은 차원의 단위만 명시적인 변환표로 통일한다. 시간과 분은 비교하되 시간과 완성한 책 권수처럼 다른 차원은 추정 변환하지 않는다. 여기서 ready는 시작안 비교 가능 상태이지 목표 달성 보장이 아니다.

- 복원 후 새 현재 수준은 기록하되, 다음 턴의 과거 목표량 재주입은 차단. 새 목표량은 명시한 뒤 기록.

## 우선순위와 구조적 판단 — 구현하지 않음

1. **저장 권한부터 강화:** 본인/타인, 현재/과거, 확정/거절/유보, 지금/조건 충족 후를 값과 함께 확인한다. 정상 원문이 대화 안에 존재한다는 사실만으로 상태 변경을 허용하지 않는다.
2. **연결 문맥을 유지:** ‘but 아직 미결정’, ‘until then 기존 유지’처럼 후보 결정을 바꾸는 뒤 문장은 함께 판단한다. 질문을 줄이려고 문장을 무조건 좁히는 방식도 피한다.
3. **시간·빈도는 별도 계산 구조:** 요일 집합, 총량, 범위, 횟수, 회당 시간, 단위를 보존해 결정적으로 계산한다. 가용 시간 파싱 실패를 무제한으로 통과시키지 않는다.
4. **표현 묶음으로 회귀 확장:** 특정 실패 문구만 추가하는 대신 긍정/부정, 본인/타인, 과거/현재, 단문/대조절을 묶어 검증한다. 실제 모델의 추출 능력은 나중에 승인한 비용 상한 안에서 별도로 평가한다.

이번 결과로 ‘모델이 약하니 교체해야 한다’고 결론내릴 수는 없다. 모델은 호출하지 않았다. 확인된 것은 **잘못된 후보가 주어졌을 때의 저장 방어와 계산 함수의 한계**다. 규칙을 더 넣어 대화를 고정하는 방향보다, 대화 생성은 유연하게 두고 상태 변경·계산의 검증 기준을 명확하게 하는 방향이 적합하다.
