2026-09-15 · 상태: 로컬 구현/오프라인 검증 완료 · 배포하지 않음

## 결과

모델·프롬프트를 교체하지 않고, 루트 웹 MVP와 사이트 작업본의 비용 보호를 공통화했다. 유료 모델 API 호출, 실제 평가, 운영 DB/환경변수 변경, 배포, 커밋/푸시는 하지 않았다. 기존 사용자의 진행 중 변경은 보존했다. Notion에 게시한 기록이 아니라 이 저장소의 로컬 작업로그다.

### 구현

1. 주 대화·보조 판단·용어 검색·계획 생성/재생성·계획 수정·주간 회고·일일 조정 및 루트의 구형 일정/목표 경로에 공통 비용 보호를 연결했다.
2. 예약마다 고유 ID와 원래 날짜를 저장했다. 중복 정산, 자정 이후 잘못된 날짜 정산, 실패를 0원으로 정산하는 경로를 제거했다.
3. 처리 중인 같은 키는 추가 모델 호출 없이 막고, 성공 응답은 DB에서 복구한다. 429 → 성공 후 응답 유실도 성공했던 논리 호출을 재사용한다.
4. 타임아웃·5xx·사용량 누락은 비용 불명으로 유지한다. 상위 에이전트의 catch/모델 대체 시도도 같은 요청 안에서 비용 차단을 우회할 수 없다.
5. 전체 및 세션별 예산, 세션별 실제 호출 횟수 제한을 원자적으로 확인한다. 예산 0은 중지이며 잘못된 설정은 안전하게 차단한다. 공개/평가 예산은 계속 독립적이다.
6. 프록시 신뢰 설정이 없는 주소를 신뢰하지 않으며, 모든 미확인 주소를 하나의 버킷으로 묶지 않는다. 원자적 rate bucket 생성과 서버 시각 사용을 적용했다.
7. `gpt-4.1-mini`를 상위 모델 단가로 집계하던 접두사 오류와 Gemini 사용량 누락 → 0토큰 변환을 수정했다. 이벤트의 미확인 총액은 `null/incomplete`로 구분한다.
8. 공급자의 Retry-After 최소 대기를 존중하고, 긴 대기/결제·할당량 조치가 필요한 오류를 자동 반복하지 않는다.
9. 입력 보존, 재시도 요청 ID 유지, 동기적 더블 클릭 잠금, 한국어/영어 비용 오류 안내를 연결했다. 루트 화면에서 비용 안내가 일반 연결 오류로 덮이던 부분도 고쳤다.
10. 기존 금액 단위 `webMvpAiBudget.ts` 두 작업본은 공통 `webMvpCostControl.ts`로 교체했다. 사이트의 이전 구현은 기존 Git 이력에 남아 있다. 운영 롤백은 코드만 되돌리는 작업이 아니므로 비용 대사 절차를 문서화했다.

## 남은 조건과 다음 단계

- 운영에 적용하지 않았다. 기존/사이트 migration 이력 대조, 호출 drain, 예산 승인, 2단계→3단계 SQL 및 모든 서버 경로 동시 전환이 먼저 필요하다.
- 로컬 PGlite는 실제 SQL을 실행하지만 독립 연결의 동시 락 타이밍/부하 검증은 아니다. 운영 전 별도 확인한다.
- 실제 AI 대화 품질, 해외 접속, 원격 Supabase 권한, 390px 브라우저 시각 QA는 이번 완료 범위가 아니다.
- 불명 비용과 4xx 거절 비용은 보수적으로 예약액을 유지하므로 실제 청구보다 많이 잡힐 수 있다. 운영 대사 없이 자동 환불하지 않는다. 추정 한도는 공급자의 청구 상한 보장이 아니다.
- 복구용 공급자 응답이 새 저장소에 생겼다. 세션 삭제에 연쇄 삭제되며, 5단계에서 내보내기·개인정보 안내와 표시 범위를 함께 확인한다.
- 선택적 일일 AI 조정 실패 때 기존 결정적 축소 행동을 유지하는 동작은 보존했다. AI/비AI 출처 안내는 출시 전 UX 점검 대상이다.
