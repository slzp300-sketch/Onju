## 원문과 대조한 기준

- 사용자의 최신 목적에 반응하며, 필요 조건을 한 번에 묶어서 확인한다.
- 정보가 부족하면 실행 초안을 미리 만들지 않고 가능한 도움과 확인 이유를 설명한다.
- 목표, 현재 수준, 기간, 시간 및 중요한 환경/제약을 반영한다.
- 계획을 제시할 때 목표와 핵심 행동을 먼저 보여주고 방법·이유·진행·기록 예시·조건부 조정·복귀를 이어 설명한다.
- 확정과 수정은 사용자 승인 경계를 지킨다. 원문의 확인되지 않은 기간·장비·체중 목표나 미지원 자동 연락을 복제하지 않는다.

## 이번 변경

1. **새 초안 전용 검사**: 기존 카드 역직렬화와 새 제안의 요구사항을 분리했다. 구형 카드 모양으로 새 초안을 보내더라도 상세 가이드와 목표에 연결된 실행 순서를 생략할 수 없다. 과거 저장 카드는 계속 읽을 수 있다.
2. **실행 시간 예산**: 단계마다 `stepMinutes`를 기록한다. 단계 수/값 범위/유한수와 합계를 검사한다. 준비·휴식·전환·기록을 포함해 회당 시간과 일치해야 한다. 모자라는 시간은 무리한 실행으로 채우는 대신 완충/휴식에 명시적으로 배분하도록 안내한다. 이 수치는 예상치이며 실제 수행 시간의 정확성을 보장하지 않는다.
3. **수정 시 설명 갱신**: 시간/빈도 등의 변경에 따라 기존 설명만 남겨 두지 않는다. 시간 예산이 있는 계획의 수정에는 새 단계별 시간이 필요하고, 수정된 기록 예시와 조건별 조정 설명도 다시 검사한다. 승인 전 원래 계획은 불변이다.
4. **화면 일치**: 저장된 단계별 예상 시간을 대화·초안 상세·계획 상세에 표시한다. 2분 트리거 등 부수 요소를 메인 제목으로 올리지 않는다.
5. **질문 상태**: 물음표 뒤 줄바꿈으로 나눈 질문도 개별 항목으로 관리한다. 명시적인 원문 근거 없이 질문 상태를 `unknown` 또는 `declined`로 바꾸지 못한다. 잘못된 보조 갱신은 유효한 사실 저장을 취소하지 않는다.
6. **측정 안내 누락 수정**: 상세 가이드가 존재할 때 첫 주 실제 기록으로 계획을 조정해야 한다는 중요 안내가 사라지던 경로를 고쳤다.

## 남는 검증 한계

코드가 직접 검사할 수 있는 스키마, 승인/저장 경계와 숫자 일관성은 검사했다. 그러나 다음은 이 결과로 증명되지 않는다.

- 새로운 표현에서 사용자의 의도·부분 답변을 항상 정확히 이해하는지.
- 바꿔 말한 질문의 의미 중복, 장기간 기록과 최신 정정의 모든 충돌.
- 단계별 시간 추정 자체가 실제로 적절한지, 모든 운동 동작이 개인에게 맞는지.
- 모든 분야에서 계획의 깊이·난이도·진행 논리가 참고 문서 수준인지.
- 실제 제공자 응답이 새 계약을 한 번에 지키는지, 비용·지연이 어떻게 달라지는지.

따라서 현재 결론은 **무료 보완 및 검사 범위 통과**다. 유료 검증은 사용자의 현재 지시에 따라 수행하지 않는다. 검증하지 않은 내용을 “완벽” 또는 “100% 문서급”으로 표시하지 않는다.
