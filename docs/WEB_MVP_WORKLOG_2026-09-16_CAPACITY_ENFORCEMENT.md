# 온주 — 시간 한도 적용 누락 후속 보완

작성: 2026-09-16 · 사용자 요청: “보완하자”

## 범위와 발견

[7차 보완](WEB_MVP_WORKLOG_2026-09-16_PERSONA_ROUND7_FIXES.md)이 끝난 뒤, 그 검사가 다루지 않은 계산 결과 → 초안 승인 연결을 점검했다. 새 가상 사용자를 모집·추가한 작업은 아니며, 기존 누적 125명의 입력·기대값을 유지하고 별도의 경계·불변성 검사를 추가했다.

수정 대상은 `logs/sites/onju-web-mvp/supabase/functions/onju-agent-v2/`의 로컬 Site 코드다. 기존 루트 앱·Edge Function의 미커밋 변경을 보존했고 별도로 동기화하지 않았다. 유료 API 호출, 배포, 운영 DB 변경, 커밋·푸시, 노션 등록은 하지 않았다.

### 1. 계산한 회당 한도를 초안 검사에서 사용하지 않음

`3 sessions of 20 minutes per week`는 주 60분·3회·회당 20분으로 정확히 계산했지만, `goalFeasibilityIssue`는 주간 시간과 횟수만 검사했다. 그래서 60분을 한 번에 실행하는 초안도 이 검사에서 통과했다.

- 회당 최대 시간을 공통 한도 조회 및 각 행동 검사에 연결했다.
- 주간 합계가 맞더라도 한 행동이 회당 한도를 넘으면 `goal_capacity_conflict`로 거절한다.
- 모든 행동을 검사하므로 짧은 행동과 긴 행동의 평균으로 제한을 우회하지 못한다.
- `3회 총 60분`은 회당 20분이라고 사용자가 말한 것이 아니다. 명시한 총량과 회당량은 구분한다.
- 범위는 기존 정책대로 상한을 적용한다. 최소치보다 적게 시작하는 가벼운 행동을 강제 차단하지 않는다.

### 2. 기준이 없는 수치가 제한 없음으로 처리됨

`20 minutes`, `20분 가능해`는 하루·주간·회당 중 무엇인지 알 수 없지만, 기존에는 unspecified가 되어 수치 한도 확인을 건너뛰었다.

- 명시적인 수량에 기준이 빠지면 unresolved로 처리하고 가용 시간 확인 단계로 돌린다.
- `퇴근 후 가능해`, `I am free after 6 pm` 같은 서술·시각 조건은 숫자 예산과 구분하여 질문을 강제하지 않는다.
- 이미 유동적·미측정으로 저장된 여건은 첫 주 측정 경로를 유지한다.

### 3. 회당 시간만 알려준 경우의 보존

`20 minutes per session`, `회당 20분`, `한 번에 20분`, `1½ hours per session`은 회당 한도로 보존하되 주간 횟수·총 시간을 계산해서 만들어 넣지 않는다.

- 주간 빈도가 없어도 알고 있는 회당 상한은 초안에 적용한다.
- 회당 0분은 현재 실행할 여건이 없는 것으로 처리한다. 목표 유지 동의만으로 이 제한을 무시하지 않는다.
- 짧은 한국어 `회당 20분`도 근거 수집 단계에서 인식한다. 저장·재로딩 후 동일한 제한을 확인한다.
- 기간·횟수 해석이 충돌하는 복합 문장은 임의로 계산하지 않는다.

### 4. 글자로 된 음수의 부호 손실

`minus 20 minutes per week`를 +20분으로 계산하는 문제도 확인했다. 공통 숫자 정규화에서 `minus`·`마이너스` 다음 숫자를 지원하지 않는 부호 있는 수량으로 처리한다. 시간은 unresolved, 목표 수량은 null로 두고 확인을 요구한다. 음수 재무 잔액 등의 별도 도메인 계산을 새로 지원한 것은 아니다.

## 변경 파일

제품 4개:

- `goalCapacity.ts`: 기준 누락 수치와 서술 구분, 독립 회당 한도 계산.
- `goalFeasibility.ts`: 회당 제한 적용, 0분 여건 처리.
- `goalIntakeEvidence.ts`: 한국어 회당 근거 수집.
- `goalNumberNotation.ts`: 글자 음수 부호를 양수로 오독하지 않도록 보호.
