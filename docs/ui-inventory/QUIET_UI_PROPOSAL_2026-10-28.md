상태: 디자인 검토용. 운영 앱에는 적용하지 않았다. AI 개발·유료 테스트·배포는 보류한다.

## 2026-10-29 색상 시안 추가

새 보드: http://127.0.0.1:5192/palette-ui-2026-10-29.html

사용자가 직접 지정한 포인트·그린 색은 유지하고, 기본 바탕은 후속 요청에 따라 이전 리넨 `#FAF0E6`으로 복원했다. 노란 기의 보조 표면·시안 보드 배경도 이전 리넨 계열로 맞췄다. 아래 값이 현재 주색 기준이다.

| 색 | 기준값 | 역할 |
| --- | --- | --- |
| 리넨 | `#FAF0E6` | 기본 바탕, 읽기·입력 공간, 그린 위 글자 |

홈·기록·작성은 리넨 비중을 크게, 목표·소모임·계정은 그린 카드로 중심을 잡고, 로그인은 그린 바탕으로 제안한다.
토마토 레드는 작은 포인트로 사용한다. 저장 실패·삭제는 색뿐 아니라 아이콘·문구를 함께 제공하며,
재시도·저장은 그린을 유지한다. 알림으로 오해할 수 있는 장식 점은 내비게이션과 모임 카드에서 제거했다.
기분 선택은 같은 선 아이콘으로 통일했고, 기존 나무 일러스트의 자연색은 보존했다.
연한 표면·구분선·짙은 글자는 세 주색에서 파생한 톤이다. 밝은 토마토 레드를 작은 글씨로 쓰지 않으며,
그 위에는 더 짙은 그린 `#153628`을 사용한다. 오늘의 차트 막대에는 그린 윤곽선도 함께 제공한다.

추가 조정: 사용자의 요청에 따라 토마토 포인트 비중을 조금 늘렸다. 선택된 하단 메뉴의 아이콘 바탕,
홈의 실천·할 일 추가 버튼, 선택 탭 밑줄, 짙은 목표 카드의 진행 막대, 첫 모임 카드 아이콘에 적용한다.
프로필·모임 표지·나무 카드에는 얇은 강조선을 더한다. 알림으로 오해할 수 있는 작은 배지는 추가하지 않고,
저장·완료 버튼은 그린으로 유지한다. 새 포인트 위 글자는 짙은 그린이며 레이아웃과 기능은 동일하다.
포인트 확대 후 영향받은 11개 화면을 390px에서 다시 확인했다. 가로 넘침과 의미 있는 작은 글씨의 대비 문제는 없었고,
JavaScript 구문 검사와 시안 빌드가 통과했다. 아래 네 비교 이미지도 현재 상태로 갱신했다.

검증 결과 (2026-10-29):

- 35개 화면 × 390px·320px = 70개 조합에서 가로 넘침·깨진 이미지·이름 없는 아이콘 버튼 없음.
- 지정 코드 반영 후 35개 화면을 390px에서 재확인: 가로 넘침·깨진 이미지 없음.
  작은 글씨 대비 4.5:1 이상 확인. 장식용 마침표·비활성 항목·플레이스홀더·가상 요소는 이 검사 범위 밖이며,
  전체 접근성 인증을 의미하지 않는다.
- 기본 바탕 복원 후 그린/리넨 대비 8.56:1, 짙은 그린/토마토 레드 대비 5.28:1.
  토마토 레드/리넨은 2.22:1이므로 본문 글씨에 사용하지 않는다.
- 네 상태의 배너 문구·대비·넘침 확인. 저장 실패 안내는 레드, 안전한 재시도 버튼은 그린.
- 브라우저 경고·오류 로그 없음. JavaScript 구문 검사와 두 시안의 Vite 빌드 통과.
- `npm run gc`: ESLint 통과 후 Knip의 OXC 파서에서 `Array buffer allocation failed`로 중단.
  따라서 이번 전체 GC는 통과로 기록하지 않는다. 라이브러리·검사 설정은 바꾸지 않았다.
- `git diff --check` 통과. 실제 앱 기능 테스트는 이번 디자인 작업 범위에서 반복하지 않았다.

모든 이름·날짜·기록·상태는 고정 예시이며, 일부 조작은 대표 흐름만 보여준다.
서버·계정·실제 기록에 연결하지 않았다. 실제 앱 반영 시에는 공통 색상 토큰 → 홈·기록 → 목표·소모임 → 작성·복구 순으로 적용하고,
인증 제공자 버튼 규격과 오류·접근성 상태는 해당 기능 구현 단계에서 별도 검증한다.

## 점검 결과

현재 앱의 부담은 문장 수뿐 아니라 **반복 안내, 여러 수치, 보조 행동이 모두 같은 비중으로 보이는 것**에서 발생한다.

1. 홈에서 오늘의 행동에 도달하기 전 인사, 목표, 날짜 범례, 기록 종류, 남은 항목 설명을 읽게 된다.
2. 습관마다 타이머·보관·쉼·대체·완료를 함께 제시해 주 행동이 약해진다.
3. 은혜 기록에서는 통계·초안 카드가 본문보다 앞서고 각 카드에 응답·수정 버튼이 반복된다.
4. 일기·습관 작성에서는 기기 보관 안내가 상단 공간을 크게 차지한다. 습관 작성의 전체 목표 선택 목록도 기본 입력을 밀어낸다.
5. 목표·통계에서 경과 일수, 목표 전체 진척, 오늘까지 기록률과 계산 설명을 반복한다. 서로 다른 분모의 숫자가 가까이 있어 혼동하기 쉽다.
6. 소모임에서 소개, 참여 상태, 관리, 초대, 규칙, 통계, 나눔이 누적된다. 정원 숫자와 정원 비율도 중복이다.
7. 복구 기능의 사용자 안내에 서버·충돌·요청 등의 설명이 길게 드러난다. 실제 행동에 필요한 차이와 보존 범위를 먼저 보여줄 필요가 있다.

브라우저로 실제 표시를 확인한 화면: 홈 개인·신앙, 목표, 통계, 소모임 목록, 마이페이지, 은혜 기록, 일기, 습관 작성, 주간 리뷰, 알림 설정. 그 외 화면·편집 변형·모달은 현재 `src/App.tsx` 경로와 페이지/공통 컴포넌트 코드, 기존 UI 인벤토리를 기준으로 검토했다. **35개 운영 화면을 모두 실기기에서 검증했다는 의미는 아니다.**

기존 로컬 미리보기 상단의 ‘예시 데이터 / 로컬 검증 시나리오’ 영역은 개발용이므로 제품 UI 개선 대상·문구량 판단에서 제외했다. 남아 있는 충돌 샘플은 상태 안내 사례로 별도 검토했다.

## 공통 방향

- 아이보리·그린·기존 나무 이미지와 4개 하단 탭을 유지한다.
- 한 화면에 대표 제목 하나, 주요 행동 하나를 우선한다.
- 부가 설명을 기본 화면에서 줄이고 정보 버튼·펼치기·상세 시트에서 읽게 한다.
- 뒤로가기, 추가, 더보기, 완료 등 익숙한 조작은 아이콘과 접근 가능한 이름을 제공한다.
- 홈·통계·소모임·마이페이지의 이름, 저장·공유·삭제 등 결과가 중요한 행동은 짧은 문구를 남긴다.
- 상태를 색상에만 의존하지 않는다. ‘기기 보관’, ‘전송 대기’, ‘서버 저장 완료’를 구분한다.
- 저장 대기·다기기 변경은 한 줄로 모으고 펼치면 항목을 보여준다. **기기 보관 실패는 계속 보이는 경고**로 유지한다.
- 초안이 없으면 초안 목록을 표시하지 않는다. 초안이 있으면 `초안 1개 · 이어쓰기`로 요약한다.
- 목표 목록은 ‘전체 진척’ 하나를 표시한다. 오늘까지 기록률과 분모는 상세에서 이름과 함께 설명한다.
- 카드 안에 카드를 겹치지 않는다. 짧은 목록은 여백과 구분선으로 정리한다.
- 글씨를 작게 줄여 맞추지 않는다. 읽어야 할 항목을 줄이고 중요한 본문을 넓힌다.

## 적용 계획

| 순서 | 범위 | 바꿀 내용 | 완료 확인 기준 |
|---|---|---|---|
| 1 | 공통 상태·홈·기록 | 상태 안내 통합, 홈 목록과 더보기, 날짜 범례 축소, 기록 통계 이동, 초안 한 줄 | 처음 화면에서 행동·본문이 보임. 실패·충돌 안내와 복원 진입은 남음 |

실제 적용은 공통 컴포넌트와 1차 화면부터 작은 묶음으로 진행한다. 저장·큐·RPC·기록 보존 규칙은 기존 구현을 사용한다. 각 단계에서 정상/빈 상태/오류/오프라인/초안/충돌을 같이 확인한다.

## 화면 유형 범위

- 매일: 홈 개인·신앙·할 일, 은혜 기록, 메모 작성, 하루 일기.
- 목표·성장: 목표 목록·상세·실천 연결, 통계, 나무, 테마.
- 돌아보기: 주간 리뷰 4단계, 리뷰 결과.
- 함께: 소모임 목록·상세·생성, 초대 참여, 공유.
- 작성: 습관·묶음·신앙 루틴·할 일·월간 목표·주간 목표, 타이머.
- 설정·시작: 마이페이지, 알림, 보관함, 로그인, 회원가입, 비밀번호 재설정, 온보딩.
- 복구: 변경 내용 비교 공통 시안, 빈 상태. 전역 저장 시나리오 4종과 주요 확인 시트.

세부 화면별 ‘현재의 부담 / 수정 방향 / 꼭 남기는 것 / 기존 경로’는 보드의 **수정 계획** 표에 수록했다. 생성/편집과 각 충돌 종류는 공통 유형으로 묶었으며 모든 예외 변형을 개별 시안으로 제작한 것은 아니다.

## 디자인 선택에 따른 유의점

- 쉼·대체를 더보기로 옮기면 홈은 간결해지지만 한 번 더 눌러야 한다. 실제 적용 후 사용 빈도를 확인하고 필요하면 짧은 선택 시트를 완료 버튼 옆에 유지한다. 숨겨진 제스처만으로 접근하게 만들지 않는다.
- 통계 기본을 주간 요약으로 바꾸는 제안은 기존 목표/습관/주간/기록 메뉴를 유지한다. 마지막 선택 탭을 기억할지는 구현 때 정한다.
- 목표 카드 펼치기를 상세 시트로 분리하는 제안은 새로운 핵심 기능 추가가 아닌 정보 배치 변경이다. 뒤로가기로 원래 위치가 복원되어야 한다.
- 짧은 비교만 보고 덮어쓰지 않도록 전체 내용 펼치기와 최종 확인을 유지한다. 삭제·기기 입력 폐기·계정 삭제의 영향은 생략하지 않는다.
- 가입 폼의 한 칸 이메일 입력과 온보딩 축약은 디자인 제안이다. 기존 인증·초안 호환성을 검증한 뒤 적용해야 한다.

## Android 화면·입력 보완 — 2026-10-29

연결된 삼성 갤럭시 노트9(SM-N960N, Android 10, WebView 156)로 검증을 이어갔다. 사용자의 에뮬레이터 중단 요청 이후에는 실기기만 사용했다. 기존 앱·계정과 분리한 **온주 UI 검증** 패키지에 실제 React 화면과 Android 래퍼, 로컬 예시 데이터 저장소를 묶었다. 운영 로그인·Supabase 서버와 통신하는 검증은 아니다.

### 수정 내용

- 공통 화면 여백을 Capacitor의 안전 영역 값과 연결했다. 상단 상태 표시줄, 하단 메뉴, 고정 저장 버튼, 타이머·설정 시트가 같은 기준을 사용한다.
- 키보드가 열린 상태에서 저장 버튼을 눌러 초점이 바뀌어도, 키보드가 닫히기 전까지 버튼 위치를 유지한다. 이미 줄어든 WebView 높이를 JavaScript에서 다시 줄이지 않는다.
- 모달·메모 시트의 최대 높이와 위치를 실제 보이는 영역에 맞췄다. 입력 스크롤 여백과 저장 알림 위치도 보완했다.
- 한글 조합 중 Enter와 Android의 조합 키 코드 229로 할 일이 저장되지 않도록 했다. 이메일·숫자 입력 키보드와 다음/완료 키 힌트, 이메일 도메인 선택의 접근성 이름을 보완했다.
- 노트9에서 **키보드 높이 이중 차감**을 발견했다. `adjustResize`와 Capacitor 8.4의 WebView 140 이상용 IME padding이 함께 적용돼 화면이 139px로 줄었다. 해당 WebView에서는 Android 창을 edge-to-edge로 맞춰 중복 차감을 막았다. 수정 후 같은 기기의 키보드 표시 영역은 **504px**이며 입력창과 저장 버튼이 동시에 보인다. 이전 WebView는 기존 OS 크기 조정 경로를 유지한다. 버전 분기는 설치된 Capacitor 소스를 기준으로 했으며 [공식 SystemBars 안내](https://capacitorjs.com/docs/apis/system-bars)의 창 설정 권고도 확인했다.

### 검증

- 전체 회귀 테스트 **63개 파일 / 511개 통과**. 한글 조합 중 저장 방지, 키보드 초점 이탈·스크롤·확대·창 크기 변경 검사를 포함한다.
- TypeScript·Vite·PWA 프로덕션 빌드, Android 로컬 `cap sync`, 네이티브 검증 APK 빌드 통과. 배포하지 않았다.
- ESLint·Knip 보고 없음, 종료 코드 0. 앞선 UI 작업과 같은 임시 일반 AST 파서 로더를 사용해 OXC raw-transfer 메모리 할당 문제를 피했다. 검사 규칙·제외 목록·의존 패키지는 변경하지 않았다.
- 노트9에서 실제 소프트 키보드, 한글 조합 입력, 할 일 저장, 상태 표시줄, 입력창과 저장 버튼의 위치를 확인했다. 키보드 화면 가로 넘침 0px, 입력창이 저장 버튼 위에 표시됨을 검사했다.
- **노트9 통합 검사 통과(24.583초, `OK (1 test)`)**: 한글 할 일 저장 → 습관 입력 → 첫 뒤로가기로 키보드만 닫힘 → 다음 뒤로가기로 이탈 확인 → 취소 시 입력 유지 → 이동 후 초안 복원·저장 → 여러 줄 일기 저장·재열기 → 기도 메모 시트 입력·저장. 실제 터치와 Android InputConnection의 한글 조합 입력을 사용했다. 8개 검사 시점의 가로 넘침은 모두 0px이다. 초기에 화면 꺼짐(0px viewport), 폼 준비 전 입력, 문서 교체 중 검사 콜백 유실로 중단된 실행은 통과로 세지 않았다.
- 작업 시작 시점과 비교해 `store`, `api`, `data`, `lib`, `types`, `utils` 변경 **0개**. 기존 기록·큐·충돌 해결 규칙, 운영 DB를 변경하지 않았다. [변경 범위 확인](android-ui-previews/source-scope.json)
