# 온주 작업로그 — 해외 무료 베타 2단계: 세션 보호

날짜: 2026-09-15 (KST)

## 결과

**2단계 로컬 구현·오프라인 검증 완료. 운영 배포·DB 적용 없음.**

루트 개발본과 별도 사이트 작업본에 공통 소유권 보호를 반영했다. 사용자·대화별 자료가 섞이지 않도록 세션 확인, 로컬 저장, 재시도, 삭제, 이전 모델 응답 연결을 보완했다. 기존 앱 구조와 사이트의 별도 기능·평가 작업은 유지했다. 모델 종류·대화 프롬프트 변경이나 실제 AI 품질 평가는 하지 않았다.

## 구현 내용

1. 모든 확인된 웹 대화·메모리·목표·계획·일일 점검·피드백·삭제·계측 진입점에서 소유 확인이 데이터 조회 및 모델 호출보다 앞서 실행되도록 정리했다.
2. 브라우저의 UUID·토큰을 하나의 쌍으로 유지한다. 기존 UUID만 있는 경우 토큰을 임의로 만들어 소유권을 주장하지 않는다. 다른 탭에서 정체성이 바뀌면 이전 화면의 요청을 중단한다.
3. DB RPC에서 세션 생성·소유·만료를 확인한다. 인증 저장소 오류 시 우회하지 않으며, 만료된 기록을 자동 연장하거나 소유 해시 없는 기존 자료를 선점하지 않는다.
4. 삭제 전용 RPC와 삭제 표식을 추가했다. 같은 소유자의 삭제 재시도는 안전하게 완료되며, 늦게 도착한 쓰기가 삭제된 세션이나 자식 자료를 다시 만들지 못하도록 했다.
5. 일부 구형/계획 수정 경로의 `previousResponseId`도 서버가 기록한 소유 목록과 대조한다. 다른 대화의 응답 ID 또는 확인할 수 없는 ID는 공급자 호출 전에 거부한다.
6. 대화·계획·주간 지도·입력 임시 저장소를 세션별 키로 분리했다. 기존 비분리 캐시는 원래 소유 세션에 한 번 연결하며 새 세션에 자동 복사하지 않는다.
7. 불러오기 실패를 빈 대화로 간주해 자동 저장하지 않는다. 실패 안내·다시 불러오기·사용자가 확인하는 새 대화 시작을 제공하고 입력을 보존한다.
8. 사이트에 남아 있던 “403 → 새 UUID 자동 생성 → 이전 대화 복사 → 자동 재시도” 동작을 제거했다. 삭제와 별도의 새 대화 시작을 구분한다.
9. 서버 관리 대화를 오래된 화면 자동 저장으로 덮어쓰지 않도록 했다. 명시적 계획 저장은 유지하고 저장 후 재조회 테스트를 추가했다.
10. 삭제 실패 뒤에도 재시도 버튼이 보여야 한다는 화면 회귀를 확인했다. 불러오기 오류가 로딩 화면에 가려지던 문제도 수정했다.

## 두 차례 점검 및 발견한 회귀 처리

1차: 세션 토큰 누락, 구형 진입점, 저장 실패, 만료 갱신, 기존 무소유 행, 삭제 후 늦은 저장, 다른 탭의 정체성 변경, 이전 모델 응답 포인터까지 보호 경계를 검토했다.

2차: 실제 서버 진입점에 가짜 DB를 넣어 접근 거부 순서를 확인했다. 별도 메모리 핸들러의 정상 저장·재조회·삭제 재시도도 실행했다. 빈 PostgreSQL/WASM에 사이트 웹 SQL 0007~0034와 새 보호 SQL을 실행했다. React DOM으로 불러오기·삭제 실패 화면을 검증한 후 전체 무료 검사를 다시 실행했다.

검사 중 발견한 화면 훅 사용 오류, 모듈 경로 오류, 함수명 충돌을 수정했다. 삭제 구현이 직접 쿼리에서 원자적 RPC로 바뀌면서 맞지 않게 된 정적 검사는 새 계약을 확인하도록 수정하고 실제 SQL·핸들러 테스트로 보강했다. 아래는 수정 후 고정 소스의 최종 결과이며, 중간 실패를 통과로 합산하지 않는다.

## 검증 한계·배포 전 조건

- PostgreSQL/WASM은 실제 SQL을 실행하지만 단일 엔진이다. 독립 DB 연결·여러 서버의 동시 생성/삭제/쓰기 경쟁 시험은 아직 하지 않았다.
- 브라우저 검사는 React DOM/jsdom이며, 390px 실제 브라우저의 시각·스크롤·여러 탭 QA를 대체하지 않는다. 통합 검증 단계에서 수행한다.
- 운영 Supabase의 테이블·권한·마이그레이션 ledger는 변경하지 않았다. 루트와 사이트 SQL 이력 충돌을 대조하고 적용 순서·구형 클라이언트 캐시를 검증하기 전에는 새 SQL·서버만 단독 배포하면 안 된다.
- 소유 해시 없는 기존 세션과 등록되지 않은 이전 공급자 응답은 자동으로 신뢰하지 않는다. 안전한 복구를 증명할 수 없으면 사용자가 새 대화를 선택해야 한다.
- 삭제 표식의 보관 정책, 외부 공급자 응답·백업·비연결 집계의 처리 범위는 5단계/게시 전 확인 대상이다.
- 실제 한국어·영어 AI 대화 품질, 해외 접속, 운영 비용 감소 효과는 검증하지 않았다. 모델·프롬프트를 변경하지 않았다고 실제 품질 검증 완료로 주장하지 않는다.
