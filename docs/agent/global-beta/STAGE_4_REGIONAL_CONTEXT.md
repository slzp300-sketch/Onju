# 4단계 — 언어·국가·시간대·주 시작일 계약

작성일: 2026-09-15 (KST)  
상태: 로컬 구현·오프라인 검증 완료 · 운영 적용 없음

## 목적

해외 사용자의 화면 언어와 국가, 시간대, 주 시작일을 서로 섞지 않고 다룬다. 한국 사용자의 기존 기록 의미와 월요일 기준 저장 인덱스를 보존하면서, 선택한 지역에 맞는 화면·날짜·요일·알림 안내를 제공한다.

## 확정한 계약

- `locale`, `countryCode`, `currencyCode`, `timeZone`, `weekStartsOn`을 별도 값으로 저장한다.
- 브라우저 언어·브라우저 시간대는 초기 힌트일 뿐 거주 국가의 증거로 사용하지 않는다. 사용자가 저장한 선택이 우선이다.
- 기존 `dayIndex`는 월요일=0, 일요일=6으로 유지한다. 주 시작일은 화면 정렬에만 사용하고 저장된 요일·기록 날짜를 재작성하지 않는다.
- 날짜 키(`YYYY-MM-DD`)는 순간 시각이 아니라 기록한 달력 날짜로 취급한다. 시간대를 바꿔도 과거 기록을 전날·다음 날로 이동하지 않는다.
- 현지 날짜·주간 범위·알림은 선택한 IANA 시간대에서 계산한다. 서머타임의 존재하지 않는 시각은 다음 유효 시각으로, 반복되는 시각은 한 번만 전달하도록 처리한다.
- 화면 번역은 개발자가 작성한 UI 문구에만 적용한다. 사용자 목표·일정·대화 원문은 자동 번역하거나 번역 사전으로 치환하지 않는다.
- 결제 기능이 없는 상태에서 통화 표시는 선호·표시용 정보로만 다룬다.

## 구현 범위

### 화면·상태

- `web-mvp/src/regionalContext.ts`: 정규화, 초기 힌트, 저장/로드, 지역 날짜, 현지 주간 범위, 표시용 요일 순서.
- `web-mvp/src/useRegionalContext.ts`: 앱 전역 지역 상태와 변경 이벤트.
- `web-mvp/src/RegionalSettings.tsx`, `regionalSettings.css`: 언어·국가·시간대·통화·주 시작일 설정, 390px 레이아웃, 저장 후 재접속.
- 두 작업본의 공통 지역 파일은 parity 테스트로 동일성을 확인한다. 설정 화면은 저장된 값을 자동 추정값보다 우선한다.
- 설정을 수정하는 동안 다른 탭에서 값이 바뀌면 현재 입력을 덮어쓰지 않고 최신값을 불러올 수 있게 한다.

### 에이전트·계획·일일 경험

- 대화·계획 생성·계획 수정·일일 점검·주간 회고·일일 조정 요청에 지역 컨텍스트를 전달한다.
- 계획의 요일 표시와 기존 레거시 요일 문자열을 현재 지역의 요일 라벨로 표시한다. 서버 저장 인덱스는 그대로 둔다.
- 일일 상태·주간 지표·주간 회고·적응 조정의 날짜, 빈 상태, 오류 및 기본 안내를 선택한 언어에 맞춘다.
- 진행 중 요청의 재시도는 요청 시점의 지역 컨텍스트 스냅샷을 유지해, 재시도 중 설정 변경으로 날짜·언어가 섞이지 않게 한다.
- 루트 경로의 기본 에러와 계획 생성/수정 에러도 현재 언어에 맞춰 안내한다.

### 알림·캘린더

- 브라우저 알림의 다음 시각, 조용한 시간, 하루 중복 방지 키를 사용자 시간대 기준으로 계산한다.
- 캘린더 파일은 선택한 IANA 시간대의 벽시각과 `VALARM`을 기록하고, 영어 제목·본문을 제공한다.
- 캘린더 앱별 실제 표시, OS 권한, 모바일 백그라운드 전달은 운영 환경에서 별도 확인이 필요하다.

## 1차·2차 점검 결과

1차 점검에서 언어·국가·시간대·통화·주 시작일의 저장 모델을 분리하고, 기존 월요일 인덱스와 기록 날짜를 변경하지 않는 경계를 확인했다. 대화부터 계획·일일·회고·알림까지 지역 컨텍스트가 필요한 활성 경로를 연결했다.

2차 점검에서 한국, 미국의 복수 시간대, 영국·캐나다·호주, 언어와 국가가 다른 조합을 고정 시계로 확인했다. 자정 경계, 뉴욕 서머타임의 유효하지 않은 시각·반복 시각, 로스앤젤레스·서울·시드니 알림, 일요일 시작 주간 표시, 새로고침·다른 탭 변경·영어 오류/빈 상태를 검사했다.

## 미확인·운영 전 조건

- 운영 사이트가 이 작업본과 같은 소스인지 확인하지 않았다. 배포 전 버전 대조가 필요하다.
- `202609150003_web_mvp_regional_context.sql`을 운영 DB에 적용하지 않았다. 기존 migration 이력·권한·RLS·RPC를 먼저 대조해야 한다.
- 운영 환경변수, 실제 해외 접속, 실제 AI 영어 자연어 품질, 공급자 청구, 캘린더 클라이언트별 `VALARM`, 모바일 OS 알림은 확인하지 않았다.
- 영어 AI 답변 품질은 지역 설정 단계의 완료 기준에 포함하지 않았다. 실제 품질 평가는 6단계 이후 승인된 비용·시나리오로 한 번에 수행한다.
- 루트 앱과 별도 사이트 작업본에는 의도적인 기능 차이가 있을 수 있다. 공통 지역 계약만 parity로 묶고, 사이트 전용 화면은 별도 테스트로 확인한다.
