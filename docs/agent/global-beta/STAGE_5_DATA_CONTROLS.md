# 5단계 — 베타 안내·문의·데이터 제어 계약

작성: 2026-09-15 · 로컬 구현/검증용 · 운영 게시/DB 적용 없음

## 목적과 화면

현재 브라우저 세션의 자료를 사용자가 확인하고 통제할 수 있게 한다. 기존 Sites 화면·배포 설정과 Supabase 구조를 유지한다. 기능 화면은 한국어/영어를 모두 지원한다.

- `/about`: 무료 베타 범위, AI 한계, 개인정보 입력 주의, 처리/보관 안내 초안, 문의·피드백.
- `/data`: 서버+기기 JSON 내보내기, 명시적으로 구분한 기기 전용 내보내기, 삭제 범위 확인→체크→확인/취소.
- `/settings` 및 공개 베타 진입 안내에서 접근 가능. 기존 대화가 삭제/중지돼도 안내와 데이터 관리에는 접근할 수 있다.
- 피드백은 직접 입력한 240자 이내 내용만 저장한다. 전체 대화/진단 자료 자동 첨부 없음. 재시도에 같은 메시지 ID를 사용하며 실패한 입력을 유지한다. 실시간 상담·답변 보장은 하지 않는다.

사용자 텍스트는 원문으로 보존한다. 구조화된 접속 키/응답 포인터 필드는 내보내기에서 제외하지만 사용자가 대화 본문에 직접 적은 비밀까지 자동 제거한다고 보장하지 않는다. 파일을 공유하기 전에 검토하도록 안내한다.

## 서버 동작

새 전진 마이그레이션: `202609150004_web_mvp_data_controls.sql`.

- export_session은 일반 claim/갱신 전에 실행. ID+독립 토큰 해시로 소유 확인하고, 세션 생성/갱신이나 모델 호출을 하지 않는다.
- `web_mvp_export_owned_session`은 STABLE SQL 함수로 한 문장의 스냅샷을 읽는다. 서버 자료와 로컬 자료는 서로 다른 시점이므로 각각의 출처/생성 시각을 구분한다.
- 만료된 소유 세션도 아직 자료가 남아 있으면 내려받고 삭제할 수 있다. 만료를 연장하지 않는다.
- 소유자 없는 레거시 세션, 다른 토큰, 잘못된 토큰은 거절한다. 삭제된 세션도 export 성공으로 위장하지 않는다.
- 컬렉션 10,000행 또는 세션+컬렉션 JSON 10MiB 초과 시 명시적인 오류. 일부만 잘라 성공으로 반환하지 않는다.
- 새로운 직접 세션 FK 테이블이 추가되면 내보내기 분류가 갱신되기 전까지 실패 처리한다.
- RPC는 service_role만 실행한다. 공개 클라이언트에 직접 권한을 주지 않는다. 응답에 Cache-Control: no-store를 적용한다.
- 아직 생성되지 않았거나 이미 정리된 UUID 삭제는 동일 생성 잠금 안에서 tombstone을 기록한다. 서버 대화를 새로 만들지 않고 늦은 최초 쓰기를 차단한다. 기존 행이 있을 때는 소유 검증을 생략하지 않는다.
- 루트와 별도 Site의 동일 SQL/공통 파일을 검사한다. Site의 stable/pilot 경로 선택은 기존 resolveAgentService를 유지한다.

## 브라우저 동작과 실패

1. 사용자가 삭제 범위를 확인하고 체크한 뒤 확정해야 요청한다. 더블 클릭은 1회로 제한한다.
2. 서버 요청 전에 해당 세션 삭제 잠금을 localStorage에 기록한다. 새로고침·다른 탭도 잠금을 읽는다.
3. 잠금이 있거나 세션이 달라지면 이전 제품 화면을 내리고 대화 저장을 중지한다. 이전 비동기 쓰기도 현재 소유자와 잠금을 확인한다.
4. 서버 성공 후에만 해당 브라우저 자료를 정리한다. 성공 응답을 확인하지 못한 경우 입력·소유 키와 잠금을 유지한다.
5. 서버 삭제 후 브라우저 정리가 실패하면 **서버 삭제 성공 / 기기 정리 미완료**를 구분해 알린다. 같은 키로 재시도 가능.
6. 전송 대기는 삭제 중/삭제된 세션 이벤트를 다시 넣지 않는다. 다른 세션의 대기 항목은 이 삭제로 제거하지 않는다.
7. 서버 export 실패를 기기 전용 백업으로 자동 대체하지 않는다. 사용자가 별도 버튼을 선택해야 하며 파일 scope가 다르다.
8. 내려받는 도중 세션이 바뀌거나 삭제가 확인되면 늦은 응답을 파일로 만들지 않는다.
9. 오류 종류별로 내보내기/삭제/피드백에 맞는 안내를 표시하고 모바일에서 결과 위치에 초점을 이동한다.

브라우저 storage event는 저장값 변경을 알리는 수단이지 여러 프로세스의 원자적 트랜잭션이 아니다. 보호된 최신 클라이언트의 로컬 재쓰기 방지와 서버 tombstone/FK 보호를 함께 사용한다. 오래된 클라이언트·다른 기기의 이미 저장된 사본을 원격으로 모두 지웠다고 주장하지 않는다.

## 두 번의 점검

1차: 실제 화면→클라이언트→메모리 API→SQL/FK→로컬 저장 키를 대조했다. 코드상 마지막 유효 사용 후 30일 만료 표시와 실제 정리/외부 보관을 분리했다. 비용 초기화의 영문 오안내도 한국시간 자정(15:00 UTC)으로 바로잡았다.

2차: 실제 메모리 핸들러+합성 DB 경계, PostgreSQL/WASM, React DOM, 실제 전송 큐의 가짜 네트워크 완료, 390px 미리보기로 검증했다. 소유권 분리·만료·권한·행 한도·삭제 cascade·취소·중복 클릭·실패 재시도·세션 변경·큐 재생성 방지를 포함했다. 미리보기에는 실제 Supabase/API 키를 로드하지 않았다. 실사용자 자료 삭제는 하지 않았다.

통합 실행 결과는 별도 5단계 작업로그에 연결한다. 오프라인 시험은 실제 모델 대화 품질, 해외 접속, 운영 마이그레이션 적용이나 다중 PostgreSQL 연결의 경쟁 타이밍까지 입증하지 않는다.

## 게시 전 반드시 확정할 운영 정보

- 운영 주체의 정확한 명칭과 공식 문의 주소/담당자.

이 정보는 확정하지 않았고 문구도 **초안**으로 표시했다. 배포·운영 게시·해외 출시 완료로 계산하지 않는다.
