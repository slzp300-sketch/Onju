# 배포 기준 SQL 원본 — 실행 금지 참고 자료

출처: 로컬에 보관된 별도 사이트 저장소 `logs/sites/onju-web-mvp`의 커밋 `90528db8e55f06101a60eb7abefacc42579d13bc`.

이 폴더의 15개 SQL은 그 커밋의 `supabase/migrations/0019`~`0033` 파일을 내용 변경 없이 보존한 것이다. SHA-256은 CRLF를 LF로 정규화해 `../stage-1-baseline.json`과 검사한다. 원본의 실제 운영 적용 여부는 이번 작업에서 조회하지 않았다.

주의:

- 이 폴더는 마이그레이션 실행 경로가 아니다. 통째로 실행하거나 루트 `supabase/migrations`에 그대로 복사하지 않는다.
- 루트 0019~0021은 같은 번호를 다른 기능에 사용한다. 운영 migration ledger와 스키마를 대조하기 전 기존 파일을 교체·재번호화하거나 적용 이력을 조작하지 않는다.
- 0001~0018 선행 스키마는 출처 저장소에 있으며, 이 15개만으로 새 DB를 구성할 수 없다.
- 이미 적용된 RPC를 재정의할 때는 최신 정의와 권한까지 대조한다. 예를 들어 예산 예약은 0028 이후 0032에서 정산 모델이 바뀌었다.
- 이 원본이 완벽히 안전하다는 의미가 아니다. 예약 ID 없는 정산·자정 경계·토큰 없는 세션 선점·동시 요청 등은 후속 단계에서 검증하고 개선한다.
- 미커밋 0034 평가 예산 SQL은 배포 기준 원본에 섞지 않았다. 별도 소스 대조표에만 기록했다.

오프라인 확인: `web-mvp`에서 `npm run test:readiness`. DB 연결이나 SQL 실행 없이 원본 해시와 의존성 정의의 존재를 확인한다.
