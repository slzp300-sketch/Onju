# 6단계 — 통합 오프라인 검증과 배포 준비

작성: 2026-09-15. 이 문서는 실행 명령서가 아닌 **배포 전 점검 계약**이다. 실제 운영 변경·실제 모델 평가·배포는 별도 승인이 필요하다.

## 완료의 의미

무료 개발 검증 통과와 해외 출시 완료를 구분한다. 합성 응답을 쓰는 검사는 실제 모델의 자연어 이해, 질문 선택, 답변 품질, 응답 속도 또는 실과금을 입증하지 않는다. 기존 한국어 기대 품질을 낮추거나 모델을 교체하지 않았다.

## 이번 보완

- 루트 웹의 랜딩과 제품 화면 코드를 분리하고 제품 화면만 지연 로딩한다. 기존 원본 앱 `src/`와 사이트의 별도 제품 구조는 유지한다.
- 오프라인 Vite 빌드는 환경파일을 읽지 않으며 공개 API URL/키도 빈 값으로 고정한다. 사이트의 실제 배포 빌더는 단 하나의 명시된 환경변수 공급원과 예상 백엔드 호스트를 요구한다. 주변 디렉터리에서 `.env.local`을 찾아 섞던 경로를 제거한다.
- 공개 빌드 변수는 URL/anon·publishable key만 허용하고 서비스 키·서버 공급자 자격증명은 빌드 프로세스에 전달하지 않는다. 검사는 설정의 형식/역할을 확인할 뿐 키의 진위·프로젝트 접근 권한을 온라인 검증하지 않는다.
- 실제 사이트 React 라우터·대화 화면·SSE 파서·초안 승인·계획 클라이언트·일일 점검·세션 저장·내보내기·삭제가 이어지는 테스트를 추가한다. 모의 데이터가 제품 소스에 섞이지 않도록 QA 디렉터리에 격리한다.
- 영어 분야명/주간 횟수와 언어 변경 뒤에도 최초 언어로 남는 피드백 버튼을 보완한다. 계획 화면의 기본 진행 지도와 재연결 상태도 현재 언어로 표시한다. 사용자가 이미 저장한 목표/마일스톤 원문은 번역 명목으로 바꾸지 않는다.
- 390px에서 긴 행동 제목이 한 줄 입력칸에 잘리던 부분을 자동 높이 텍스트 영역으로 바꾼다. 제목 변경·창 크기 변경·폰트 로드 후 다시 맞추고 기존 blur/Enter 저장 경로는 유지한다. 요일별 행동/완료 기준/축소 계획의 스크린리더 이름도 영어로 제공한다.
- 빌드 파일·서버 소스·마이그레이션의 크기/SHA-256과 환경변수 **이름만**을 저장하는 인벤토리를 만든다. 프런트·서버·DB 코드 목록이 있다고 일괄 배포하거나 마이그레이션을 실행해서는 안 된다.

## 2차 점검 — 실행과 재현

`node web-mvp/scripts/verify-offline.mjs`는 모델 공급자 네트워크를 차단한 자식 프로세스로 실행한다. 모델 키를 제거하고, 테스트·타입·양쪽 빌드·ESLint·Knip·합성 지표·평가 계획 준비와 인벤토리를 하나의 로그 폴더에 기록한다. 소스가 실행 전후 달라지면 전체 결과를 통과 처리하지 않는다.

`qa/journey-ui/backend.mjs`는 명시된 합성 시나리오만 반환한다. 호출하지 않은 기능이나 오류를 무조건 성공으로 처리하지 않는다. UI 테스트 외부의 SQL 경쟁/세션 권한/비용 정산은 기존 실제 핸들러 및 PGlite 테스트가 담당한다. 이는 운영 서버 E2E 또는 독립 PostgreSQL 연결의 락 검증과 다르다. 테스트에서 쓰지 않는 autosave는 서버 저장을 재현하지 않으며, 대화/계획 확정 저장/점검 상태는 합성 저장소에서 유지한다.

390px 브라우저 확인은 `qa/journey-ui/preview.vite.ts`로 별도 포트 5190에서 실제 Site 화면을 띄운다. `.env`를 읽지 않고 모든 API를 같은 로컬 합성 서버로 보내며 화면에 OFFLINE QA 배지를 표시한다. 제품 빌드에 이 파일을 import하거나 이 설정으로 배포하지 않는다. 종료 시 미리보기 서버를 중지한다.

## 배포 전 체크리스트와 적용 순서

1. **동일 소스 확정**: 사용자 승인 범위를 기준으로 루트와 Site의 변경 파일을 검토한다. 검증 당시 두 소스 지문·빌드 인벤토리·테스트 로그를 함께 보관한다. 현재 턴은 커밋·푸시하지 않는다.
2. **운영 사실 확정**: 운영 주체/문의 주소, 무료 한도, 대상 국가/연령, 처리 업체·리전, 실제 만료 정리 일정, 로그·백업·삭제 방지 기록의 보관 기준을 확정한다. 초안 표시와 미정 항목을 확정된 사실처럼 게시하지 않는다.
3. **DB 원장 대조**: Site와 루트의 0019~0021 등 번호 중복은 서로 같은 migration이 아니다. 두 폴더를 합쳐 `db push`하지 않는다. 운영 ledger와 실제 함수·테이블 정의를 확인하고 필요한 차이만 새 forward migration으로 승인받는다. `reference-migrations/`는 참고용이며 독립 실행 체인이 아니다.
4. **변경 창과 복구본**: 신규 AI 유입을 중지하고 진행 중 호출·비용 예약을 정리한다. 현재 배포 버전, 비밀값을 포함하지 않는 설정 이름, DB 백업/복구 가능성, 기존 actual+pending 비용 대사를 확인한다.
5. **DB → 모든 서버 경로 → 프런트**: 스키마 정합성 이후 `202609150001` 세션, `202609150002` 비용, `202609150003` 지역, `202609150004` 데이터 제어 migration의 실제 파일명·선행 조건을 인벤토리와 대조한다. 활성 stable 및 pilot wrapper/공개 별칭도 함께 갱신한다. `verify_jwt`·CORS·소유 토큰·만료·레이트 제한·신뢰 프록시 설정을 확인한다. 원본 앱의 인증 AI 함수는 웹 MVP 범위와 분리한다.
6. **구버전 캐시 대응**: 이전 브라우저는 새 소유 토큰/지역/비용 계약을 모를 수 있다. 토큰 없는 기존 세션을 새 토큰으로 임의 소유시키지 않는다. 접근 불가 상태는 입력 보존·복구 안내로 처리하고, 현재 세션 종료/새 대화 동의를 받는다. 서버의 구형 비용 RPC 권한을 다시 열어 호환시키지 않는다. HTML 캐시 갱신과 콘텐츠 해시 자산을 확인한다.
7. **명시적 release 빌드**: `ONJU_BUILD_ENV=process` 또는 절대경로 `ONJU_ENV_FILE` 중 하나와 `ONJU_EXPECTED_SUPABASE_HOST`를 지정한다. 공개 URL/키는 사용자 승인 프로젝트의 값만 사용한다. 실제 값은 문서·로그·Git에 기록하지 않는다. `ONJU_EXPLICIT_BUILD=1`은 빌더가 설정해 추가 dotenv 자동 로드를 막는다.
8. **운영 산출물 재검증**: `release-inventory.json`의 `deployable:false` 산출물은 API가 비어 있는 무료 검사용이므로 업로드하지 않는다. 동일 소스로 공개 설정만 주입해 다시 빌드하고 새 해시·크기·노출 변수·라우트 fallback·캐시/404·HTTPS를 확인한다. Sites 프로젝트 ID/호스팅 디렉터리도 재확인한다.
9. **승인된 실제 평가 후 공개**: 아래 단일 후속 평가를 통과한 버전만 제한 공개한다. 응답 오류/소유권 오류/비용 급증/계획 손실이 보이면 중단한다. 영어권 테스트 3~5명은 이 이후다.
10. **복구**: 새 호출을 차단한 뒤 검증된 프런트·서버 쌍으로 되돌린다. 새 비용 대장/삭제 tombstone을 지우거나 구형 비용 RPC를 열어 예산·소유권을 초기화하지 않는다. DB는 역순 삭제보다 호환 가능한 forward fix를 우선한다. 새 DB와 구서버 조합이 안전한지 확인되지 않으면 유입 중지 상태를 유지한다.

## 한 번으로 모은 후속 실검증 — 아직 실행하지 않음

- 자동 준비된 `evaluation-plan.json`의 29개 시나리오/59개 사용자 턴은 **실행 계획**이다. 공급자 호출 수와 같지 않고 계획 생성/수정·재시도로 늘 수 있다. 실제 평가 직전에 동일 소스에서 시나리오 중복을 제거하고 총 호출 상한·달러 상한·중단 조건을 승인받는다.
- 품질: 영어·한국어 동일 사례, 목표만 제시/기간·현재 위치 누락, 한 번에 여러 정보, 유동 일정, 수정·거절·주제 전환, 기억 유지, 근거 없는 시간 단정 금지, 계획 행동의 개인화, 간결한 문단/강조, 확인 전 저장 금지를 실제 모델로 확인한다.
- 연결: 한국·영어권 실제 브라우저/네트워크에서 첫 방문·새로고침·장시간 후 재접속·오프라인 재시도·느린 SSE·중복 요청·실제 모바일 키보드를 확인한다. 해외 사용자 접속은 로컬 시간대 변경만으로 대신하지 않는다.
- 보안/운영: 다른 소유 토큰 거절, 만료·삭제 재쓰기 방지, export 한도/신규 테이블 누락 거절, 독립 DB 연결의 동시 예약/삭제 경쟁, 배치 정리, 로그·비용 대장 대사를 스테이징 우선으로 실행한다.
- 지표: 실제 공급자 호출별 토큰/금액/캐시/오류와 요청별 비용을 함께 남긴다. 실패 사용량 미확인은 0원으로 기록하지 않는다. 대화 원문 수집은 별도 동의 정책을 따른다.

출시 판단: 실제 품질 기준 미달, 운영 사실 미확정, 소유권/삭제/비용 경계 실패가 하나라도 있으면 확대 공개를 보류한다. 무료 개발 검사가 통과했다는 이유만으로 이 조건을 생략하지 않는다.
